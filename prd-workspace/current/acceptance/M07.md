| --- | --- | --- | --- | --- |
| AC-F002-13 | 系统管理员登录 | 访问 F001-F015 任一有数据的列表、详情、附件和直接地址 | 均按公司全局返回且允许执行对象当前状态支持的操作，日志记录系统管理员真实身份 | P0 |
| AC-F002-14 | admin 打开“权限授权” | 修改 PM 模板并尝试修改系统管理员模板 | PM 模板可保存并直接生效；系统管理员模板全部权限只读，不能取消、停用或删除 | P0 |
| AC-F002-15 | PM 只负责济南 | 分别从列表、搜索、候选、计数、消息和直接地址访问青岛对象 | 所有入口均不返回青岛名称或数量，直接访问为 403 | P0 |
| AC-F002-16 | admin 保存权限模板时服务端任一步失败 | 受影响角色刷新菜单并发起业务请求 | 旧完整权限配置继续生效，不出现菜单、接口或字段权限混用 | P0 |
| AC-F002-17 | 总裁、市场副总、区域总监或 PM 登录 | 查看导航、访问 F002 直接路由并调用角色模板或权限查询接口 | 导航无“权限授权”；页面和接口返回 403，响应不包含角色、权限数量、权限键、版本或影响人数 | P0 |
| AC-F002-18 | admin 选择非管理员内置角色并形成有效权限差异 | 填写 5-500 字原因、确认影响预览并保存 | 新完整权限配置直接生效，新请求立即按新配置鉴权，日志记录前后权限、影响和 admin 真实身份 | P0 |
| AC-F002-19 | admin 查看系统管理员模板 | 尝试伪造取消权限、停用或删除请求 | 页面全部权限只读且无保存入口；服务端拒绝请求，管理员模板仍保持启用和全权限 | P0 |
| AC-F002-20 | admin 编辑包含父子和依赖关系的权限 | 勾选操作、取消页面或选择字段编辑/脱敏 | 自动补齐或联动移除依赖并正确显示半选；服务端拒绝不满足依赖的伪造权限集合 | P0 |
| AC-F002-21 | admin 对非管理员模板有实际修改 | 点击保存但未填写原因，随后填写原因并查看确认弹窗 | 原因不足 5 字或超过 500 字不能提交；合法时展示目标角色、当前权限、权限差异和在职员工数 | P0 |
| AC-F002-22 | 某角色存在多条历史权限变更日志 | admin 查看历史并尝试恢复任一旧配置 | 日志按时间倒序只读展示前后差异、原因、影响、操作者和结果；页面无恢复或回滚入口，伪造请求被拒绝且当前配置不变 | P0 |
| AC-F002-23 | 两个 admin 会话读取同一角色当前配置 | 一个会话先保存，另一个仍按旧配置保存 | 后一请求返回 409 和最新配置摘要，不覆盖先保存配置；本地差异保留供刷新后对比 | P0 |
| AC-F002-24 | 权限集合、当前配置或审计任一步写入失败 | admin 保存 | 整个操作不生效，旧配置继续完整生效，不生成残缺配置或成功提示 | P0 |
| AC-F002-25 | 某角色的新配置移除其当前菜单或操作 | 该角色用户继续使用已打开页面并发起新请求 | 新请求立即返回 403；导航最迟 5 分钟刷新，当前页面停止请求、清理缓存并跳至首个有权页面 | P0 |
| AC-F002-26 | admin 或任一业务角色进入员工详情或非管理员模板 | 尝试为单个员工增减权限、向非管理员模板写入 F002，或通过兼任获得 F002 | 页面无员工例外入口且非管理员树无 F002；伪造请求被拒绝，除内置 admin 外任何账号均不能获得权限授权 | P0 |
| AC-F002-27 | admin 保存、保存失败或非 admin 越权访问 F002 | 查询对应权限审计 | 可追溯权限键增删、前后值、角色、原因、影响人数、admin 真实身份、请求 ID、结果与生效时间；日志不可修改或删除 | P0 |
| AC-F002-28 | admin 编辑非管理员模板 | 勾选某操作权限后取消所属页面 | 勾选操作自动补齐页面；取消页面联动移除该页全部操作，保存预览列出两类差异 | P0 |
| AC-F002-29 | admin 编辑字段权限 | 勾选字段编辑后取消对应字段查看 | 勾选编辑自动补齐查看；取消查看联动移除编辑，服务端拒绝不合法集合 | P0 |
| AC-F002-30 | admin 编辑附件权限 | 勾选下载/删除后取消附件查看或上传 | 下载依赖查看；删除依赖查看与上传，前端联动且服务端执行相同校验 | P0 |
| AC-F002-31 | admin 查看 HR/人事模板 | 配置审批中心查看和处理本人主管待办 | HR 仅可处理本人主管待办，不获得客户业务审批范围；数据范围规则在右栏只读且不能改为公司业务全局 | P0 |
| AC-F002-32 | HR 或 admin 在 M06 编辑仍承担区域中心主管或地市责任的员工角色 | 保存人工角色变化 | 区域中心主管缺失区域总监角色时系统按主管关系自动补齐且不占人工 1-5 上限；不再主管任何区域中心时只移除系统自动来源角色；人工原有角色保留，PM 地市责任仍按 M08 资格边界校验 | P0 |
| AC-F002-33 | 全新环境或已初始化环境再次执行部署迁移 | 初始化六个角色、admin、权限树和四级周期 | 首次创建稳定内置对象；重复执行复用相同 ID/编码且不覆盖用户已调整的非系统默认配置，不重置编号序列或 admin 密码 | P0 |
| AC-F002-34 | admin 查看六个内置角色模板 | 依次检查角色名称、编码和数据范围 | 包含 HR/人事；HR 数据范围类型为公司组织、范围对象为组织，其他角色使用规定固定范围，字段均只读 | P0 |
| AC-F002-35 | 总裁角色字段权限被配置为员工手机号明文查看，HR 被进一步配置为脱敏 | 两者查看其他员工手机号 | 总裁仍最多看到前 3 后 4 位；HR 按更严格模板只看到脱敏值；没有任何模板能突破固定隐私上限 | P0 |
| AC-F002-36 | 普通用户或 admin 尝试修改、覆盖、删除既有业务审计日志或据此恢复历史权限 | 直接调用审计写接口或历史恢复接口 | 系统拒绝原记录变更和历史恢复；原前后值、操作者、时间和请求 ID 保持可查，当前权限配置不变 | P0 |

> Source Governance（2026-08-24，DEC-165）：AC-F002-32 先前“移除区域总监角色必须先更换主管”的统一阻断措辞为 Historical / Replaced Evidence。当前区域中心主管关系会自动维护带来源的区域总监角色，人工角色与自动角色分别治理；M07 仍只拥有角色模板，不拥有员工角色关联。

> Permission Apply Current Rule（2026-08-31，DEC-189）：权限经影响确认后直接生效，只保留只读、只追加变更日志；本期不提供一键回滚、选择历史配置恢复或双版本并存。
