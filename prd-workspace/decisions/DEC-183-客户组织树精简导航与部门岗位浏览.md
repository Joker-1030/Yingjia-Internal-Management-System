# DEC-183：客户组织树精简导航与部门岗位浏览

- 日期：2026-08-31
- 状态：已确认
- 背景：M09 客户组织树已按 DEC-181 拆分为左侧公司导航和右侧当前对象工作区。当前公司“部门与岗位”继续叠加独立筛选后页面内容过多，左侧公司导航占用过宽，树节点同时展示编号和对象类型标签也与右侧详情重复。
- 决策：
  1. 公司导航筛选继续用于定位行业、集团和客户公司；选中客户公司后的“部门与岗位”不再提供客户部门名称、部门编码、标准岗位名称、岗位编码或状态筛选，也不提供查询、重置操作。
  2. “部门与岗位”直接展示当前公司的部门子树和标准岗位；空树显示当前公司暂无部门或岗位。每个父节点首次加载 50 个直接子节点并保留“加载更多”。
  3. 左侧公司导航在双栏构图中作为定位辅助区收窄，右侧当前对象工作区保持主要内容宽度；窄屏仍按既有规则改为上下布局。
  4. 左侧公司导航树以名称为主要识别信息。行业节点不展示行业编码，集团节点不展示集团编号，客户公司节点不展示公司编号，也不展示“客户公司”类型标签；既有状态和客户公司的业务责任层级标识继续保留。
  5. 行业编码、集团编号和公司编码继续在对应详情中展示，编号数据、生成、唯一性、筛选和维护规则均不改变。
- 替代关系：部分替代 DEC-181 中“部门岗位筛选只作用于当前客户公司”“切换公司清空部门岗位筛选条件”以及“两区筛选独立”的页面表达。DEC-181 的两阶段工作区、公司双页签、上下文隔离、树归属和加载更多规则继续有效；DEC-178 对实际存在的页面筛选继续有效。
- 未采用方案：保留部门岗位筛选但折叠；只缩小筛选控件；在树节点继续展示编号；隐藏详情编号；改变组织层级或新增树折叠模式。
- 原因：部门与岗位已限定在当前公司，继续叠加五项筛选会挤压主要组织浏览和详情空间。编号在详情中已有稳定位置，树节点应优先支持快速识别名称和层级。
- 决策人：Product Owner
- 影响范围：M09、Acceptance、Prototype
