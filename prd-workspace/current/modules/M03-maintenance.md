## Quick Overview

- **模块解决什么：** 将客户维系规则转为可执行任务，跟踪任务、专项和覆盖 KPI，并沉淀可审计的维系记录与历史。
- **谁主要使用：** 总裁、市场副总、区域总监、PM 和系统管理员按角色与责任范围查看或处理；HR/人事无 M03 客户业务权限。
- **主要页面：** 任务总览、执行明细/我的任务、任务详情、专项列表与详情、覆盖客户明细、维系记录及新增/编辑/详情。
- **核心操作：** 查看和筛选任务、完成任务、申请延期/暂停/取消、逾期补录或补完成、发布专项、查看覆盖 KPI、新增或编辑维系记录。
- **关键边界：** M09 提供规则与客户组织稳定事实，M02 提供客户/关键人/任职，M08 提供责任，M04 提供审批，M05 提供停用结果；M03 只拥有生成后的任务、专项、执行项、维系记录和历史。
- **治理边界：** 节令补完成、批量重算、补录路由和跨公司稳定 ID 已按 DEC-163 形成 Current Rule；暂停资格、暂停期间状态、恢复重算与节令越期关闭已按 DEC-200 形成 Current Rule。旧资料只作 Historical / Replaced Evidence。

## 1. 模块目标

M03 是客户维系执行与结果沉淀模块。它把 M09 当前有效的周期、事件、提醒、标题和执行要求转换为可追踪的父任务与任务执行记录，让责任人完成、补录或受控处理异常任务，并通过专项、覆盖 KPI 和维系记录反映执行结果。

M03 负责：

- 父任务、任务执行记录、任务规则快照及生成后的任务生命周期；
- 专项维系、关键人覆盖 KPI 及其执行项、目标和进度；
- 独立或任务关联的维系记录、附件关联和记录历史；
- 完成、逾期、补录、关闭、取消、迁移和完成认定的业务表达；
- 向 M01、M02 和 P01 输出任务风险、进度、维系结果和通知事件。

任务生成边界固定为：

```text
M09 当前有效规则与稳定对象事实
  -> M03 校验客户、关键人、任职、责任和人员资格
  -> M03 幂等生成父任务与任务执行记录
  -> 保存生成时规则、对象和责任快照
  -> 生成后的任务按 M03 生命周期独立运行
```

M10 成功导入且适用当前 M03 规则的正式对象，必须在导入成功后 5 分钟内进入上述幂等生成流程。失败导入行不生成任务；任务生成失败不回滚 M10 导入成功结果；重试不得重复生成父任务或执行记录。

M09 后续修改配置只影响新生成任务，不回写历史任务、不批量重算已有任务、不改变旧任务快照。DEC-102、DEC-110 和 Shared 06 的相反表达已由 DEC-148/149/163 标记为 Historical / Replaced。

M03 不拥有客户主数据、关键人身份与任职普通维护、区域或地市责任、内部员工组织、权限模板、停用审批容器、通用审批容器或消息已读状态。

| 角色 | 可见与数据范围 | 可执行操作 | 审批与代办边界 | 关键限制 |
| --- | --- | --- | --- | --- |
| 总裁 | 公司全局任务、专项、记录及有权详情 | 查看；创建、编辑、发布专项；记录本人维系 | 按当前路由兜底处理省级业务责任客户任务异常 | 本人记录不代替他人完成任务；不是所有任务异常的固定审批人 |
| 市场副总 | 全国市场范围 | 查看；创建、编辑、发布专项；记录本人维系 | 审批省级业务责任客户任务异常；市级/区县级任务异常主要为抄送 | 抄送不产生任务执行权，也不扩大对象范围 |
| 区域总监 | 本人主管的全部区域中心并集 | 监管；执行本人负责的省级业务责任客户五类任务和专项/KPI；记录本人维系；发起本人任务异常 | 审批市级/区县级业务责任客户任务异常 | 不使用“本区域”单数扩大范围；无主管区域时客户范围为空 |
| PM | 当前有效负责地市；无有效地市时范围为空 | 执行本人市级/区县级业务责任客户任务及专项/KPI；完成、补录、申请延期/暂停/取消；记录本人维系 | 发起本人任务异常，不处理省级业务责任客户任务 | 搜索、候选、数量、详情和操作均受当前有效责任约束 |
| HR/人事 | 无 M03 客户业务范围 | 无 M03 查看、执行、专项或记录操作 | 无 M03 审批权 | M06 组织维护能力不产生 M03 权限；直接访问返回 403 且不泄露 |
| 系统管理员（admin） | 公司全局 | 查看并执行本文已经定义的 M03 操作；发布专项；独立记录维系 | 可按规则代办任务或审批，代办原因和真实身份进入审计 | 全局能力不改写原执行人、责任快照或业务路由，不产生未定义操作 |

M07 角色模板只能进一步收紧 M03 的菜单、操作、字段和附件权限，不能扩大角色业务资格、对象范围、任务执行人、专项发布人或审批路由。无权入口不可见；直接访问、候选、计数、附件和详情统一返回 403，不泄露对象是否存在。

## 3. 核心对象

### 3.1 M03 拥有的对象

| 对象 | 产品含义 | 关键关系与生命周期 | M03 所有权边界 |
| --- | --- | --- | --- |
| 父任务 | 按常规计划、生日年月、节假日年度或专项建立的稳定工作主题 | 使用稳定父任务编号，可包含多条任务执行记录；其状态由执行记录聚合 | M03 拥有编号、主题、聚合状态和历史 |
| 任务执行记录 | 分配给具体执行人的一次可跟踪工作项 | 关联唯一父任务，保存执行人、截止、状态、完成认定和历史 | M03 拥有生成后的执行生命周期；不改外部责任事实 |
| 任务规则快照 | 执行记录生成时保存的规则版本和当时业务参数 | 来源于 M09 规则、M02 对象、M08 责任和 M06 人员资格 | M03 保存且不得由 M09 回写；完整字段仍有 Clarification |
| 专项 | 有起止时间、目标范围和执行要求的父对象 | 分类固定为专项维系或关键人覆盖 KPI；正式发布后与唯一父任务一对一 | M03 拥有发布、目标、进度和结束后冻结结果；不设置草稿状态 |
| 专项维系执行项 | 对一名关键人的一次专项维系动作 | 使用专项 ID 与关键人稳定 ID 防重；完成必须生成维系记录 | M03 拥有执行项和完成认定，不拥有关键人身份 |
| 覆盖 KPI 执行项 | 每名责任人面向目标客户集合的一条聚合待办 | 由部门或岗位覆盖事实自动达标；有效期内可能重新打开 | M03 拥有聚合待办和达标历史，不修改 M09 岗位事实 |
| 维系记录 | 一次真实客户接触事实 | 可独立创建或唯一关联任务；保存后业务字段锁定，仅可追加附件 | M03 拥有内容、关联任务、状态和审计历史 |
| 附件关联 | 维系记录或补录证明与受控文件的关联 | 文件通用规则来自 Shared；关联随父业务对象权限重新鉴权 | M03 拥有业务关联和操作审计，不定义通用文件能力 |
| 关闭/取消与执行历史 | 任务退出有效集合、责任迁移、规则判定和完成认定的历史 | 保留流程编号、原因、人员、时间和前后状态 | 不伪记完成、不物理删除、不回收 ID 或编号 |

## 4. 页面与入口

### 4.1 维系管理入口

维系管理固定为三个一级页签：任务总览、执行明细/我的任务、维系记录。PM 默认进入“我的任务”，其他有权角色默认进入任务总览。专项从任务总览进入，不创建第四个一级页签。

入口、页签、数量、筛选候选和详情始终使用同一最终权限与责任范围。页面分别表达 Loading、Empty、Empty Result、Error、PermissionDenied、Submitting 和 Success。

### 4.2 任务总览

任务总览每行展示父任务，筛选项仅为任务编号、任务标题、任务类型、任务状态、最低任务完成进度和最高任务完成进度；各项使用常驻可见标签并只匹配自身字段，默认每页 20 条。同一业务字段在筛选、列表和详情中使用同一名称；目标范围和执行人不作为任务总览筛选项或列表列。

列表展示任务标题、任务编号、任务类型、任务状态、开始时间、结束时间、执行记录统计项、任务完成进度和可用操作，不展示目标范围或每行更新时间。常规维系是持续续期的长期计划，不适用任务完成进度，单元格固定显示 `-`；专项维系、关键人覆盖 KPI、生日关怀和节假日关怀按 6.1.1 展示 1 位小数百分比，适用但分母为 0 时显示 `--`。进度单元格不展示分子/分母或进度条，有限任务的全部有效执行记录完成时显示 `100.0%`。“执行周期”不再作为组合列：常规维系的开始时间显示“长期”、结束时间显示 `-`；专项维系和关键人覆盖 KPI 显示专项配置的开始、结束日期；生日关怀显示主题月份首日和末日；节假日关怀显示当前年度节假日日历的开始、结束日期。表格右上角统一展示最近一次成功加载或刷新列表数据的“数据更新时间”，该时间不等于任一业务对象的更新时间。

最低/最高任务完成进度按 `0.0%-100.0%` 的包含边界范围筛选，允许只输入一端，并与其他筛选条件取交集。启用任一进度条件时，显示 `-` 的常规维系和显示 `--` 的零分母有限任务均不命中；最低值高于最高值时不执行筛选，并提示“最低进度不能高于最高进度”。

父任务没有执行记录时显示空态，不增加新的父任务状态。筛选有数据但无命中时显示 Empty Result 并保留条件。

### 4.3 执行明细 / 我的任务

执行明细每行展示任务执行记录，筛选项仅为任务编号、任务执行记录编号、任务标题、任务类型、关键人名称、客户公司、执行人、截止开始日期、截止结束日期和风险范围；各项只匹配自身字段。五类当前分类继续由“已完成、待执行/暂停、当前逾期、补录审核中、已过期未完成”页签承载，不重复增加状态筛选。PM 的“我的任务”只展示本人当前有权执行的市级/区县级业务责任客户任务和专项/KPI；区域总监的执行范围包含本人负责省级业务责任客户任务。

风险范围固定为：

- **全部：** 不附加风险或临期条件。
- **当前逾期风险：** 仅命中常规维系、生日关怀或节假日关怀中当前处于“当前逾期”的执行记录；暂停、专项维系、关键人覆盖 KPI、补录审核中和已过期未完成不命中。
- **未来 7 日到期：** 仅命中当前可执行的待执行记录，当前截止晚于今天且不晚于未来第 7 个自然日；当天到期、已完成、暂停、当前逾期、补录审核中、已过期未完成、已取消和已关闭均不命中。

“当前逾期风险”与“未来 7 日到期”互斥；不提供“曾经逾期”或“无当前风险”选项。当前逾期风险沿用 `DEC-121《客户可见健康状态与维系健康率使用同一任务风险范围》`：[`prd-workspace/decisions/DEC-121-客户可见健康状态与维系健康率使用同一任务风险范围.md`](../../decisions/DEC-121-客户可见健康状态与维系健康率使用同一任务风险范围.md) → “决策”，并按 `DEC-200《暂停任务不形成逾期并按任务类型恢复或关闭》`：[`prd-workspace/decisions/DEC-200-暂停任务不形成逾期并按任务类型恢复或关闭.md`](../../decisions/DEC-200-暂停任务不形成逾期并按任务类型恢复或关闭.md) → “暂停期间”“替代关系”排除全部暂停任务。M01 需要处理的重点异常进入本页时，继续按照 `DEC-066《工作台下钻只回填落地页原生筛选》`：[`prd-workspace/decisions/DEC-066-工作台下钻只回填落地页原生筛选.md`](../../decisions/DEC-066-工作台下钻只回填落地页原生筛选.md) → “决策”回填上述可见原生筛选，不建立隐藏条件。

列表区分任务编号与任务执行记录编号，展示生成时渲染后的任务标题、当前截止、执行人、对象上下文、当前分类、完成认定和曾逾期事实，不展示每行更新时间。原“关键人 / 覆盖目标”统一命名为“执行目标”：常规维系、专项维系、生日关怀和节假日关怀展示具体关键人，覆盖 KPI 展示待补齐的目标部门或目标岗位。原“客户单位 / 集合”统一命名为“客户范围”：前述具体关键人任务展示对应客户公司，覆盖 KPI 按责任人聚合执行项展示 `共 N 个客户`。覆盖 KPI 的该数量仅为当前聚合范围摘要，不提供点击或任务详情下钻；客户集合明细只从“任务详情 → 数据看板 → 覆盖客户”查看。表格右上角统一展示数据更新时间。取消或关闭记录保留在历史中，不计入有效执行记录五类统计。

### 4.4 父任务与任务执行详情

五类父任务详情统一使用标题为“任务详情”的 Drawer，并固定为“任务详情、数据看板、执行明细”三个页签。Drawer 标题栏只展示“任务详情”和关闭入口，不附加任务编号、任务类型或其他对象信息；名称识别区只展示任务名称和一处任务状态，不在任务名称下方展示编号、类型、开始/结束时间或有效期说明。

“任务详情”页签是任务编号、任务类型、开始时间、结束时间、更新时间及按任务类型展开字段的唯一展示位置，不重复任务名称和任务状态，也不增加“目标范围”汇总字段。关键人定期维系计划不展示任务标题模板和执行要求；生日/节假日关怀展示适用规则的事件、职级、任务标题模板和执行要求；专项维系展示发布时的目标条件、任务标题模板和执行说明；关键人覆盖 KPI 展示集团、业务责任层级/区域、覆盖维度、目标部门或岗位和目标覆盖率，且不重复展示顶部已有的任务名称。详情中的分类字段统一命名为“任务类型”。“数据看板”展示该父任务已有聚合指标和状态，不新增指标；常规维系不展示“任务完成进度”指标卡，但继续展示覆盖客户、覆盖关键人及五类执行记录数量。“执行明细”保留当前授权范围内的执行记录表格，但不展示操作列、任务详情或维系记录下钻入口；查看和处理单条执行记录继续从一级“执行明细/我的任务”进入。

任务执行详情展示任务编号与任务执行记录编号、生成时渲染后的任务标题、生成时保存的执行要求、客户/关键人快照、执行人和责任快照、原截止与当前截止、规则版本、当前分类、完成认定、关联记录、异常审批、创建/更新时间和执行历史。

从父任务下钻执行记录或从消息、工作台进入详情时重新鉴权。局部加载失败保留上次成功值、更新时间和重试入口，不用空白或业务状态代替错误反馈。

#### 6.1.1 任务完成进度的适用范围与口径

“关键人定期维系计划”对应本文的常规维系任务主题。该计划按关键人职级周期持续续期，没有固定结束时间，后续执行记录会持续产生，因此不适用用于衡量有限任务全生命周期推进程度的“任务完成进度”。任务总览固定显示 `-`，表示“不适用”；最低或最高任务完成进度筛选启用时不命中；任务详情的“数据看板”不展示该指标卡。其已完成、待执行 / 暂停、当前逾期、补录审核中、已过期未完成等执行数量仍按当前授权范围实时统计和展示，不影响常规维系的完成、续期或健康判断。

专项维系、关键人覆盖 KPI、生日关怀和节假日关怀是有明确结束边界的有限任务，其“任务完成进度”按当前授权范围内该父任务/任务主题的有效任务执行记录实时计算：

```text
任务完成进度
= 已完成的有效任务执行记录数 / 该主题下全部有效任务执行记录数 × 100%
```

- 分母包括五类有效任务执行记录：已完成、待执行 / 暂停、当前逾期、补录审核中、已过期未完成；已取消或已关闭的执行记录退出有效集合，不计入分母。
- 分子包括完成认定为按期完成、审批通过后认定按期的逾期补录、逾期后补完成的有效任务执行记录。
- 补录审核中计入分母，但审批通过前不计入分子。
- 分母为 0 时显示 `--`；百分比保留 1 位小数。`--` 表示指标适用但当前没有有效执行记录，与常规维系表示不适用的 `-` 不同。
- 该指标表达有限任务主题的全生命周期累计推进程度，不是本月、本季度或当前这一轮的完成率。
- 任务总览只展示上述百分比结果，不展示分子/分母或进度条；分子等于分母且分母大于 0 时显示 `100.0%`。最低/最高进度筛选只使用这一实时结果，不建立新的指标或存储字段。

算例：某个有限任务主题包含已完成 4 条、待执行 / 暂停 3 条、当前逾期 1 条、补录审核中 1 条、已过期未完成 1 条时，有效任务执行记录总数为 10 条，任务完成进度为 `4 / 10 = 40.0%`。该数据仅用于解释口径，不是产品默认数据。

完成进度的精确来源：

- `DEC-049《任务主题指标和状态采用执行任务实时计算》`：[`prd-workspace/decisions/DEC-049-任务主题指标和状态采用执行任务实时计算.md`](../../decisions/DEC-049-任务主题指标和状态采用执行任务实时计算.md) → “决策”（实时聚合和有效统计集合继续有效；旧四态已被 DEC-196 替代，常规维系的进度适用性已被 DEC-199 替代）。

- `DEC-196《父任务状态仅表达时间生命周期并以完成进度表达执行结果》`：[`prd-workspace/decisions/DEC-196-父任务状态仅表达时间生命周期并以完成进度表达执行结果.md`](../../decisions/DEC-196-父任务状态仅表达时间生命周期并以完成进度表达执行结果.md) → “完成进度展示与筛选”与“边界”（常规维系的完成进度适用性已被 DEC-199 替代）。

### 6.2 生成、续期与规则快照

M03 生成任务时读取 M09 当前有效规则，校验 M02 的关键人/任职、M08 的责任和 M06 的人员资格，并保存当时规则与责任快照。生成失败从最后成功扫描位置继续，不跳过未扫描区间，也不创建“失败任务”业务状态。

常规维系完成后，以实际维系日加完成时当前职级周期生成下一条执行记录并复用父任务编号。未完成常规任务不自动生成下一期；无论逾期多久都持续当前逾期，直至补完成或由客户侧对象停用、关键人调岗、取消等已确认流程关闭/迁移。当前阶段员工停用直接取消该员工全部未完成任务，不生成下一期、不改派且不逐条发起取消审批；完整版本的交接式停用不属于当前规则。

M09 配置变化只影响新生成任务：

- 不回写历史任务；
- 不批量重算已有任务；
- 不改变已有任务的规则、责任或对象快照；
- M03 不提供配置编辑、重算预览或批量重算入口。

DEC-102、DEC-110 和 Shared 06 中的相反表达统一作为 `Historical / Replaced Evidence`，不得据此恢复重算能力。

### 6.3 完成、延期、暂停、取消与补录

- 正常完成必须同时形成正式维系记录和任务完成认定；任一环节失败整体不生效。
- 延期的新截止必须晚于当前截止且最多延后 90 日；专项维系和覆盖 KPI 没有单项延期。
- 暂停至必须晚于当前时点且最长 365 日。只有当前未逾期且从未逾期的常规维系、生日关怀和节假日关怀记录可申请；专项维系和关键人覆盖 KPI 不允许暂停。提交和审批生效时均校验资格，审批生效前已逾期时暂停不生效，任务保持当前逾期并由 M04 记录业务处理失败。
- 暂停期间归入“待执行 / 暂停”，暂停提醒和普通完成入口；不会因时间越过当前截止而进入当前逾期，不形成“曾经逾期”或“首次逾期时间”，也不影响客户/关键人健康状态或维系健康率。
- 常规维系到达暂停至日期时，以恢复日期读取关键人当前职级和该职级当前有效周期，按“恢复日期 + N 个自然日”重算当前截止至当日 `23:59:59`；原截止永久保留，历史记录旧/新当前截止、恢复时职级、周期和恢复时间。恢复后进入待执行，并从新当前截止重新判断后续逾期。
- 生日/节假日暂停至日期未越过当前截止时恢复为待执行并沿用原当前截止；暂停期间一旦越过当前截止，记录自动关闭并退出有效任务集合，不进入任务完成进度分子或分母，也不形成已过期未完成、曾经逾期或首次逾期时间。未暂停的生日/节假日越过截止后仍进入已过期未完成。
- 取消原因 5-500 字；通过后退出有效任务集合并保留历史，不计完成。
- 员工停用级联取消使用 M06 已确认的停用原因，不要求为每条任务重复填写原因或建立 M04 审批；取消保留任务编号、原执行人、前后状态、实际停用操作人、时间和员工停用关联。员工恢复不恢复这些已取消任务。
- 逾期补录要求实际维系时间不晚于当前截止、原因 5-500 字且至少 1 个合法证明附件；审批通过前不完成、不续期。
- 逾期补完成要求实际时间晚于当前截止且任务类型允许，不进入补录审批。生日、节假日和覆盖 KPI 当前不提供入口；AC-F008-44 已按 DEC-163 治理，旧 7 天窗口只作 Historical / Replaced Evidence。
- 专项维系是否允许逾期补完成及其最后截止来自专项快照；超过专项允许截止后拒绝。

暂停规则的精确来源为 `DEC-200《暂停任务不形成逾期并按任务类型恢复或关闭》`：[`prd-workspace/decisions/DEC-200-暂停任务不形成逾期并按任务类型恢复或关闭.md`](../../decisions/DEC-200-暂停任务不形成逾期并按任务类型恢复或关闭.md) → “决策”“暂停期间”“常规维系恢复”“生日/节假日恢复或关闭”。暂停是“待执行 / 暂停”分类中的受控事实，不创建第六个互斥状态。

### 6.4 专项通用字段

| 字段 | 录入/展示 | 必填与规则 |
| --- | --- | --- |
| 专项分类 | 单选 | 必填；专项维系或关键人覆盖 KPI |
| 标题 | 文本 | 必填；长度按现有 F009 规则校验 |
| 发布人 | 只读 | 当前实际发布人，受角色权限约束 |
| 开始日期 | 日期 | 必填；不能晚于结束日期 |
| 结束日期 | 日期 | 必填；发布后作为全部执行项唯一截止，结束后不可修改 |
| 执行说明 | 多行文本 | 必填；按现有 F009 长度规则校验 |

专项不设置草稿状态，也不提供保存草稿操作。正式发布成功时才建立专项、父任务、正式任务编号和执行项；发布重试只形成一个专项、一个一对一父任务、一项二者共用的 `MT` 任务编号和一组唯一执行项，不得另建专项业务编号。专项与父任务状态一致，内部稳定 ID 及对象关联继续保留。

### 6.5 专项维系字段与匹配

专项维系在通用字段之外使用：行业、集团、区域、省市、客户公司、采购决策人、职级、标准岗位、逾期补完成开关/截止和标题模板。

- 空维度表示不限制，多个维度取交集；全部为空时必须显式确认全范围预计关键人数。
- 采购决策人支持全部、仅采购决策人、排除采购决策人，不改变关键人普通列表排序。
- 目标对象使用 M02/M09 稳定 ID 和当前有效任职，不复制客户或关键人字段。
- 有效期内新增、调岗或职级变化按专项原规则动态进入/退出范围，并防止重复执行项。
- 专项结束后冻结结果；未完成项进入已过期表达，不再新增匹配。

### 6.6 关键人覆盖 KPI 字段与口径

覆盖 KPI 使用：集团、目标业务责任层级、业务责任区域范围、覆盖维度、目标客户部门或标准岗位、只读岗位口径类型、目标覆盖率和只读截止。

- 覆盖维度只能是客户部门或标准岗位；切换维度清空另一维度目标并要求重新选择。
- 目标部门和岗位使用 M09 当前稳定 ID，不提供自由文本或自定义岗位。
- 分母为授权范围内正常的目标层级客户公司；目标需覆盖数按“分母 × 目标率”向上取整。
- 每名责任人生成一条聚合执行项；省级业务责任客户由业务责任省所属区域总监执行，市级/区县级业务责任客户由业务责任城市当前负责人 PM 执行。
- 系统按所选部门或岗位的覆盖事实自动达标，不能人工完成；有效期内失去达标条件时复用原执行项重新打开，恢复后再次自动完成。
- 分母为 0 时显示 `--`，不触发低进度动态。

跨多个客户公司的覆盖 KPI 必须使用稳定部门/岗位 ID 组成目标集合，不按名称匹配或合并同名对象，也不恢复集团共享部门。多个稳定 ID 在页面中的展示顺序或分组细节若未定义，可标 `Clarification / Governance Needed`，但不影响该 Current Rule。

### 6.7 维系记录字段

| 字段 | 必填/默认 | 只读与规则 |
| --- | --- | --- |
| 记录 ID / 编号 | 系统生成 | 稳定 ID 和 `WH-YYYYMMDD-六位流水`，全局唯一且不可回收 |
| 记录状态 | 系统生成 | 正式生效、补录审核中或补录驳回；默认列表只显示正式生效 |
| 关键人 | 必填 | 使用稳定 ID；上下文入口锁定，全局入口无默认 |
| 客户公司 / 当前任职 | 从关键人读取 | 只读，不接受展示文本作为独立输入 |
| 维系方式 | 必填 | 电话、微信、线下拜访、视频会议、邮件、其他；“其他”需 2-30 字说明 |
| 维系时间 | 必填 | 不晚于当前时间，不早于当前任职生效时间 |
| 沟通摘要 | 必填 | 5-1000 字；禁止纯重复字符、纯标点或纯空白 |
| 客户反馈 | 必填 | 5-1000 字；禁止纯重复字符、纯标点或纯空白 |
| 下一步计划 | 可空 | 0-1000 字；不自动生成任务 |
| 附件 | 可空 | 最多 9 个、合计 100 MB；执行统一格式、MIME、文件头、预览和权限规则 |
| 关联任务 | 可空、只读 | 已完成维系类任务必须唯一关联正式记录 |
| 维系人 / 录入人 | 系统记录 | admin 代办时同时保留原业务维系人、管理员录入人和原因 |

同名关键人或展示文本不能替代稳定 ID。提交时重新校验关键人状态、当前任职、责任和权限；对象失效时阻止保存并保留合法输入。

### 6.8 维系记录编辑与附件

- 任何已保存的维系记录，无论是否关联任务，都只能按权限追加附件；关键人、当前任职/客户公司、维系方式、维系时间、摘要、反馈、下一步计划、关联任务、维系人和录入人全部只读。
- 已有附件不能删除、解除关联或替换；追加附件不改变任务完成认定，也不重新匹配任务。
- 图片和 PDF 可按权限在线预览；Office 文件展示元数据并按受控下载规则获取。
- 文件扩展名、MIME、文件头、数量、总大小或安全检查不通过时，仅拒绝非法或超限文件，保留其他输入和已经通过的附件。

补录驳回记录的长期入口、是否可基于原记录重提及其与原审批的关系仍未完整定义；不得借“追加附件”入口自行补造重提流程。

## 7. 状态与反馈

### 7.1 页面状态

| 页面状态 | 产品表达 |
| --- | --- |
| Loading | 页面、列表、详情或影响数据加载中，保留稳定布局 |
| Empty | 当前授权范围没有任何记录或执行项 |
| Empty Result | 存在数据但当前筛选无命中，保留筛选并提供重置 |
| Error | 页面或局部加载失败，保留条件/上次成功值并允许重试 |
| PermissionDenied | 返回 403，不显示对象名称、数量、状态、附件地址或是否存在 |
| Submitting | 保存、完成、发布或申请正在提交，阻止重复操作 |
| Success | 操作完成后显示结果并刷新对应对象，不改变无关上下文 |

### 7.2 父任务状态

父任务或任务主题只使用：待开始、进行中、已结束。状态只表达时间生命周期，不表达执行完成结果：有有效执行记录时，开始时间未到为待开始；开始后且尚未超过结束时点为进行中；超过结束时点为已结束。完成数量和任务完成进度不参与状态判断，因此有效期内达到 `100.0%` 仍为进行中，结束后无论进度是否为 `100.0%` 均为已结束。常规维系没有结束时间，开始后持续为进行中；零执行项显示空态，不增加第四个父任务状态。

### 7.3 任务执行记录当前分类

有效任务执行记录使用五类互斥当前分类。这里的“已完成”是单条执行记录的完成结果，“已过期未完成”是单条记录不再允许执行的未完成终态；当前产品不存在笼统的执行记录“已过期”分类。它们也不等于 7.2 的父任务时间生命周期状态。

| 当前分类 | 用户可观察含义与业务事实 | 有限任务完成进度口径 | 后续执行记录 |
| --- | --- | --- | --- |
| 已完成 | 单条执行记录已经形成有效完成认定，包括按期完成、审批通过后认定按期的逾期补录、逾期后补完成，或覆盖 KPI 系统达标 | 计入分母和分子 | 只有常规维系按 6.2 以实际维系日和当前职级周期生成下一期；其他类型不因“已完成”自动套用常规续期 |
| 待执行 / 暂停 | 单条记录尚未完成且当前未进入逾期；批准暂停后暂停提醒和普通完成入口，暂停期间不形成逾期或健康风险 | 计入分母，不计入分子；生日/节假日暂停越过截止自动关闭后退出分母 | 不生成下一期；常规维系恢复时重算当前截止，生日/节假日按是否越过截止恢复或关闭 |
| 当前逾期 | 已超过当前截止、尚未完成，但该类型仍允许继续执行或补完成 | 计入分母，不计入分子 | 未完成常规维系不生成下一期，并持续当前逾期，直至补完成或受控关闭/迁移 |
| 补录审核中 | 用户在截止后提交了“实际维系时间不晚于当前截止”的补录证明，正在等待 M04 审批 | 计入分母，审批通过前不计入分子 | 审批通过后转为已完成并按适用规则续期；驳回后回到当前逾期 |
| 已过期未完成 | 该类型已经越过允许执行或补完成的边界，当前记录不再允许完成；生日/节假日越过截止即进入本分类，专项维系按发布快照的允许截止判断 | 计入分母，不计入分子 | 当前记录不生成下一期；后续新周期或新事件是否生成新记录仍按对应任务生成规则处理 |

取消或关闭记录退出有效集合并保留历史，不作为第六类当前状态；对适用任务完成进度的有限任务，不进入分子或分母，也不因取消/关闭生成下一期。常规维系不适用任务完成进度，但取消或关闭仍退出其有效执行数量集合。按期完成、逾期登记但审批认定按期、逾期后补完成和系统达标属于“完成认定”，不是另一套当前状态。

父任务层面不再使用“已完成 / 已过期”：父任务、任务主题和发布后专项只按起止时间展示“待开始 / 进行中 / 已结束”，即使完成进度达到 `100.0%` 也不会提前结束。精确来源：

- `DEC-196《父任务状态仅表达时间生命周期并以完成进度表达执行结果》`：[`prd-workspace/decisions/DEC-196-父任务状态仅表达时间生命周期并以完成进度表达执行结果.md`](../../decisions/DEC-196-父任务状态仅表达时间生命周期并以完成进度表达执行结果.md) → “决策”“边界”“替代关系”。
- `DEC-197《专项不设置草稿并在校验通过后直接发布》`：[`prd-workspace/decisions/DEC-197-专项不设置草稿并在校验通过后直接发布.md`](../../decisions/DEC-197-专项不设置草稿并在校验通过后直接发布.md) → “决策”“替代关系”。
- Shared Product Facts：[`prd-workspace/current/shared/04-core-objects-and-states.md`](../shared/04-core-objects-and-states.md) → “维系任务状态与完成认定”。
- `FLOW-08《shared-maintenance-state》`：[`prd-workspace/current/user-flows/FLOW-08-shared-maintenance-state.md`](../user-flows/FLOW-08-shared-maintenance-state.md) → 主状态图及其 Current 定位说明。
- Acceptance：[`prd-workspace/current/acceptance/M03.md`](../acceptance/M03.md) → `AC-F008-33`、`AC-F008-43`、`AC-F008-44`、`AC-F008-45`、`AC-F008-53`、`AC-F009-35`。

“暂停中”只表示“待执行 / 暂停”分类内已获批且尚未结束的暂停事实，不是新的互斥持久状态。申请资格、生效复核、健康排除、恢复和自动关闭详见 DEC-200 的对应章节。

### 7.4 专项状态

正式专项只使用：待开始、进行中、已结束。专项不设置草稿状态；发布后与其唯一父任务保持一致，只按起止时间判断，不因任务完成进度达到 `100.0%` 提前结束。专项执行项继续使用任务执行记录分类，不能把两层状态混成统一状态机。

### 7.5 维系记录状态

维系记录使用：正式生效、补录审核中、补录驳回。默认记录列表只显示正式生效；补录审批通过后转为正式记录，驳回后不改变当前逾期任务。

### 7.6 M04 外部审批状态

审批中、已通过、已驳回、已通过-业务处理失败和处理人失效由 M04 拥有。M03 只显示关联状态、流程编号和有权跳转，不把这些状态写入任务或记录状态机。

### 7.7 P01 消息结果

到期提醒、逾期升级通知、发送成功/失败和消息已读属于 P01 消息结果。消息发送失败不回滚已生效任务事实，也不产生“失败任务”状态；M03 只保留可追踪的通知结果。

### 7.8 错误与操作反馈

| 类型 | 场景 | 反馈与保护 |
| --- | --- | --- |
| 页面错误 | 任务、专项、记录或详情加载失败 | 保留筛选或上次成功值、更新时间和重试入口 |
| 生成失败 | 调度或任务生成失败 | 从最后成功位置重试，不跳过区间，不创建失败状态 |
| 完成失败 | 记录、附件、认定或续期任一步失败 | 整体不生效，任务保持原状态，表单与临时附件可重试 |
| 补录阻断 | 实际时间、原因或证明附件不合法 | 不建立审批、不提前完成，字段级说明原因 |
| 日期非法 | 未来维系时间、早于任职、专项起止或延期/暂停日期非法 | 就地提示并保留其他合法输入 |
| 附件错误 | 格式、MIME、文件头、数量、大小或检查失败 | 拒绝问题文件，保留已通过附件和其他输入 |
| 对象失效 | 客户、关键人、任职或当前责任失效 | 重新校验后阻止提交，不基于过期上下文写入 |
| 外部流程冲突 | 客户侧停用/恢复、关键人调岗、员工停用或责任变化与当前操作冲突 | 按外部生效结果关闭、取消、迁移、重算或阻断，不建立第二套状态；当前员工停用取消该员工全部未完成任务 |
| 并发或重复 | 对象版本变化或重复提交 | 重复请求复用原结果；变化时提示冲突和最新摘要，不静默覆盖 |
| 无权限 | 菜单、候选、详情、附件或直接地址越权 | 403 且不泄露对象信息 |
| 影响预览失败 | 专项目标或结束日期变化无法计算影响 | 当前反馈口径未完整定义，保留 Clarification，不自行决定是否保存 |

错误码、发送失败、加载失败或保存失败都属于页面/操作反馈，不得直接成为任务、专项或维系记录业务状态。

## 8. 用户流程

### 8.1 当前产品流程

1. **规则生成：** 读取 M09 当前规则和稳定对象事实 → 校验关键人、任职、责任和人员资格 → 防重建立父任务/执行记录 → 保存规则、对象和责任快照 → 输出提醒事件。
2. **正常完成：** 当前执行人提交 F010 维系记录 → 校验当前截止和对象 → 同一结果中保存记录与完成认定 → 常规任务按实际维系日和当前职级周期生成下一期。
3. **逾期补录：** 当前逾期且实际时间不晚于当前截止 → 填写原因并上传证明 → 进入 M04 审批 → 通过后记录正式生效并认定按期，驳回回到当前逾期。
4. **逾期补完成：** 实际时间晚于当前截止 → 按任务类型和快照判断是否允许 → 保存正式记录并认定逾期后补完成；不进入补录审批。
5. **专项发布与执行：** 填写发布表单 → 发布预览和确认 → 校验通过后建立专项、唯一父任务与执行项 → 有效期内动态匹配 → 维系记录完成或覆盖事实自动达标 → 结束后冻结；校验或预览未通过时保留当前表单输入，但不创建任何对象。
6. **主动维系记录：** 选择稳定关键人 → 匹配 0、1 或多条本人有效常规任务 → 分别独立保存、同一结果闭环或阻断告警。

### 8.2 FLOW-03：任务异常

[FLOW-03](../user-flows/FLOW-03-M03-task-exception.md) 是延期、暂停、取消和逾期补录的 Current Product Flow。补录沿用前面已按业务责任层级解析的审批节点：市级/区县级业务责任客户进入区域总监，省级业务责任客户进入市场副总、角色空缺或继续上提时由总裁处理。DEC-163 已消除旧的“全部补录固定区域总监”解释。

### 8.3 FLOW-08：维系状态

[FLOW-08](../user-flows/FLOW-08-shared-maintenance-state.md) 是任务执行五类状态与完成认定的 Current Mechanical Evidence。其旧“生日/节假日超过规则窗口”措辞按 DEC-125/147/163 仅作 Historical / Replaced Evidence；Current 分支是越过截止直接进入已过期未完成。

FLOW-08 不授权新增节令补完成入口，也不把完成认定、暂停、审批或提醒混入同一状态机。

### 8.4 FLOW-12：任务异常审批

[FLOW-12](../user-flows/FLOW-12-M03-task-exception-approval.md) 是与 FLOW-03 同义的 Current Product Flow。补录箭头复用前述业务责任层级节点，不得解释为省级业务责任客户固定送区域总监。

### 8.5 外部流程归属

- 关键人调岗及任职生效属于 M02；
- 任务异常和补录审批容器属于 M04；
- 客户侧停用/恢复属于 M05；
- 地市责任迁移属于 M08；
- 消息投递和已读属于 P01。

M03 只消费这些流程的生效结果并处理自身任务、专项或记录，不复制外部流程。

## 9. 权限边界

### 9.1 M03 拥有

- 父任务、任务执行记录、专项、专项维系执行项、覆盖 KPI 执行项和维系记录；
- 生成后的规则/责任/对象快照、当前分类、完成认定、关闭/取消和历史；
- 专项目标、发布、动态匹配、进度和冻结结果；
- 维系记录与附件关联，以及任务完成的一致性结果。

### 9.2 M03 不拥有

- 客户主数据、关键人身份和任职普通维护；
- 职级周期、提醒、生日/节假日规则、年度日历和标准岗位配置源；
- 区域、省市或客户负责人关系；
- 员工、账号、内部部门或系统角色；
- 权限模板和个人权限例外；
- 停用/恢复申请、影响历史或审批容器；
- 通用审批实例、节点和处理动作；
- 导入批次生命周期；
- 消息中心已读/未读状态或工作台页面。

### 9.3 数据范围与直接访问

列表、筛选候选、数量、详情、附件、工作台下钻和消息跳转使用同一最终权限。区域总监按本人主管的全部区域中心并集，PM 按当前有效负责地市；范围不可用时失败关闭。

权限、责任或人员资格变化后，写操作立即重新校验。失权页面不能继续展示缓存对象；无权入口隐藏，直接访问统一返回 403，不泄露对象名称、状态、数量、附件或是否存在。

### 9.4 M07 只能收紧

M07 可以收紧 M03 的菜单、页面、操作、字段和附件权限，但不能：

- 给 HR/人事新增 M03 客户业务权限；
- 扩大区域总监或 PM 的责任范围；
- 改变任务执行人、专项发布人或审批路由；
- 允许普通角色跨范围查看、完成、补录或编辑记录；
- 允许通过字段权限修改 M09 配置、M02 对象或 M08 责任。
