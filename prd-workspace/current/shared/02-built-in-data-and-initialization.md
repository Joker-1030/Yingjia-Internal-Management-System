## 系统内置数据与上线业务初始化

系统必须区分“随产品发布、任何环境都必须存在的系统内置数据”和“根据英嘉科技实际组织及客户资料建立的上线业务初始化数据”。系统内置数据由部署迁移脚本幂等创建和升级；上线业务初始化数据由实施人员在正式启用前按本稿页面规则配置或导入，不得把演示账号、演示客户或固定业务名称写入产品代码。

### 系统内置数据

| 对象 | 必须内置的内容 | 初始化与保护规则 |
| --- | --- | --- |
| 系统角色 | 总裁 `PRESIDENT`、市场副总 `MARKET_VP`、区域总监 `REGIONAL_DIRECTOR`、PM `PM`、HR/人事 `HR`、系统管理员 `ADMIN` | 角色 ID 和编码稳定且永久唯一；重复部署复用原对象，不重复创建；角色名称可随产品升级显示新文案但编码不变 |
| 角色范围规则 | 公司全局、全国市场、所属区域、负责地市、公司组织 | 按本稿角色数据范围固化；不依赖上线人员姓名或部门名称 |
| 系统管理员账号 | 唯一内置 `admin` 系统账号及其 `ADMIN` 绑定 | 不绑定普通员工角色，不允许在 F001/F002 删除、停用或转移；部署时生成符合密码策略的初始密码并通过安全渠道交付，本期不设有效期、不强制首次修改，不得内置公开默认密码 |
| 权限树与依赖 | F001-F015 与 M11 的菜单、页面、操作、字段和附件权限键及父子依赖 | 权限键可幂等升级，不得复用旧键表达新含义；系统管理员模板始终全权限，其余五个角色按产品默认模板初始化后可由 admin 调整，但不能突破业务不变量 |
| 职级周期 | 一级、二级、三级、四级四条固定配置 | 默认周期依次为 7、15、30、45 自然日，默认提醒节点为 3、1、0；首次初始化后由有权角色按 M09 修改并形成配置版本 |
| 通用枚举与编号序列 | 本稿定义的状态、来源、流程和业务编号序列 | 部署升级不得重置、回收或从头覆盖既有业务编号 |

### 上线业务初始化

| 对象 | 首批上线要求 | 建立方式与启用条件 |
| --- | --- | --- |
| 内部组织与员工 | 总经办、综合运营部、财务部、咨询产品部、师资管理部、市场运营部、能源事业部、软件研发部，以及市场运营部下的山东、江苏、华南、浙江区域运营中心；实际员工和账号以启用前确认名单为准 | 属于英嘉科技业务数据，不是通用产品种子；由实施初始化后交 HR/admin 在 F001 持续维护；四个区域运营中心必须保存为正常部门且“是否区域中心=是” |
| 员工系统角色关联 | 全部员工对应的总裁、市场副总、区域总监、PM、HR/人事人工角色（每人 1-5 个）及可追溯自动角色 | 员工由 HR/admin 建立或编辑时直接关联人工角色；区域中心主管缺失区域总监角色时自动增加且不占人工上限，不维护内部岗位库和岗位角色映射；地市负责人候选在启用前通过角色校验 |
| 区域与地市责任 | 四个区域中心的主管、关联省份、驻地城市及首批地市负责人 | admin 在 M08 配置（市场副总可编辑关联省份，区域总监可分配本区域地市责任）；存在正常客户的省份和地市必须先完成责任配置，才能批量建立对应客户单位和生成任务 |
| 客户基础数据 | 行业、集团公司、客户单位、客户部门、标准关键人岗位和首批关键人 | 行业、客户部门和标准岗位不提供虚构通用默认值；由业务确认后在 M09 配置或按 M10 导入。候选为空时页面显示对应空态并提供有权入口，不得静默使用 Demo 数据 |
| 生日/节假日任务规则 | 预置的生日关怀和节假日关怀规则集合 | 规则集合上线时按业务确认结果预置；页面不提供新增入口，仅支持编辑既有规则和启用/停用 |
| 项目基础配置 | 首批采购包、课程方向、平台公司及若干临时虚拟讲师候选 | 采购包和平台公司由 admin 在 M11 维护；临时虚拟讲师只支持当前项目人员选择和排期校验，不形成正式讲师管理模块 |
| 历史项目 | 需要保留的进行中、已交付或已完成项目基本信息 | 初始化期通过 M10 项目模板按公司/省级本人/市区县本人范围导入；成功行生成新 XM 编号，项目资料和满意度后续单独维护；初始化结束后关闭新上传并长期保留批次报告 |

内部组织、员工和部门主管关系的首批建立使用一个“组织关系原子初始化批次”。实施人员先在模板中为部门和员工填写全局稳定编码，再通过编码声明员工的一个或多个平级所属部门、人工系统角色及部门主管，因此允许同一批次内前向引用尚未落库的对象。主管尚非部门成员时自动增加成员关系；区域中心主管缺失区域总监角色时自动增加带来源角色。系统先完成工作簿结构、编码唯一、引用存在、员工状态、系统角色和主管资格校验；全部通过后同时建立组织、员工、账号、部门成员、角色关联和主管关系。任一行失败时整批不生效，错误报告精确到工作表、行号、字段、错误码和修复建议。该初始化通道仅在“初始化未完成”状态对实施 admin 开放；正式启用后关闭。

正式启用检查必须验证：六个角色及编码唯一、admin 可使用安全交付的初始密码登录（不强制首次修改）、原子初始化批次已成功、员工角色关联无责任阻断、四个区域中心标记正确、存在客户的省份和地市均有负责人、四级周期配置存在。任一检查失败时系统保持“初始化未完成”，仅允许 admin 和 HR 进入其有权的初始化页面；不得向业务角色开放不完整客户经营、任务或审批数据。
