# DEC-178：页面筛选使用常驻标签并按业务字段拆分

- 日期：2026-08-27
- 状态：已确认
- 背景：现有列表和管理页部分筛选项依赖 placeholder、下拉首项或 `title` 说明含义，并使用一个关键词框同时匹配编号、名称、客户、人员、摘要等多个业务字段。筛选生效或输入内容后，用户难以持续判断每个条件的准确含义。
- 决策：
  1. 所有页面级筛选控件使用始终可见的独立字段标签，placeholder、首个选项和 `title` 不替代标签；标签紧邻对应控件左侧并与控件同行展示，筛选区换行时按“标签 + 控件”整组换行，不改为标签在控件上方；日期起止分别标明完整含义。
  2. 不同业务字段分别提供筛选项。项目编号与项目名称、关键人编号与关键人名称等字段不得共用一个关键词框。
  3. 同一结果集内多个已填写筛选字段按 AND 取交集；同一多选字段继续取并集。独立分类结果区由各自字段过滤，不强制不同对象类型互相求交。
  4. 本决策只改变筛选项表达和字段匹配边界，不改变候选、默认值、权限、数据范围、排序、分页、空态和业务生命周期。
  5. 可搜索选择器内部用于定位同一候选对象的名称/编码匹配继续有效，不视为页面级聚合筛选。
- 替代关系：替代 Shared 03 及 M02、M03、M06、M07、M08、M09、M10、M11 中一个关键词匹配多个业务字段的旧表达；M04 已分离的流程编号与业务对象名称规则继续有效，M05 的对象名称单字段筛选继续有效。
- 布局治理：标签在控件上方的实现自 2026-08-28 起为 Historical / Replaced，当前规则为标签在左、控件在右、同行成组展示。
- 未采用方案：保留聚合关键词框，仅通过 placeholder 罗列匹配字段；使用浮动提示或 Tooltip 代替常驻标签；拆分字段但继续让任一输入匹配其他字段。
- 原因：让用户在输入前后都能明确知道每项筛选的对象和口径，减少对编号、名称及其他字段匹配范围的猜测。
- 决策人：Product Owner
- 影响范围：M02、M03、M04、M05、M06、M07、M08、M09、M10、M11、P01、Acceptance、Shared、Prototype
