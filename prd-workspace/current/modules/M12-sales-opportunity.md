# M12 销售与商机管理

- 文档状态：Active modular PRD Source of Truth
- Product Status：CURRENT
- Product Review Status：NOT REVIEWED
- Engineering Status：NOT STARTED
- Source of Truth：本文件（M12）；模块集合入口为 `prd-workspace/current/PRD.md`
- 当前收口依据：DEC-194

## 1. 模块目标

M12 用同一组当前销售事实完成三件事：逐级分配可核对的商机数量目标；查看销售仪表盘和当前商机快照；持续创建、推进、跟进并协同支撑商机。

日常沟通中的“线索”只描述处于商机录入、需求确认等早期阶段的商机。系统不建立独立线索对象、线索菜单、线索字段或另一套生命周期。

## 2. 当前范围

### 2.1 包含

- 销售仪表盘；
- 商机数量指标的公司、区域和 PM 逐月分配、版本和调整；
- 商机列表、新建、详情、改派和顺序推进；
- 商机跟进记录、下一步行动和逾期提醒；
- 一人或多人方案支撑请求、响应、交付和关闭；
- 与 M04 的指标调整审批关系，以及与 P01 的跟进/支撑消息关系。

### 2.2 不包含

- 独立 Lead/线索对象、菜单、字段、状态或转商机流程；
- 合同管理对象、合同页面、合同归档、补充协议或合同撤销；
- 财务系统角色；
- 回款、开票、预计成本、毛利或财务确认；
- 已签约商机阶段、签约金额/数量目标及完成值；
- 因 M12 上线而改变 M11 当前人工创建项目的规则；
- 从历史销售 Demo、旧增量或实现代码恢复上述能力。

## 5. 页面结构

M12 一级入口包含：

1. `销售仪表盘`：默认页，查看周期目标与完成、当前商机概览、阶段漏斗、趋势和区域覆盖；
2. `商机列表`：筛选、分页查看商机，并进入新建和详情；
3. `销售指标`：由有权角色从仪表盘进入，维护目标、分配、版本和调整。

商机详情包含：

- 基本信息；
- 方案支撑；
- 流转与跟进记录。

所有页面级筛选遵循 Current 统一规则：编辑条件不会立即筛选，点击“筛选”后生效，重置清空条件并回到第 1 页；不展示“筛选结果 N 项”等结果说明。

## 6. 销售指标

### 6.1 当前指标维度

当前只维护 `商机数量` 目标：完成值取权限范围内在所选周期有效创建、且未被停用或认定重复的商机数；正常落选仍保留创建事实，周期按商机创建日期。

签约金额、签约数量、回款金额和毛利金额不属于 Current M12 指标维度。页面不得为这些未接入事实提供维护入口，也不得用 0 表达“尚无数据源”。

### 6.2 粒度与守恒

1. 指标按自然年度建立，月份是最小分配粒度；季度和年度由月份汇总。
2. 每月区域目标合计必须等于公司目标；每月 PM 目标合计必须等于所属区域目标。
3. 初次分配在守恒校验通过后直接发布：市场副总分配区域，区域总监分配本区域 PM；总裁和系统管理员可覆盖任一层级。
4. 已发布目标调整形成新版本。总裁和系统管理员调整直接生效；市场副总调整区域目标由总裁审批；区域总监调整 PM 目标由市场副总审批，市场副总岗位空缺时由总裁处理。
5. 调整审批中继续使用最近生效版本；驳回不改变当前目标。
6. 人员、区域或责任变化不改写历史月份目标；只允许调整当前月及未来月份，且调整后继续满足守恒。
7. 版本保留调整前后值、差额、原因、操作人、审批实例和生效时间，只追加不覆盖。

## 7. 销售仪表盘

仪表盘把“所选周期”和“当前快照”明确分开：

- 所选周期：商机数量目标、完成、差额、完成率和新建商机趋势；
- 当前快照：全部商机数、活跃商机数/金额、中选数/预计金额、落选数/预估金额、阶段漏斗、客户商机覆盖和区域对比。

规则：

1. 活跃商机为商机录入、需求确认、方案支撑、比选或中选阶段，排除落选、停用和认定重复。
2. 活跃金额在商机录入至比选阶段使用预估金额，中选阶段使用预计签约金额。
3. 中选率为有效中选结果数除以有效中选与落选结果数；未形成结果的活跃商机不进入分母。
4. 客户单位当前存在至少一条活跃商机时视为有商机覆盖；只有历史落选商机不构成当前覆盖。
5. 趋势展示新建和中选事件，支持数量/金额切换；合同或财务事件不进入 Current M12 趋势。
6. 用户可从数值、漏斗或区域行进入同口径商机明细；落地条件可见、可修改、可重置，数量一致。
7. 无数据时数值可显示 0、比率显示 0%；查询失败或外部数据未接入不能显示为 0。

## 8. 商机列表与新建

### 8.1 列表

列表默认按最近更新时间倒序，独立展示：商机编号、商机名称、商机类型、阶段、客户单位、当前有效金额、优先级、当前阶段停留时间、负责人、创建时间和创建人。

筛选项：商机编号、商机名称、商机类型、阶段、客户单位、业务责任区域、负责人、优先级、预计成交日期、创建日期、跟进是否逾期。商机名称模糊匹配；商机编号精确匹配；多个已应用条件取交集。

### 8.2 新建字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 商机名称 | 是 | 表达本次销售机会 |
| 商机类型 | 是 | 培训商机、AI 项目商机 |
| 预估金额 | 是 | 大于或等于 0 |
| 优先级 | 是 | 高、中、低 |
| 客户单位 | 是 | 只从当前账号有权范围内的正常客户单位选择 |
| 客户关联信息 | 只读派生 | 集团、行业、业务责任区域和客户负责人读取 Current 客户事实，不在商机重复维护 |
| 商机关键人 | 是 | 从所选客户单位当前有效关键人中多选；切换客户后清空失效选择 |
| 商机需求描述 | 是 | 记录本次机会的明确需求 |
| 预计成交日期 | 是 | 作为销售预期，不替代跟进日期 |
| 商机负责人 | 是 | PM 新建默认本人；其他有权角色按范围选择有效 PM |
| 首次跟进日期 | 是 | 不早于下一业务日，形成当前跟进承诺 |
| 同时创建方案支撑 | 是 | 默认否；选择是后填写支撑人员和回应时限 |
| 支撑人员 | 条件必填 | 一名或多名在职员工 |
| 回应时限 | 条件必填 | 默认创建后 48 小时，保存为明确截止时间 |

保存成功后生成全局唯一且永久保留的商机编号、创建时间和首条“商机录入”阶段记录。重复提交只产生一条商机和一组支撑请求。

## 9. 商机阶段与改派

当前阶段主链路：

```text
商机录入 -> 需求确认 -> 方案支撑 -> 比选 -> 中选
     \           \           \        \       \
      +-----------+-----------+--------+------> 落选
```

1. 主链路只能逐级前进，不允许跳过或退回。
2. 任一未落选阶段可进入落选；进入落选必须填写落选原因、竞争对手和复盘说明。
3. 进入中选必须填写中选日期和预计签约金额。中选仍可跟进，等待未来独立合同能力；M12 不提供已签约按钮或状态。
4. 落选是 Current M12 终态，不再显示阶段推进或新增跟进入口。
5. 每次变化保留原阶段、新阶段、生效时间、操作人和阶段必填事实，不覆盖历史。
6. 当前阶段停留时间从最近一次阶段生效时间自动计算；落选后冻结。
7. 仅当前负责人可正常推进和跟进；区域总监必须先在本区域有效 PM 间改派，不能直接代推进。系统管理员代操作保留真实身份，不改写负责人。
8. 改派保留前后负责人、原因、操作人和生效时间；过程指标按事件发生时负责人归属，后续改派不改写历史。

客户停用、负责人停用或负责人失去范围时，不允许继续推进；有权管理者先完成合法改派或处理客户状态。

## 10. 方案支撑

1. 商机创建时或创建后可向一名或多名在职员工发起支撑请求；每名支撑人员生成一条独立请求并独立计时。
2. 状态依次为：待响应、已响应、支撑中、已交付、已关闭。
3. 支撑人员确认接收后为已响应；首次提交过程内容后为支撑中；提交可预览附件或明确交付说明后为已交付；商机负责人确认接收后为已关闭。
4. 负责人要求补充时退回支撑中并保留意见；待响应可撤回，已响应后关闭原请求并重新发起，不覆盖历史。
5. 首次有效回应超过截止时间时，向商机负责人和支撑人员直属主管发送消息；已交付或关闭不删除既有超时事实。
6. 被指派员工只可查看完成支撑所需的客户、需求和方案信息，不获得销售指标、其他商机或客户经营权限。
7. 支撑人员处理中停用时，原请求保留历史，负责人关闭原请求并向有效员工重新发起；不新增自动转交状态。

## 11. 商机跟进

跟进记录字段：跟进时间、跟进方式、参与关键人、跟进内容与结果、当前风险、下一步行动、下次跟进日期和可选附件。除附件外均为必填；当前风险可明确选择“暂无风险”。

规则：

1. 跟进时间不得晚于提交时间；参与关键人从商机当前有效关键人中选择。
2. 下次跟进日期必须晚于本次跟进时间；新记录保存后，上一条承诺闭环，新日期成为当前承诺。
3. 到达下次跟进日期当日上午提醒负责人；当日仍无新有效跟进时，从次日起每日一次；逾期满 3 个自然日时同时提醒所属区域总监，节假日不顺延。
4. 新增有效跟进后停止旧承诺提醒；提醒失败不改变逾期事实。
5. 落选后不再要求或允许新增跟进；已有跟进历史继续只读可见。

商机跟进记录与 M03 维系记录是不同业务对象，不互相替代或复制。

## 12. 状态与失败保护

- Loading、Empty、Empty Result、Error、PermissionDenied、Submitting 和 Success 是页面反馈，不是商机状态。
- 必填缺失、关键人失效、范围变化或阶段不合法时不创建记录、不改变阶段，并保留用户可继续修正的输入。
- 并发阶段推进按当前版本拒绝后到请求，不覆盖已生效结果。
- 越权直接访问返回 403，不透露对象名称、状态、数量或是否存在。
- 指标发布不守恒时明确指出月份和差额，不生成生效版本。
- 消息失败不回滚商机、跟进或支撑事实，并按 P01 规则重试。
