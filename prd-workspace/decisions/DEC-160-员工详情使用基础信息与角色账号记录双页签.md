## DEC-160：员工详情使用基础信息与角色账号记录双页签

- 日期：2026-08-20
- 状态：已确认
- 背景：员工详情把基础档案、角色、账号和登录事件堆在一个长抽屉内，记录边界不清晰。
- 决策：员工详情抽屉固定两个页签。“基础信息”展示脱敏手机号、邮箱、工号、入职日期、部门路径、主管关系、区域身份、系统角色和员工状态；账号状态与最近登录仅 admin 可见，HR 可按 DEC-158 查看尚未被本人修改的系统生成初始密码。“角色与账号记录”只展示员工账号创建、系统角色增减、账号启用/停用、管理员密码重置、本人密码修改和 admin 可见的登录摘要。记录保存事件类型、发生时间、操作人/来源、变更前后或结果，不保存或展示密码明文、密码哈希、验证码、失败次数、会话令牌、设备/IP、完整手机号或跨业务对象详情；非 admin 不展示最近登录时间、锁定与会话运行信息。
- 未采用方案：继续使用单页长抽屉；把所有安全日志开放给 HR；在角色记录中复制人员异动完整审批内容。
- 原因：双页签便于评审和使用，事件边界既能追溯角色账号变化，也避免泄露安全实现与重复业务记录。
- 决策人：产品经理（2026-08-20 员工详情评审意见）
- 影响范围：F001、F002、附录 A/C/D、GLOSSARY、客户管理 Demo
