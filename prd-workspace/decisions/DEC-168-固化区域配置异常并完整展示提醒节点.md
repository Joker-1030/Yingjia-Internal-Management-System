# DEC-168：固化区域配置异常并完整展示提醒节点

- 日期：2026-08-25
- 状态：已确认
- 背景：Product Owner 要求罗列区域配置异常原因并增加独立测试数据，同时指出生日规则的站内提醒节点比 PRD 中的固定集合少。
- 决策：
  1. M08 区域配置异常固定为四类：区域中心主管缺失或停用；主管不具备区域总监角色；已配置区域的关联省份或驻地失效；有客户的地市缺少有效 PM。
  2. 首次从未完成关联省份或驻地配置的区域为“待配置”；已完成配置后关联省份或驻地失效为“配置异常”。
  3. Demo 新增四个独立测试区域，每个区域只表达一类异常；现有正常区域和正常场景保持不变。
  4. M09 生日/节假日站内提醒节点始终展示全部固定候选：截止日及提前 1/2/3/5/7/10/15/30 天。超过当前“提前生成天数”的节点置灰且不可勾选；降低提前生成天数时，新超出范围的已选节点取消选择。
  5. M09 仍至少需要一个有效提醒节点，不允许输入固定集合外的数值，保存值仍按去重后倒序的逗号分隔格式表达。
- 替代关系：本决策替代 DEC-167 中“只显示不超过提前生成天数的候选”的表达；DEC-167 其他规则继续有效。
- 未采用方案：将已配置后的省份/驻地失效仍显示为待配置；改动现有正常区域来制造异常；隐藏超过提前生成天数的节点；允许勾选超范围节点并自动改大提前生成天数。
- 原因：异常分类和独立测试数据让区域配置问题可见、可验证；完整展示提醒候选让用户理解可用范围，同时保留提前生成天数的有效性约束。
- 决策人：Product Owner（2026-08-25 明确确认 `1A / 2B` 并回复“执行”）
- 影响范围：M08、M09、相关 Acceptance、当前 Prototype 源码与 Demo Mock 数据
