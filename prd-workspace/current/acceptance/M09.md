# M09 Acceptance Criteria

> Existing stable IDs, priority, and row order are preserved. Product-owner-confirmed wording replacements and the appended AC-F005-40 are governed below.

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F005-12 | 用户配置周期 30 天 | 输入重复提醒节点、31 天节点或超过 10 个节点 | 非法值就地提示且不能保存；合法节点去重后倒序保存 | P0 |
| AC-F005-13 | 客户部门仍被有效任职引用 | 发起停用并保留默认“关闭未完成任务并记录原因”，或改选转移方案但不选替代部门 | 默认方案可继续提交并在影响摘要列出将关闭任务；转移方案缺少适用于受影响公司的正常替代部门时阻止提交 | P0 |
| AC-F005-14 | 行业已被集团引用 | 停用行业后打开新增集团和存量详情 | 新建候选不含该行业，存量详情仍正确展示且引用不丢失 | P0 |
| AC-F005-15 | 关键人生日为 02-29 | 生日规则在闰年和非闰年运行 | 闰年按 02-29 生成；非闰年按规则事件日 02-28 生成并记录折算标识，不丢失关键人 | P0 |
| AC-F005-16 | 当前年度节假日同步失败但有最近成功版本 | 调度生成节假日任务 | 使用最近成功版本且不重复任务，同时向总裁、市场副总和管理员告警 | P0 |
| AC-F005-17 | 用户保存启用的节假日规则 | 未选择关联节假日，或所选节假日与另一启用规则在同一职级重叠 | 系统分别提示必选或列出冲突规则并阻止保存；未选择节假日不生成任务 | P0 |
| AC-F005-18 | 用户修改某职级周期并确认 | 弹窗确认后仅该职级更新，已存在任务截止不变 | 保存后新生成的任务按新周期计算；内部配置版本递增并继续用于并发、审计和任务快照，页面不展示版本字段 | P0 |
| AC-F005-19 | 用户在不同职级分别修改周期 | 每行独立保存确认 | 各职级互不影响；确认弹窗明确提示已存在任务不受影响 | P1 |
| AC-F005-20 | 标准关键人岗位仍被当前关键人任职或进行中岗位覆盖 KPI 引用 | 尝试停用并伪造替代岗位参数 | 系统列出引用明细并阻止停用，忽略并拒绝替代参数；必须先逐人完成调岗审批或结束引用，不能批量改写任职或 KPI | P0 |
| AC-F005-21 | 两个不同客户部门需要同名岗位 | admin 在各部门分别新增并查看组织树 | 两个岗位使用不同稳定 ID 和编码并分别挂在各自部门下；同一部门同名被阻止，不跨部门复用或合并 | P0 |
| AC-F005-22 | 用户查看四个职级的常规维系规则并生成新任务 | 检查页面字段、任务快照并伪造逾期补完成期限参数 | 页面不存在常规补完成期限字段，任务固定允许逾期补完成且补完成截止为空；伪造期限参数被拒绝且不写入规则或任务 | P0 |
| AC-F005-23 | 用户打开任一预置生日/节假日规则 | 尝试新增规则、寻找“允许逾期补完成”开关或伪造开启参数 | 页面无新增按钮且服务端拒绝创建请求；规则表单不存在允许逾期补完成和补完成期限字段，任务越过截止直接进入已过期未完成；伪造参数被拒绝且不写入规则或任务 | P0 |
| AC-F005-24 | 节假日日历同一事件先后同步两个版本并改变事件日 | 在任务生成前和生成后分别同步 | 生成前使用最新正常版本；生成后保留既有任务日期和版本快照并产生差异提示，不重复任务或静默改截止；缺少必填日历字段时整条事件不可供规则选择 | P0 |
| AC-F005-25 | 配置版本字段不对业务页面展示 | admin、总裁与市场副总分别查看职级周期配置 | 所有角色均看不到配置版本字段；内部版本、并发校验、审计和任务规则快照保持有效（DEC-167 部分替代 DEC-150） | P1 |
| AC-F005-26 | 已存在覆盖一级和二级的启用生日规则 | 编辑另一预置规则，把适用职级改为二级和三级并启用 | 系统列出冲突规则和重复职级“二级”并阻止保存；调整为仅三级后可保存，同一关键人同年只生成一条生日任务 | P0 |
| AC-F005-27 | 用户打开预置生日/节假日规则并生成任务 | 查看规则表单与生成任务的截止时间 | 规则表单不含截止宽限天数字段；任务截止固定为事件日当天 23:59:59；伪造宽限参数被服务端拒绝 | P1 |
| AC-F005-28 | admin、总裁、市场副总、区域总监、PM、HR 分别访问客户基础配置 | 查看三个页签并尝试在客户组织树新增行业、集团、客户公司、部门和岗位 | admin 可维护全部节点，行业、部门和岗位编码由系统生成；总裁和市场副总只能查看，区域总监、PM 和 HR 无菜单且直接访问返回 403 | P0 |
| AC-F005-29 | 同一集团含多级客户公司和多级客户部门 | 展开整棵客户组织树 | 按“行业→集团→公司子树→部门子树→岗位”展示；公司节点先列下级公司再列直属部门，部门节点先列下级部门再列岗位，不生成虚拟占位节点 | P0 |
| AC-F005-30 | 树中存在超过 50 个直接子节点且深层节点命中关键词 | 执行筛选、加载更多和重置 | 搜索不受已加载页限制，命中节点保留完整祖先路径；分页不重复、不遗漏，重置后恢复默认行业层 | P1 |
| AC-F005-31 | admin 分别选中行业、集团、公司、部门和岗位节点 | 从右上角新增菜单依次打开五类表单，并在表单中更换上级 | 系统按当前路径预填有效上级；上下文不足时按业务顺序补选；上级变化立即清空全部失效下级值且不允许携带旧 ID 提交 | P0 |
| AC-F005-32 | 已有同名行业或编号服务短暂失败 | admin 新增行业并重试同一请求 | 同名按去空格、大小写不敏感规则阻止；成功时只生成一个 `IND`+6 位流水编码，失败时不落库、不重复占号 | P0 |
| AC-F005-33 | 已存在正常行业、同名集团或已使用的统一社会信用代码 | admin 新增集团并提交重复名称或信用代码 | 集团名称全局唯一，信用代码在全部集团和客户公司中全局唯一；表单和接口均不存在集团架构类型字段 | P0 |
| AC-F005-34 | 按省市区自动归属的集团尚无中间层公司 | admin 先创建市公司或区县公司，再补建省公司或市公司 | 系统允许缺中间层并按区划生成当前有效父子路径；补建后按稳定公司 ID 重组展示路径，不改变关键人、任务和历史引用 | P0 |
| AC-F005-35 | 任意集团已有同省省公司和同省同市市公司 | admin 新增该市区县公司，再提交缺失、越级或无法解析负责人的责任区划 | 新公司自动挂到同市市公司；缺少市公司时降级挂同省省公司，二者均缺失时挂集团；缺失、越级或无法解析负责人的区划被阻止 | P0 |
| AC-F005-36 | admin 分别从集团节点和客户公司节点新增客户部门 | 查看上级候选并提交 | 集团节点必须继续选择客户公司后才能提交；部门只能挂在所选客户公司或该公司内上级部门下，不存在集团直属部门 | P0 |
| AC-F005-37 | 同一客户公司存在多级部门 | admin 修改上级、尝试选择其他公司部门、自身或后代 | 仅同公司正常部门可选；跨公司、自身、后代均被阻止，不形成环或跨公司路径 | P0 |
| AC-F005-38 | admin 新增标准岗位 | 依次选择行业、集团、客户公司和部门并保存 | 岗位只挂在所选部门下并生成系统内全局唯一且不重复的 `POS`+8 位编码；上级变化清空下级；无部门不能提交，不存在岗位直接挂公司或跨部门复用 | P0 |
| AC-F005-39 | 总裁、市场副总或 admin 查看客户组织树节点详情 | 依次选择集团、公司、部门和岗位 | 右侧只显示主数据字段、路径、状态和审计，不显示关键人数、任务数、专项、KPI或客户负责人，也没有业务数据下钻；版本冲突仍返回 409 | P0 |
| AC-F005-40 | admin 编辑生日或节假日规则并已设置提前生成天数 | 查看并修改站内提醒节点 | 提醒节点使用固定复选框候选“截止日、提前 1/2/3/5/7/10/15/30 天”；只显示不超过提前生成天数的选项，至少勾选 1 项，不能输入其他数值 | P0 |

> Source Governance（2026-08-22，DEC-163）：AC-F005-38 的标准关键人岗位编码固定为系统生成 `POS` + 8 位数字，系统内全局唯一、不可编辑、永久不回收。DEC-123 的“同集团唯一”只作 Historical / Replaced Evidence。本注记不增加 AC ID、改变优先级或顺序。
>
> Source Governance（2026-08-24，DEC-167）：AC-F005-18/25 的 admin 可见配置版本旧表达由“业务页面不展示版本字段”替代；内部版本递增、乐观锁、审计和任务规则快照继续有效。新增 AC-F005-40 固化生日/节假日站内提醒节点的复选框交互。
