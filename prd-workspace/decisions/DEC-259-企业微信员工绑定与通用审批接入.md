# DEC-259 企业微信员工绑定与通用审批接入

- 日期：2026-11-18；状态：延期模块内已确认定义 / NOT REVIEWED / NOT STARTED。
- Owner：M04 审批中心；内部组织与账号事实仍归M06 组织与员工。
- 类型：NEW / CHANGE；影响：HIGH；Product Concept Delta：NEW CONCEPT INTRODUCED；Approved Baseline：UNKNOWN。

## 确认来源

用户要求企微对接统一放审批板块并开始更新PRD。已确认：先绑定双方已有员工；HR/admin核对，一对一且不可重复，同名不自动绑定，未绑定/冲突禁止发起；先做通用审批，模板另定；admin配置接入、表单路线在企微，不建平台审批引擎。仅同步平台发起单，按本人申请/审批/抄送关系查看，admin全量核查；沿企微动作权限、admin不代审批、真实结果同步、防重复。审批人沿企微模板内置路线确定，平台不手工选择；已映射的业务字段可由平台下拉选择。修改重提答复为“这个根据企微的审批规则来”，未选择固定原单或新单。核对官方文档未找到直接动作接口依据后，用户最新明确“那就平台直接同意、驳回、撤回，不放在平台做，就放在企微”，替代此前的平台直接处理目标。

完整问答及旧建议被替代范围见 `docs/requirement-discussions/active/REQ-DISCUSSION-2026-09-01-M04-WECOM-APPROVAL.md` →“11. 2026-11-18：Product Owner确认与部分正式化”“13. 2026-11-18：审批处理统一在企微执行”。

## 当前决定

1. 审批相关企微集成定义归M04；M06仍拥有内部组织、员工、账号和角色。审批专项不自动创建或覆盖组织账号、不自动停用；企业微信扫码登录另由 [`DEC-261`](./DEC-261-企业微信扫码登录.md) 定义，不改变本决定的审批边界。
2. 身份绑定与模板配置、审批读取、审批处理分别控制。HR/admin维护一对一绑定；仅admin配置接入；HR/领导不因维护身份或职级扩大审批读取。
3. 企微维护审批事项目录、模板字段、控件、申请人范围及审批路线；平台发起先选择审批事项，再按事项动态展示并填写字段，已映射的业务字段使用平台下拉选项。审批人和抄送人均由模板路线预设，平台不提供手工选择。平台仅同步平台发起单及其企微端后续变化，企微原生新单和历史不自动纳入。
4. 同意、驳回、撤回统一在企微执行，平台不提供这三项直接处理操作。平台负责填写发起及同步企微原单过程和结果；权限严格沿企微，admin全量核查不等于代操作。平台跳转入口未在本轮定义，不自动新增。
5. 以企微确认结果同步，失败不显示成功、重复通知不重复建单或覆盖历史。修改重提依选定模板及企微实际规则，不预设原单/新单；存在回调不证明可执行动作或可可靠关联重提单。
6. 具体模板目录、申请人范围、同步时效及漏通知处理、修改重提具体方式、必要页面和财务规则尚未完整定义；事项选择、动态字段及路线预设规则已正式化，其余只正式化已确认部分。平台直接同意/驳回/撤回已移出需求，不再作为待验证的开发目标。
7. M04保持DEFERRED / NOT REVIEWED / NOT STARTED；Working Demo提供审批中心菜单、动态发起表单和来源业务发起入口，真实企业微信接入与研发仍未开始。已确认需审批的业务按M04 §1.2—1.3执行。2026-11-27用户重申“PM的发起交接也要审批，区域总监可以直接调整”：原PM交接须经企微审批，通过后按计划生效，审批中、驳回或撤回保持原责任；主管中心内总监直接调整仍不审批。此范围替代DEC-204的PM交接直接生效边界，其余未纳入审批的直接操作保持；不授权真实企业配置或Push。
