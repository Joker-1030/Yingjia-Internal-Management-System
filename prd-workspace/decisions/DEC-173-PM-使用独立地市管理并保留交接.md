# DEC-173：PM 使用独立地市管理并保留交接

- 日期：2026-08-25
- 状态：部分被 DEC-187 替代；PM 独立地市管理和本人交接发起继续有效，撤回取消
- 背景：现行“区域中心与地市配置”把区域配置、全区域地市责任和 PM 本人责任放在同一入口。Product Owner 要求 PM 不再进入后台配置页面，改用独立菜单查看本人所属区域和本人负责地市。
- 决策：
  1. “区域中心与地市配置”不再对 PM 显示；PM 直接访问返回 403，且不返回区域列表、数量、配置详情或其他 PM/地市信息。
  2. 新增“地市管理”菜单，仅当前有效角色集合包含 PM 的账号可见；总裁、市场副总、区域总监、HR/人事和 admin 均无该入口。该角色边界不通过 M07 模板向非 PM 放宽。
  3. “地市管理”按 PM 当前所属区域分别展示区域名称、部门编码、区域总监、关联省份、驻地和配置状态；多个区域不合并。
  4. 每个区域只统计本人当前负责地市数及其客户数、关键人数，只展示本人当前有效负责地市；不展示其他 PM、其他地市、待分配地市或后台配置数据。
  5. 区域和地市信息只读，不提供编辑区域、分配、直接调整、按 PM 查看、查看范围或客户下钻。
  6. PM 的地市交接能力不取消：本人仍可对当前负责且无进行中交接的地市发起交接，并在首个处理动作前撤回；入口迁移到“地市管理”。交接审批、计划生效、失败保护、历史和通知规则保持不变。
  7. PM 无所属区域和有区域但无负责地市使用不同空态，不得通过空态、摘要、筛选或直接访问泄露其他责任事实。
- 替代关系：替代 DEC-127/当前 M08 中 PM 通过“区域中心与地市配置”查看本人区域的入口表达；补充 DEC-143 的交接发起位置，不改变其“仅原负责 PM 发起、所属区域总监审批”规则。
- 未采用方案：保留 PM 的区域配置菜单；取消 PM 交接；向其他角色开放“地市管理”；在 PM 页面展示所在区域全部 PM 或全部地市。
- 原因：把配置治理和个人责任查看分开，减少 PM 接触后台配置噪音，同时保留本人责任转移流程。
- 决策人：Product Owner（2026-08-25 确认 `1A / 2A / 3A`，纠正原 `2B` 并回复“执行”）
- 影响范围：M08 Current PRD、Acceptance、Shared 权限、FLOW-10、Product Boundary、导航、权限目录和 Prototype
