# M11 项目管理

- 文档状态：Current
- Source of Truth 生效日期：2026-08-27
- 功能范围：项目、采购包、平台公司、项目人员、项目资料、满意度、项目责任历史
- 关联模块：M01、M02、M06、M08、M10、P01、Shared

## Quick Overview

### 模块目标

M11 用统一项目对象承接培训项目和 AI 软件项目的立项、执行、交付、资料、评价、责任、商业快照与历史。项目负责人由客户业务责任层级及业务责任区域决定；项目主阶段与资料、评价、回款待办分离；采购包和平台公司是 M11 自有配置，客户、业务责任地区、员工、导入和消息继续由既有模块提供唯一事实。

### 当前阶段边界

- 当前人工创建持续开放到商机与合同能力正式上线；初始化结束不关闭人工创建。
- 商机与合同能力正式上线后，关闭普通人工创建，只有合同审核验证通过后，商机负责人才能从商机发起创建项目。
- 当前取消项目直接生效；未来统一审批中心上线后再接入取消审批。本规则不表示当前已经具备该审批。
- 当前只展示`待回款`，不登记回款明细且不能解除；后续由财务模块接管。
- 当前使用若干虚拟讲师数据作为项目人员候选，不形成正式讲师管理模块；正式讲师库上线后切换为正式候选。
- 当前员工停用不选择交接人或校验项目阻断；员工名下项目保留且不自动取消，停用本身不迁移项目负责人。完整版本才在停用时选择交接人并完成适用项目交接。

## 1. 用户目标与产品边界

### 1.1 用户目标

- 由有权人员建立可追溯的项目，明确客户、业务责任地区、负责人、时间、资源、金额和人员。
- 按项目类型推动开始、交付、资料补齐、评价和完成。
- 让地区责任交接同步迁移项目责任，避免出现无有效负责人项目。
- 通过项目价格与费率快照保留创建或开始前最后确认的商业事实。
- 在 M01 与 P01 中向责任人提供可处理待办和站内提醒。

### 1.2 M11 负责

- 项目主数据、主阶段、并行待办标识、项目资料、满意度、人员安排和责任历史。
- 采购包及其课程方向、平台公司配置与生命周期。
- 项目创建、阶段流转、允许修改、取消、自动完成和项目内审计。
- 向 M01、M08、M10 和 P01 输出项目事实与约束。

### 1.3 M11 不负责

- 维护客户公司、客户编号或业务责任区划；这些事实来自 M09/M02。
- 维护区域中心、区域总监、PM 或地市责任；这些事实来自 M06/M08。
- 建立正式讲师库、讲师费用扣减或排课优先级规则。
- 审核合同、维护商机、记录回款明细或实现统一审批中心。
- 在 M11 内另建批量导入页面、项目批量导出、批量编辑或批量取消。

## 3. 核心对象

| 对象 | 产品含义 | 生命周期或稳定性 |
| --- | --- | --- |
| 项目 | 一次面向客户的培训或 AI 软件服务 | `已立项`、`进行中`、`已交付`、`已完成`、`已取消` |
| 项目责任 | 创建负责人快照、当前负责人及责任历史 | 当前负责人始终跟随客户业务责任对应的地区责任 |
| 项目商业快照 | 课程报价、合作课酬、管理费比例和项目单价 | 创建时保存；开始前调整资源时整体刷新；开始后锁定 |
| 采购包 | 框架范围内可选择的课程资源集合 | `正常`、`停用`；不可删除 |
| 课程方向 | 采购包中的课程简述及不含税/含税报价 | 随采购包维护；项目单选一个方向 |
| 平台公司 | 走账或师资合作的平台主体 | `正常`、`停用`；不可删除 |
| 项目人员安排 | 主讲师、辅讲师、项目助教及其变更记录 | 培训项目适用；取消后释放排期但保留历史 |
| 项目资料 | 按项目类型区分的交付材料 | 完成前可按阶段维护；完成后仅补充可选资料 |
| 满意度 | 项目满意度及适用的参与人员满意度 | `已交付`后填写；`已完成`后只读 |
| 并行待办标识 | `资料待上传`、`待评价`、`待回款` | 不是项目主阶段，可同时存在 |

## 4. 页面与入口

### 4.1 一级菜单

`项目管理`是独立一级菜单，包含：

1. `项目列表`；
2. `采购包管理`；
3. `平台公司管理`。

项目导入只从 M10 数据导入进入，不在项目管理菜单重复提供入口。

### 4.2 项目列表

列表展示：项目编号、项目名称、项目类型、客户公司、地区、当前项目负责人、开始时间、结束时间、项目天数、项目金额、主阶段、并行待办标识和当前可用操作。

筛选包括：

- 项目编号：只匹配项目编号；
- 项目名称：只匹配项目名称；
- 项目类型；
- 主阶段；
- 待办标识；
- 客户；
- 地区；
- 当前项目负责人；
- 项目开始时间；
- 项目结束时间。

项目开始时间和项目结束时间是两个独立筛选条件：开始时间有值时，仅保留`项目开始时间 >= 所选开始时间`的项目；结束时间有值时，仅保留`项目结束时间 <= 所选结束时间`的项目；两者同时有值时按 AND 取同时满足两个条件的结果。只填写其中一个条件时，不对另一个时间字段附加限制。

列表和筛选只返回当前角色有权项目。无权操作不展示按钮，直接请求返回无权限且不泄露对象信息。

### 4.3 项目详情

项目详情使用独立详情页，不使用右侧 Drawer 承载完整详情。详情分为四个 Tab：

1. `基本信息`；
2. `人员安排`；
3. `资料与满意度`；
4. `变更与责任历史`。

页面顶部按角色、阶段和操作资格展示编辑、取消、确认 AI 软件项目交付、补充资料等操作。只读角色不展示操作按钮。

### 4.4 项目创建与编辑页面

- 当前人工创建从项目列表的`创建项目`按钮进入独立页面，不使用 Modal 或 Drawer；页面标题为`创建项目`。
- 已立项且未开始项目从详情页的编辑入口进入同一结构的独立页面，页面标题为`编辑项目`。
- 创建页底部按钮固定为`取消`、`创建项目`；编辑页底部按钮固定为`取消`、`保存`。
- 点击`取消`返回进入该页面前的来源页面，不保存任何修改；创建场景不生成或占用项目编号。
- 创建成功后直接进入新项目详情，不显示成功 Toast。
- 编辑保存成功后返回项目详情，并显示`保存成功` Toast。
- 校验失败时停留在当前页面，在对应字段旁展示具体失败原因，不保存项目、不生成或占用项目编号。固定反馈为：
  - 必填文本字段：`请填写{字段名}`；必选字段：`请选择{字段名}`；
  - 项目名称重复：`项目名称已存在，请修改后重试`；
  - 客户无法唯一匹配有效负责人：`该客户未匹配到唯一有效项目负责人，无法创建项目`；
  - 开始时间晚于结束时间：`项目开始时间不得晚于项目结束时间`；
  - 手工项目天数不合规：`项目天数最小为0.5天，且必须为0.5天的整数倍`；
  - 项目类型、资源类型与合作形式组合不允许：`当前项目类型、资源类型与合作形式不匹配，请重新选择`；
  - 所选采购包或平台公司已经不可用：`所选采购包或平台公司当前不可用，请重新选择`；
  - 培训项目未选择主讲师：`培训项目至少需要选择一名主讲师`；
  - 讲师排期冲突：展示冲突讲师、冲突时间和关联项目编号。

## 5. 项目创建

### 5.1 当前人工创建

- 人工创建开放到商机与合同能力正式上线，初始化结束不关闭该能力。
- PM 只能选择本人责任地市内的市级或区县级业务责任客户。
- 区域总监只能选择本人负责的省级业务责任客户。
- 系统管理员可选择公司范围客户，但不能绕过客户业务责任、地区映射或负责人校验。
- 项目不设置草稿；创建必须一次通过全部校验，成功后直接进入`已立项`。

### 5.2 未来商机流转

- 商机与合同能力正式上线后，普通人工创建入口关闭。
- 合同审核并验证通过后，商机负责人在商机中点击`创建项目`。
- 系统带出商机、合同、客户和按客户业务责任解析的项目负责人；商机负责人补充项目类型、时间、资源等项目字段。
- 校验通过后直接进入`已立项`，不增加独立项目立项审批。
- 当前尚未建设商机模块时，所属商机编号为空。

### 5.3 负责人前置条件

- 业务责任层级为省级的客户项目负责人，是其业务责任省份所属区域中心的当前有效区域总监。
- 业务责任层级为市级或区县级的客户项目负责人，是其业务责任城市的当前有效 PM。
- 客户所属集团、显式组织上级和当前组织路径均不参与项目负责人解析。
- 无法唯一匹配有效负责人时阻止立项，任何角色包括系统管理员都不能绕过。
- 项目不得以负责人为空或`负责人待分配`状态成立。

### 5.4 编号与名称

- 项目编号格式为`XM` + 4 位年份 + 6 位年度流水，例如`XM2026000001`；每年重新开始。
- 编号只在全部校验通过且项目成功立项时生成；打开页面、放弃创建或校验失败不占号。
- 已生成编号永久保留，项目取消不回收。
- 项目名称由创建操作人填写，必填，且不得与当前未取消项目重名。
- 已取消项目不继续占用名称；新项目可复用其名称，但取消记录保留原名称。

## 6. 项目字段与数据来源

| 字段 | 规则 |
| --- | --- |
| 项目编号 | 系统成功立项时生成，只读 |
| 项目名称 | 人工必填；当前未取消项目中唯一 |
| 创建时间 | 精确到年月日时分秒；历史导入使用原创建时间 |
| 创建操作人 | 当前人工创建人；未来为商机负责人 |
| 项目类型 | `培训项目`、`AI软件项目`；立项后锁定 |
| 所属商机编号 | 当前为空；未来从商机带出并锁定 |
| 客户编号、客户公司 | 从当前有效客户公司下拉选择并带出稳定编号；立项后锁定 |
| 客户快照 | 立项时锁定客户稳定 ID、编号、名称、业务责任层级及业务责任省/市/区县；不保存组织上级作为项目责任依据 |
| 地区 | 根据客户业务责任省、市、区县确定；立项后锁定 |
| 创建负责人快照 | 项目立项时匹配到的有效负责人 |
| 当前项目负责人 | 随客户业务责任对应的区域/地市责任变化而更新 |
| 资源类型 | `采购包课程`、`平台师资合作`、`AI区域框架` |
| 合作形式 | `直接服务`、`师资合作`、`走账合作` |
| 项目开始/结束时间 | 精确到年月日时分；开始时间不得晚于结束时间 |
| 项目天数 | 自动计算后可在允许阶段手工修改，最小 0.5 天且必须为 0.5 的整数倍 |
| 项目单价 | 培训项目按资源带出，单位元/天；AI 软件项目不使用按天单价 |
| 项目金额（含税） | 培训项目自动计算；AI 软件项目由负责人填写 |
| 结账金额 | 表示我公司该项目实际应收金额，按合作形式计算 |

项目立项后，客户编号、客户公司、客户快照和地区完全锁定。客户组织上级变化只改变客户当前组织路径，不改项目客户引用、负责人或历史快照；客户选择错误时必须取消项目后重新创建。

## 7. 项目天数与金额

### 7.1 自然日天数

- 按自然日计算，不使用小时数相除。
- 同一天项目：结束时间不晚于`12:00`计`0.5天`，晚于`12:00`计`1天`；开始时间位于`12:00`及之后的下午时段时计`0.5天`。
- 跨日项目：开始日早于`12:00`计`1天`，不早于`12:00`计`0.5天`；中间自然日各计`1天`；结束日不晚于`12:00`计`0.5天`，晚于`12:00`计`1天`。
- 自动结果允许手工修改；手工值最小`0.5天`且必须为`0.5`的整数倍。

### 7.2 金额与精度

- 培训项目：`项目金额 = 项目单价 × 项目天数`。
- AI 软件项目：项目金额由项目负责人填写，不按天数计算。
- 直接服务：`结账金额 = 项目金额`。
- 师资合作：`结账金额 = 项目金额`。
- 走账合作：`结账金额 = 项目金额 ×（1 - 管理费比例）`。
- AI 软件项目直接服务时，负责人填写的项目金额即结账金额；走账合作时按相同比例扣减。
- 项目单价、项目金额、结账金额和合作课酬保留两位小数；管理费比例和自动计算税率保留两位百分比小数；自动结果四舍五入后展示和保存。

## 8. 采购包、平台公司与商业快照

### 8.1 资源与合作形式组合

| 资源类型 | 允许合作形式 | 平台公司与价格规则 |
| --- | --- | --- |
| 采购包课程 | 直接服务、走账合作 | 选择一个采购包中的一个课程方向；培训项目单价使用课程含税报价 |
| 平台师资合作 | 师资合作 | 关联平台公司，项目单价使用平台公司的合作课酬 |
| AI区域框架 | 直接服务、走账合作 | 仅 AI 软件项目可选；直接服务不关联平台公司，走账合作关联平台公司 |

- 直接服务不关联平台公司。
- 走账合作使用平台公司管理费比例；师资合作使用平台公司合作课酬。
- AI 软件项目不使用按天项目单价，即使选择其允许的资源类型，金额仍由负责人填写。

### 8.2 采购包管理

- 字段：采购包编号、采购包名称、状态、有效期、课程方向。
- 每个课程方向维护一句话课程介绍、不含税报价、含税报价；两种报价输入后自动计算税率，单位元/天。
- 项目只能选择状态`正常`且处于有效期内的采购包，并单选其中一个课程方向。
- 不维护服务客户、中标主体、平台公司、框架总额度或已使用额度；不计算、占用或释放框架金额。
- 编号格式为`CGB` + 4 位年份 + 6 位年度流水，例如`CGB2026000001`；每年重置，创建后不变且停用不回收。

### 8.3 平台公司管理

- 字段：平台公司编号、平台公司名称、管理费比例、合作课酬、状态。
- 选择平台公司名称后带出编号、管理费比例和合作课酬。
- 编号格式为`PT` + 6 位全局流水，例如`PT000001`；不按年份重置，创建后不变且停用不回收。

### 8.4 配置权限与生命周期

- 只有系统管理员可新增、编辑、停用和恢复采购包或平台公司。
- PM、区域总监只查看并在项目中选择当前正常有效配置。
- 总裁、市场副总、HR/人事和仅商机负责人不获得配置入口。
- 两类配置都只有`正常`、`停用`，不提供物理删除；停用后退出新项目候选，既有项目继续使用快照。
- 新增和编辑采购包、平台公司统一使用 Modal；标题按对象和动作显示`新增采购包`、`编辑采购包`、`新增平台公司`或`编辑平台公司`，底部按钮固定为`取消`、`保存`。
- 停用和恢复必须先打开二次确认弹窗，不能点击后立即改变状态。停用标题按对象显示`确认停用采购包`或`确认停用平台公司`，正文固定为`停用后将退出新项目候选，已有项目继续使用已保存快照。`；恢复标题按对象显示`确认恢复采购包`或`确认恢复平台公司`，正文固定为`恢复后将按当前状态和有效期重新进入项目候选。`。
- 停用和恢复确认弹窗的底部按钮固定为`取消`、`确认`；点击`取消`关闭弹窗且不改变状态，点击`确认`后执行对应状态变更。
- 上述 M11 配置 Modal 均允许通过右上角`×`或点击遮罩关闭；两种方式都等同于点击`取消`，不得保存表单、占用编号或改变配置状态。
- 采购包课程方向允许系统管理员新增、编辑和移除，但每个采购包至少保留一个课程方向；移除入口使用`×`图标按钮，Tooltip 固定为`移除该课程方向`。

### 8.5 项目快照

- 项目创建时保存课程不含税/含税报价、平台合作课酬、管理费比例和项目单价快照。
- 采购包或平台公司后续变化不追溯修改已创建项目。
- 项目开始前调整采购包、课程方向、合作形式或平台公司时，按新选择重新生成整组商业快照。
- 项目开始后，资源字段及其价格、费率快照全部锁定。

## 9. 项目人员与排期

### 9.1 人员范围

- 培训项目必须选择至少 1 名主讲师，可选择多名。
- 辅讲师和项目助教非必填，均可选择多名。
- AI 软件项目不展示主讲师、辅讲师和项目助教字段。
- 正式讲师管理模块上线前，当前使用若干虚拟讲师数据作为候选；该临时数据不定义讲师完整生命周期。

### 9.2 排期冲突

- 选择或调整项目人员、修改影响人员排期的项目时间时，校验全部已选主讲师、辅讲师和项目助教的其他项目排期。
- 冲突时阻止保存，并展示冲突人员、冲突时间和关联项目编号。
- 任何角色都不能强制覆盖冲突。
- 初始化项目导入暂不校验讲师排期；正式讲师排期事实可用后，导入也接入同一规则。
- 项目取消后立即释放人员排期；取消项目不再参与冲突判断，但保留人员与原排期历史。

## 10. 项目主阶段与并行待办

### 10.1 主阶段

| 主阶段 | 进入条件 | 退出或终止条件 |
| --- | --- | --- |
| 已立项 | 创建或导入成功 | 到达开始时间自动进入进行中，或取消 |
| 进行中 | 到达开始时间 | 培训项目到结束时间自动交付；AI 项目由负责人确认交付；或取消 |
| 已交付 | 培训项目到结束时间；AI 项目负责人确认 | 完成条件齐全自动完成，或取消 |
| 已完成 | 必填资料、项目满意度及适用人员满意度全部齐全 | 终态；仅允许补充可选资料 |
| 已取消 | 有权人取消成功 | 终态，只读，不可恢复 |

- 项目没有草稿状态。
- 回款不阻塞项目完成。

### 10.2 并行待办标识

- `资料待上传`、`待评价`、`待回款`不是主阶段，可并行存在。
- 培训项目进入`已交付`后：必填资料不齐显示`资料待上传`；项目或适用人员满意度不齐显示`待评价`；当前版本同时显示`待回款`。
- AI 软件项目到期未确认交付时不显示三类待办，只发送确认交付提醒；确认后进入`已交付`，再按资料、项目满意度和当前回款边界显示待办。
- 项目进入`已完成`后，资料和评价待办消失；`待回款`可以继续保留。
- 项目取消后清除全部项目待办和后续提醒。

### 10.3 自动完成

- 项目必须先处于`已交付`。
- 培训项目必填资料、项目满意度、全部主讲师满意度，以及已选择辅讲师/项目助教的对应满意度齐全后自动进入`已完成`。
- AI 软件项目必填资料和项目满意度齐全后自动进入`已完成`，当前不要求讲师评分。
- 当前`待回款`不影响自动完成，也不能由用户解除。

## 11. 分阶段修改规则

| 阶段 | 允许修改 | 锁定或附加条件 |
| --- | --- | --- |
| 已立项且未开始 | 项目名称、开始/结束时间、培训人员、资源类型、采购包/课程方向、合作形式、平台公司、AI 项目金额、手工项目天数、项目资料 | 客户、业务责任地区、项目类型锁定；资源变化重建商业快照；人员/时间校验排期 |
| 进行中 | 项目名称、结束时间、主讲师、辅讲师、项目助教、项目资料 | 商业资源与快照锁定；结束时间重算天数及培训金额/结账金额；人员变化填写原因并校验排期 |
| 已交付 | 项目名称、实际主讲师/辅讲师/助教、项目资料、满意度 | 人员修正填写原因并留痕；满意度仅本阶段可填写 |
| 已完成 | 仅新增非必填可选资料 | 名称、满意度及其他字段只读；可选资料不能删除或替换 |
| 已取消 | 无 | 全部只读，不可恢复 |

- 项目名称修改不要求填写原因，但保留前后名称、实际操作人和时间。
- 进行中修改结束时间后，重新计算项目天数；培训项目同步重算项目金额和结账金额，并保留前后值。
- 进行中或已交付调整人员时填写原因，保留调整前后人员、实际操作人和时间。
- 进行中和已交付的项目资料可新增、删除和替换；历史文件关联和操作记录继续保留。
- 所有影响时间、人员、金额、资源和资料的修改保留前后值、操作人和操作时间。

## 12. 项目资料与满意度

### 12.1 培训项目资料

| 分类 | 必填 | 允许文件类型 |
| --- | --- | --- |
| 授课视频 | 是 | 视频 |
| 项目照片 | 是 | 图片 |
| 项目验收报告 | 是 | 文档 |
| 课程实例 | 否 | 图片、视频、文档 |
| 教材或讲义 | 是 | 文档 |
| 操作手册 | 否 | 文档 |
| 复盘 PPT | 否 | 文档 |
| 总结长图或回顾视频 | 否 | 图片、视频 |
| 其他 | 否 | 图片、视频、文档 |

### 12.2 AI 软件项目资料

| 分类 | 必填 | 允许文件类型 |
| --- | --- | --- |
| 项目验收报告 | 是 | 文档 |
| 操作手册 | 是 | 文档 |
| 交付版本或成果说明 | 是 | 文档 |
| 部署或开通证明 | 是 | 图片、文档 |
| 项目实施总结 | 是 | 文档 |

该清单及文件类型映射是当前阶段规则；后续调整须重新确认产品需求。

### 12.3 项目资料专用附件规则

- 授课视频和回顾视频：`.mp4`、`.mov`，单文件不超过`2 GB`，每分类最多`20`个。
- 项目照片和总结长图：`.jpg`、`.jpeg`、`.png`，单文件不超过`20 MB`，每分类最多`100`个。
- 报告、讲义、手册、PPT 等文档沿用 PDF 和 Office 类型，单文件不超过`100 MB`，每分类最多`20`个。
- 同一资料分类允许多种文件类型时，每个文件按其实际类型执行对应的扩展名、大小和数量规则。
- 禁止可执行文件、脚本、宏文件、压缩包、加密文件、零字节文件和伪装扩展名。
- 文件扩展名、声明类型和内容必须匹配，安全扫描通过才算成功。
- 部分文件失败时保留其他成功文件，并逐个展示失败原因。

### 12.4 满意度

- 项目满意度和人员满意度均为`1-100分`，无默认值，由项目负责人填写；系统管理员可按代操作规则执行。
- 仅`已交付`阶段允许填写；`已立项`、`进行中`不能提前填写，`已完成`后全部只读且系统管理员也不能修正。
- 培训项目：项目满意度必填；每名主讲师满意度必填；选择辅讲师或项目助教时，对应人员满意度必填。
- AI 软件项目：项目满意度必填，当前不要求人员满意度。
- 当前只记录评分，不执行讲师扣款或排课降级；这些能力属于未来讲师管理。

### 12.5 已完成后的可选资料

- 当前项目负责人可新增非必填可选资料，不能删除或替换已有资料。
- 地区责任交接后的新负责人继承该能力；原负责人无权继续操作。
- 系统管理员可代当前负责人新增，并记录实际操作人。
- 补充资料不改变`已完成`阶段，每次新增都保留历史。

## 13. 取消项目

- 当前版本取消直接生效，不进入审批；未来统一审批中心上线后，项目取消再切换为审批。
- 项目负责人可以取消本人负责项目。
- 区域总监只能取消本人作为项目负责人的省级业务责任客户项目，不能取消区域内 PM 项目。
- PM 项目只能由对应 PM 或系统管理员取消。
- 系统管理员可代项目负责人取消，展示并记录实际操作人。
- `已完成`项目不可取消；`已立项`、`进行中`、`已交付`可以取消。
- 取消必须填写原因，成功后项目只读、不可恢复，清除全部项目待办与后续提醒并立即释放人员排期。

## 14. 项目负责人、交接与历史

- 项目保存创建负责人快照和当前项目负责人；两者可以不同。
- 当前项目负责人始终跟随客户业务责任对应的正式区域/地市责任交接或直接调整变化，不允许将单个项目脱离该责任单独转交。DEC-182 的当前员工停用是阶段性例外：停用清空地区责任时不自动迁移或取消项目，项目保留停用前责任记录和完整历史，停用账号立即失去访问与操作能力。
- PM 交接同步转移其全部`已立项`、`进行中`、`已交付`和`已完成`项目。
- 区域总监交接同步转移其负责的全部省级业务责任客户`已立项`、`进行中`、`已交付`和`已完成`项目。
- `已取消`项目不转移，保留取消时负责人和责任历史。
- 地区责任与相关项目负责人必须在同一次交接中生效；任一项目无法迁移时，整个交接阻断，不允许出现负责人空档。
- 当前员工停用不以适用项目交接为前置条件，停用本身不迁移负责人或取消项目；项目主阶段和并行待办保持原值，不新增“负责人待分配”项目状态。
- 完整版本才要求停用时选择交接人、完成适用责任/任务/项目交接并在无阻断后停用；该能力不属于当前版本。
- 责任历史保留原负责人、现负责人、责任地区、生效时间、实际操作人和关联交接事实。

## 15. 提醒与工作台

### 15.1 AI 软件项目确认交付提醒

- 到达结束时间仍未确认交付时，通过 P01 立即提醒项目负责人一次，此后每天一次。
- 逾期满 3 天后，同时每天提醒项目所属区域的区域总监。
- 项目负责人确认交付或项目取消后停止。
- 提醒不改变项目阶段，不创建审批或独立任务。

### 15.2 培训项目资料与评价提醒

- 项目进入`已交付`且资料或评价未齐全时，通过 P01 立即提醒项目负责人一次，此后每天一次。
- 逾期满 3 天后，同时每天提醒项目所属区域的区域总监。
- 项目进入`已完成`或`已取消`后停止。

### 15.3 M01 工作台表达

- PM 本人项目的`确认 AI 项目交付`、`资料待上传`和`待评价`进入`我的待办`。
- 区域总监本人负责的省级项目按同一规则进入待办；区域内 PM 项目逾期升级只作为监督提醒，不产生代办操作。
- 系统管理员查看公司全范围项目待办汇总，可下钻并按代操作权限处理。
- 总裁和市场副总只读查看公司项目提醒汇总，不进入`我的待办`。
- HR/人事不展示项目事项。
- `待回款`只展示提醒摘要，不进入`我的待办`。
- 当前不新增项目数量、金额、阶段分布或趋势等经营指标。

## 16. M10 初始化项目导入

### 16.1 入口与开放周期

- M10 新增`项目`导入类型，M11 不另建导入页面。
- 项目导入只在初始化阶段开放；初始化完成后隐藏模板并禁止新上传。
- 已形成的历史批次和报告长期保留，并继续按数据范围查看。
- 省级业务责任客户关键人导入是独立能力：区域总监只能导入本人负责的省级业务责任客户关键人，长期开放，不随项目导入关闭；不得导入市级/区县级业务责任客户关键人。

### 16.2 权限与批次范围

- 系统管理员导入公司全范围项目。
- 区域总监导入本人作为项目负责人的省级业务责任客户项目，并查看本区域全部项目导入批次及报告。
- PM 导入本人负责的市级/区县客户项目，只查看本人创建的项目导入批次及报告。
- 初始化完成后，历史批次继续使用同一查看范围。

### 16.3 模板与系统生成字段

模板字段：项目名称、项目类型、客户编号、原创建时间、开始时间、结束时间、项目天数、资源类型、采购包及课程方向、合作形式、平台公司、AI 软件项目金额、导入阶段。

系统生成或匹配：项目编号、地区、当前项目负责人、项目单价、培训项目金额、结账金额。模板不得自由填写项目负责人。项目人员、项目资料和满意度不在基本信息模板中，导入后单独维护。

### 16.4 导入校验与结果

- 项目导入沿用 M10 预校验、确认、单行原子和允许部分成功规则。
- 每行独立成功或失败；失败行不回滚其他成功项目，也不生成项目编号。
- 命中当前占用项目名称或其他稳定项目标识时跳过，不覆盖或更新已有项目。
- 当前版本不支持导入`已取消`项目。
- 历史项目当前负责人按导入时客户业务责任对应的地区责任匹配；无法匹配有效负责人时阻断该行。
- 导入阶段必须与项目开始/结束时间及项目类型生命周期一致；不一致时阻断，不静默改写阶段或时间。
- 原历史编号不作为当前编号；成功导入生成新的`XM`编号，年份取原创建时间所属年份，并在该年度序列递增。
- 历史上标记已完成但当前必填资料或满意度不齐时，导入后显示`已交付`及对应待办；补齐后按自动完成规则进入`已完成`。
- 当前初始化导入不校验讲师排期，且不允许批量编辑、批量取消或借导入更新存量项目。

## 17. 状态、反馈与异常

| 场景 | 产品结果 |
| --- | --- |
| 客户无有效地区负责人 | 阻止创建或导入，指出负责人前置条件，不建立项目 |
| 项目名称重复 | 阻止创建、改名或导入；已取消项目名称不占用 |
| 采购包/平台公司停用或过期 | 不进入新选择候选；已有项目继续使用快照 |
| 讲师排期冲突 | 阻止保存，展示人员、时间和关联项目编号，无强制覆盖 |
| 导入阶段与时间不一致 | 阻断该行并要求修正 |
| 附件部分失败 | 保留已成功文件，逐项显示失败原因 |
| 提醒发送失败 | 主项目状态不回滚，P01 保留可重试结果 |
| 权限或责任变化 | 重新鉴权并清除旧范围；不凭历史负责人放行 |
| 已完成或已取消后伪造修改 | 返回状态冲突，项目事实保持不变 |

页面同时表达 Loading、Empty、Empty Result、Error、PermissionDenied、Submitting 和 Success；这些页面反馈不成为项目主阶段。

## 21. Decision / Governance

- DEC-174：项目管理成为 Current M11，并从当前人工创建过渡到合同商机流转。
- DEC-175：项目负责人由地区责任唯一驱动，交接必须同步项目且不得出现空档。
- DEC-176：项目使用五个主阶段与三个并行待办标识，当前取消直接生效。
- DEC-177：初始化项目导入归 M10，区域总监获得严格限定的项目与省级关键人导入能力。
- DEC-180：项目客户快照和负责人解析只使用客户稳定 ID、名称与业务责任事实；显式组织上级及组织路径不参与项目责任。
- DEC-182：当前员工停用不做项目交接阻断且不自动取消项目；完整交接式停用只作未来边界。

DEC-078 中“项目管理后置、本期不建设”的部分自 2026-08-27 起为 Historical / Replaced；合同归档审批、合同内容边界和财务分工继续有效。

## 22. 明确不包含

- 项目草稿、批量导出、批量编辑、批量取消和已取消项目恢复。
- 当前版本的回款明细、已回款操作或待回款解除。
- 当前版本的项目取消审批；未来统一审批中心只作为边界记录。
- 正式讲师库生命周期、讲师费用扣减、排课优先级和评分后续处置。
- 商机、合同的当前菜单与生命周期实现；只保留未来创建切换规则。
- 当前员工停用的交接人选择、项目交接阻断或自动项目取消；完整停用交接只作为未来边界记录。
- 项目经营指标、金额趋势、阶段分布和项目分析看板。
