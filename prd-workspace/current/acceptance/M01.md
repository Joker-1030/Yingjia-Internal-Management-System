# M01 Acceptance Criteria

> Mechanical migration from the current full PRD. Stable IDs, wording, priority, and row order are unchanged.

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F014-24 | 系统管理员登录 | 在系统运行和全国客户经营视图间切换并查看内容 | 可见公司全局技术和客户数据，所有操作仍显示系统管理员身份，不伪装业务角色 | P0 |
| AC-F014-25 | 指标分母为 0 | 查看覆盖率或完成率 | 显示 `--` 和可解释空态，不显示 0% 或 100% | P0 |
| AC-F014-26 | 管理层切换本月、本季度、本年 | 查看两张对比表与完成率 | 周期起止、分母、表头同步；当前快照类指标不随周期变化并有标签 | P0 |
| AC-F014-27 | 用户查看指标卡、趋势柱、区域/地市/PM 对比行、我的待办和重点动态 | 分别尝试进入来源页面 | 指标卡、趋势柱和对比行不提供下钻；我的待办及需要处理的重点异常可进入来源页面，回填可见原生筛选并重新鉴权；普通重点动态只读展示 | P0 |
| AC-F014-28 | 单个指标服务超时且存在上次成功值 | 打开工作台 | 仅该卡片显示过期标识、上次值和时间，其他模块可用；无旧值时显示 `--` | P0 |
| AC-F014-29 | PM、区域总监和市场副总查看同一全国数据集 | 分别打开工作台并进入保留的待办或重点异常下钻 | PM 仅负责地市，区域总监仅所属区域，市场副总为全国市场；落地页和入口对象范围一致 | P0 |
| AC-F014-30 | 一个有效关键人分别存在常规、生日、节假日、专项维系或覆盖 KPI 当前逾期 | 逐项计算维系健康率 | 常规、生日或节假日任一逾期均使该关键人不计入健康人数；只有专项维系或覆盖 KPI 逾期时仍计入健康人数 | P0 |
| AC-F014-31 | 当前范围同时有未来提醒、本人待办、普通保存成功、客户风险和专项异常 | 查看重点动态 | 只展示已发生的客户风险、专项异常等规定类别；未来提醒进入提醒、本人责任进入待办、普通保存成功不进入重点动态 | P1 |
| AC-F014-32 | 同一集团同时存在省级、市级、区县级业务责任客户以及多个严格归属的部门和标准岗位 | 查看工作台指标卡并打开覆盖 KPI 专项详情 | 工作台不出现部门/岗位覆盖率指标与覆盖分析入口；专项详情按目标部门 ID、标准岗位 ID 分别展示应覆盖/已覆盖/当前覆盖率/目标覆盖率，分母为 0 显示 `--` | P0 |
| AC-F014-33 | 不同客户公司或部门下存在同名标准岗位 | 查看覆盖 KPI 发布预览与专项详情 | 按所选稳定岗位 ID 分别计算且页面展示完整公司→部门→岗位路径，不因名称相同自动合并；详情数字与执行明细一致 | P0 |
| AC-F014-34 | 当前范围发生客户责任配置异常且该客户没有逾期任务 | 查看客户健康、重点动态和系统运行工作台 | 客户健康仍按二态显示健康，不出现“待分配”；管理角色重点动态展示责任异常事件，admin 同时看到原因、影响任务数和处理入口 | P0 |
| AC-F014-35 | 张三的常规维系任务自 3 月 2 日起逾期且一直未处理 | 在后续任意日期查看关键人、客户和维系健康率，随后补完成 | 补完成前任务始终显示当前逾期并标红，张三持续不计入健康人数且客户汇总逾期；补完成后生成未来下一期，健康结果按新任务重新计算，历史逾期不删除 | P0 |
| AC-F014-36 | 当前未逾期且从未逾期的常规维系任务获批暂停，暂停至日期晚于原当前截止 | 分别在原当前截止前后及恢复后查看任务、当前逾期数、关键人/客户健康状态和健康率 | 暂停期间始终归入待执行 / 暂停，不增加当前逾期数，不形成曾经逾期或首次逾期时间，关键人和客户保持健康且关键人计入健康分子；恢复时按恢复日、关键人当前职级和当前有效周期重算新当前截止，恢复后再从新截止判断风险 | P0 |
| AC-F014-37 | 省级、市级和区县级业务责任客户各有一名有效关键人，其中仅省级业务责任客户关键人的生日任务当前逾期 | 计算区域维系健康率并查看对应待办/重点异常 | 三名关键人均在分母，省级业务责任客户关键人不在健康分子且由业务责任省所属区域总监负责处理；汇总与对应任务事实口径一致 | P0 |
| AC-F014-38 | 同一数据范围分别仅存在专项维系逾期、覆盖 KPI 逾期、常规逾期、生日逾期、节假日逾期，以及三类日常维系任务暂停的关键人 | 逐项查看关键人状态、客户状态并计算维系健康率 | 仅常规、生日或节假日处于当前逾期时关键人及客户显示逾期且关键人不计入健康分子；专项维系逾期、覆盖 KPI 逾期和暂停任务均保持健康且计入健康分子；三处结果使用同一任务集合 | P0 |
| AC-F014-39 | 当前存在项目确认交付、资料待上传、待评价、待回款、已中止结算及区域内 PM 项目逾期升级 | PM、区域总监、admin、总裁、市场副总和 HR 分别打开工作台并查看保留入口 | PM/区域总监本人项目的前三类可处理事项进入我的待办并可下钻；已中止项目不产生前三类待办，仅在涉及金额结算时保留待回款提醒摘要；区域内 PM 项目升级仅为区域总监监督提醒；admin 查看公司汇总并可按 M11 代操作；总裁/市场副总只读提醒汇总；HR 不展示；不新增项目经营指标 | P0 |
| AC-F014-40 | 当前用户存在超过 5 条来自不同模块的可处理待办 | 打开工作台“我的待办” | 页面最多展示 5 条；本 AC 不规定具体选中哪 5 条、类别间顺序或同优先级顺序，这些规则在 M01 专项讨论确认前不得由实现自行固化为产品规则 | P0 |
