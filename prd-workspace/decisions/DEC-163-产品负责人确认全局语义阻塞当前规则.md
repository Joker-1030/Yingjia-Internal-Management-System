# DEC-163：产品负责人确认全局语义阻塞当前规则

- 日期：2026-08-22
- 状态：部分被 DEC-198 替代；第 5 项多角色发起客户侧停用/恢复已失效，其余规则继续有效
- 决策来源：产品负责人在“PRD Global Source Governance Remediation Prompt”中的明确确认
- 背景：GLOB-001、003、004、006、007、011、012、016、018、021、022、024 在旧 PRD、Acceptance、Decision、Flow 或 Shared 中存在相反表达，导致 Candidate 无法形成唯一 Current Rule。
- 决策：
  1. 客户部门只能归属一个客户公司，不存在集团共享客户部门；当前层级为“客户公司 -> 客户部门 -> 标准关键人岗位”。
  2. 生日和节假日任务不允许逾期补完成，不提供宽限窗口或补完成入口。
  3. 规则变更只影响新生成任务；已生成任务保留生成时规则快照，不允许批量重算或回写。
  4. 省公司任务的逾期补录按省公司责任路由上提市场副总或总裁；市/区县任务仍由所属区域总监审批。
  5. 总裁、市场副总、区域总监、PM 和 admin 可在真实业务范围内发起客户主数据停用/恢复；HR/人事不可发起。
  6. 停用生效时统一关闭适用的未完成任务，不提供通用任务责任转移、迁移或重新分配能力。
  7. 当前关键人因筛选、范围或数据变化失效时，自动选择当前结果集第一位有效关键人；无有效结果时进入未选择/空态。
  8. 跨公司覆盖 KPI 严格使用稳定对象 ID 组成目标集合，不按名称匹配或合并同名部门、岗位，也不建立集团共享 KPI 对象。
  9. 关键人手机号在列表、详情、编辑表单、审批快照和操作日志中对全部角色统一脱敏，不显示明文。
  10. 导入限制为单工作表最多 5,000 条业务行；5,001 条及以上拒绝导入。
  11. 导入按单行原子处理；每行独立成功或失败，某行失败不回滚其他成功行。同一行对应业务对象不得形成产品事实半成品。
  12. 标准关键人岗位编号由系统生成，格式为 `POS` + 8 位数字，系统内全局唯一、不可编辑、永久不回收。
  13. 关键人调岗进入 M04 审批，审批成功后执行任职变化；用户填写的计划调岗日保留在任职履历中，不因计划日期提前改变当前任职。实际生效时点若与既有“审批通过与计划日较晚时刻”规则仍有差异，继续作为 Clarification，不在本决策中扩张。
  14. `已通过-业务处理失败` 的审批结论仍为已通过；业务对象可保持原状态并受控重试，持续失败只提醒 admin，不产生普通业务角色审批待办，不新建审批实例，也不改为已驳回。
- 历史/替代关系：本决策替代 DEC-018 的集团共享部门模型、DEC-043/DEC-106 中生日和节假日允许补完成的部分、DEC-102/DEC-110 中批量重算已生成任务的部分、DEC-123 中标准关键人岗位编号“同集团唯一”的范围。DEC-125、DEC-148、DEC-149、DEC-161 和 DEC-064 与本决策一致并继续有效。
- 未采用方案：恢复任一历史冲突规则；按名称合并跨公司对象；将导入原子性解释为整个工作表或整个批次；将产品确认反推为 Source of Truth Migration 授权。
- 原因：产品负责人已逐项给出明确产品裁决，需要建立单一可解析的 Current Rule 入口，同时保留原始 Decision、Acceptance、Flow 和 PRD 文本作为 Historical / Replaced Evidence。
- 决策人：产品负责人
- 影响范围：M01-M10、GLOB-001/003/004/006/007/011/012/016/018/021/022/024、Acceptance、User Flow、Shared、Glossary、Product Boundary

> 后续治理（2026-08-24，DEC-164）：本决策第 13 项保留的关键人调岗实际生效时点 Clarification 已关闭。Current Rule 为审批通过时刻与计划调岗日 00:00 取较晚值；等待期间关联展示“已通过待生效”，审批结论仍为已通过。原 Clarification 文本保留用于追溯。

> 后续治理（2026-09-03，DEC-198）：本决策第 5 项的多角色客户侧停用/恢复发起权已被替代。Current Rule 为仅内置 `admin` 可操作集团公司、客户公司、关键人和客户部门的停用/恢复，影响校验与二次确认后直接生效，不进入 M04；M05 继续保留记录和审计。
