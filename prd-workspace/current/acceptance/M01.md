# M01 Acceptance Criteria

> Current Acceptance；既有稳定ID和优先级保留，2026-09-11按确认的角色概览与固定卡片布局更新。

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F014-24 | 系统管理员登录 | 在系统运行和全国客户经营视图间切换并查看内容 | 可见公司全局技术和客户数据，所有操作仍显示系统管理员身份，不伪装业务角色 | P0 |
| AC-F014-25 | 指标分母为 0 | 查看覆盖率或完成率 | 显示 `--` 和可解释空态，不显示 0% 或 100% | P0 |
| AC-F014-26 | 用户查看任务卡并切换项目分析维度/指标 | 查看各卡片 | 不再显示任务月/季/年控件；专项逐项全生命周期，常规当前快照；项目切换只更新自身图形、合计、数值和占比，不筛选其他卡片 | P0 |
| AC-F014-27 | 用户查看概览数字、项目阶段图及本人待办 | 尝试操作 | 数字与阶段图只读无下钻；待办进入既有来源页并重新鉴权；首页不执行业务写操作，不新建多层详情 | P0 |
| AC-F014-28 | 单个指标服务超时且存在上次成功值 | 打开工作台 | 仅该卡片显示过期标识、上次值和时间，其他模块可用；无旧值时显示 `--` | P0 |
| AC-F014-29 | PM、区域总监和市场副总查看数据 | 打开工作台及保留待办入口 | PM关键人/任务按当前负责地市，总监按全部主管区域并集，市场副总全国市场；项目按M11独立资格。最终权限先过滤后聚合；失权不泄露名称、数量、阶段；HR/单独商机支撑不增加M01资格 | P0 |
| AC-F014-30 | 一个有效关键人分别存在常规、生日、节假日、专项维系或覆盖 KPI 当前逾期 | 逐项计算维系健康率 | 常规、生日或节假日任一逾期均使该关键人不计入健康人数；只有专项维系或覆盖 KPI 逾期时仍计入健康人数 | P0 |
| AC-F014-31 | 当前范围有本人待办、监督事项、未来提醒和已发生动态 | 查看业务工作台 | 只保留本人可处理待办；不另设重点动态和长提醒清单，监督不转代办；P01消息与来源事实保持，普通保存不新增通知 | P1 |
| AC-F014-32 | 同一集团同时存在省级、市级、区县级业务责任客户以及多个严格归属的部门和标准岗位 | 查看工作台指标卡并打开覆盖 KPI 专项详情 | 工作台不出现部门/岗位覆盖率指标与覆盖分析入口；专项详情按目标部门 ID、标准岗位 ID 分别展示应覆盖/已覆盖/当前覆盖率/目标覆盖率，分母为 0 显示 `--` | P0 |
| AC-F014-33 | 不同客户公司或部门下存在同名标准岗位 | 查看覆盖 KPI 发布预览与专项详情 | 按所选稳定岗位 ID 分别计算且页面展示完整公司→部门→岗位路径，不因名称相同自动合并；详情数字与执行明细一致 | P0 |
| AC-F014-34 | 客户责任异常但没有逾期任务 | 查看来源客户健康及系统运行视图 | 客户健康仍为健康/逾期二态，不出现待分配；业务首页不新增异常动态卡，admin系统视图既有异常表达保持 | P0 |
| AC-F014-35 | 张三的常规维系任务自 3 月 2 日起逾期且一直未处理 | 在后续任意日期查看关键人、客户和维系健康率，随后补完成 | 补完成前任务始终显示当前逾期并标红，张三持续不计入健康人数且客户汇总逾期；补完成后生成未来下一期，健康结果按新任务重新计算，历史逾期不删除 | P0 |
| AC-F014-36 | 当前未逾期且从未逾期的常规维系任务获批暂停，暂停至日期晚于原当前截止 | 分别在原当前截止前后及恢复后查看任务、当前逾期数、关键人/客户健康状态和健康率 | 暂停期间始终归入待执行 / 暂停，不增加当前逾期数，不形成曾经逾期或首次逾期时间，关键人和客户保持健康且关键人计入健康分子；恢复时按恢复日、关键人当前职级和当前有效周期重算新当前截止，恢复后再从新截止判断风险 | P0 |
| AC-F014-37 | 省级、市级和区县级业务责任客户各有一名有效关键人，其中仅省级业务责任客户关键人的生日任务当前逾期 | 计算区域维系健康率并查看对应待办/重点异常 | 三名关键人均在分母，省级业务责任客户关键人不在健康分子且由业务责任省所属区域总监负责处理；汇总与对应任务事实口径一致 | P0 |
| AC-F014-38 | 同一数据范围分别仅存在专项维系逾期、覆盖 KPI 逾期、常规逾期、生日逾期、节假日逾期，以及三类日常维系任务暂停的关键人 | 逐项查看关键人状态、客户状态并计算维系健康率 | 仅常规、生日或节假日处于当前逾期时关键人及客户显示逾期且关键人不计入健康分子；专项维系逾期、覆盖 KPI 逾期和暂停任务均保持健康且计入健康分子；三处结果使用同一任务集合 | P0 |
| AC-F014-39 | 有权项目包含六主阶段及本人可处理事项 | 各角色打开工作台 | PM本人项目、总监全部主管区域项目、总裁/副总/admin公司项目按原资格聚合；支持数量/原项目金额分布，项目只读；本人交付/资料/评价进入待办，监督和待回款不是代办，HR不展示 | P0 |
| AC-F014-40 | 当前用户存在超过 5 条来自不同模块的可处理待办 | 打开工作台“我的待办” | 页面最多展示 5 条；本 AC 不规定具体选中哪 5 条、类别间顺序或同优先级顺序，这些规则在 M01 专项讨论确认前不得由实现自行固化为产品规则 | P0 |
| AC-F014-41 | 当前角色有客户、关键人、常规/专项任务及项目 | 查看四块概览 | 关键人与覆盖按M01 §6.2/6.3/6.19；常规待完成/逾期按§6.17，专项逐项按§6.20；项目分组按§6.18。无数据、空分母与失败分别表达，后台规则不出现在业务界面 | P0 |
| AC-F014-42 | 待办为零、少量、大量或长名称，窗口为宽屏/窄屏 | 查看工作台并滚动卡片内容 | 关键人/任务各自固定高度，项目/待办等高；卡片不随条数增长，标题固定；关键人/任务左侧数字纵排保持可见，右侧列表独立滚动且表头固定；超量内容与操作可达；窄屏上下排列仍固定高度；不因限高改变选取/排序 | P0 |
| AC-F014-43 | 总裁/副总/总监各有不同客户责任范围，且有多个不同生命周期的专项 | 查看覆盖行及任务区 | 总裁/副总按区域，总监按当前PM负责客户；覆盖率逐组按客户数计算，总体不平均百分比；常规仅待执行/暂停与逾期，专项每项完成/有效执行项，不混月度率或KPI客户覆盖率；失权无泄露 | P0 |
| AC-F014-44 | 同一有权项目集合有培训/AI软件及六主阶段，含取消/中止 | 筛选全部/培训/AI软件，并切换阶段/类型与数量/金额组合 | 默认全部类型+阶段+数量；类型筛选先于统计，维度/指标切换保留类型；培训阶段数量/金额及占比只取同一有权培训集合，AI软件同理；类型分组保留正式零值行；无结果沿用零合计空态；分组互斥合计等于中心，分类数值和占比同步；金额用含税原项目金额，两位小数，占比一位；零合计占比--，非法金额仅阻断金额视图；不新增写操作或财务字段 | P0 |
| AC-F014-45 | PM本人范围内存在已覆盖/未覆盖及停用客户、无效关键人，或责任发生变化 | 查看关键人概况右侧 | 仅列同一覆盖率分母中有效关键人数0的正常公司名称，沿用来源顺序，不截TopN、不加下钻；左指标固定、右列表独立滚动且表头固定；全部覆盖与无客户分别显示对应空态；失权不泄露，管理角色分组不变 | P0 |
