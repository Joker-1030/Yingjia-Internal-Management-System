## 1. 模块目标

M12 用同一组当前销售事实完成三件事：逐级分配可核对的商机数量目标；查看销售仪表盘和当前商机快照；持续创建、推进、跟进并协同支撑商机。

日常沟通中的“线索”只描述处于商机录入、需求确认等早期阶段的商机。系统不建立独立线索对象、线索菜单、线索字段或另一套生命周期。

## 2. 当前范围

### 2.1 包含

- 销售仪表盘；
- 商机数量指标的公司、区域和 PM 逐月分配、版本和调整；
- 商机列表、新建、详情、改派和顺序推进；
- 商机跟进记录、下一步行动和逾期提醒；
- 一人或多人方案支撑请求、响应、交付和关闭；
- 已发布指标调整直接生效，以及与 P01 的跟进/支撑消息关系。

### 2.2 不包含

- 独立 Lead/线索对象、菜单、字段、状态或转商机流程；
- 合同管理对象、合同页面、合同归档、补充协议或合同撤销；
- 财务系统角色；
- 回款、开票、预计成本、毛利或财务确认；
- 已签约商机阶段、签约金额/数量目标及完成值；
- 因 M12 上线而改变 M11 当前人工创建项目的规则；
- 从历史销售 Demo、旧增量或实现代码恢复上述能力。

## 5. 页面结构

M12 一级入口包含：

1. `销售仪表盘`：默认页，查看周期目标与完成、当前商机概览、阶段漏斗、趋势和区域覆盖；
2. `商机列表`：筛选、分页查看商机，并从操作列进入详情或从页面操作区新建商机；
3. `销售指标`：由具备设置、分配或调整权限的管理角色进入，按权限维护目标、分配、版本和调整；PM 使用独立只读`我的销售指标`，只展示本人月度目标、完成、差额、完成率和本人调整历史；
4. `我的方案支撑`：对具有商机支撑角色且有页面权限的有效员工展示；无请求时显示既有空态，单角色登录进入此页，集中查看和处理本人请求所需的最小商机、客户、支撑需求、时限和交付信息。
5. `方案支撑管理`：仅 admin 使用，查看公司全量方案支撑请求并按原请求允许的动作代操作；页面始终记录 admin 真实身份，不把 admin 写为候选、受理人或原支撑人员。

商机详情包含：

- 基本信息；
- 跟进记录；
- 方案支撑；
- 阶段历史。

`跟进记录`和`方案支撑` Tab 的名称承担当前内容区标题，Tab 内不重复展示同义标题或说明；有权操作按钮位于表格前的统一操作区，表格和空状态保持原业务含义。

所有页面级筛选遵循 Current 统一规则：编辑条件不会立即筛选，点击“筛选”后生效，重置清空条件并回到第 1 页；不展示“筛选结果 N 项”等结果说明。

商机列表、方案支撑列表和销售指标中的普通列表默认每页 20 条，可选 20/50/100；`我的销售指标`仅展示本人月度记录和本人调整历史，不扩展跨层级数据范围。

## 6. 销售指标

### 6.1 当前指标维度

当前只维护`商机数量`目标：完成值取权限范围内在所选周期新建的商机数，正常落选仍保留创建事实，周期按商机创建日期。Current M12 不存在“停用商机”或“认定重复”状态和操作，因此不得设置相应排除条件。

`商机数量目标完成率 = 周期有效新建商机数 / 周期目标 x 100%`，结果保留 1 位小数；`差额 = 完成数 - 目标数`，正数表示超额。周期目标为 0 时完成率显示`—`，不以 0% 替代。

签约金额、签约数量、回款金额和毛利金额不属于 Current M12 指标维度。页面不得为这些未接入事实提供维护入口，也不得用 0 表达“尚无数据源”。

### 6.2 粒度与守恒

1. 总裁或系统管理员先建立并发布一个自然年度 12 个月的公司目标，月份是最小分配粒度；季度和年度由月份汇总。
2. 每月区域目标合计必须等于公司目标；每月 PM 目标合计必须等于所属区域目标。
3. 市场副总分配区域目标，区域总监分配本区域 PM 目标；总裁和系统管理员可覆盖任一层级。上级目标允许先发布；下级尚未分配时，对应层级显示`未分配`且不计算该层完成率。
4. 已发布目标调整形成新版本。总裁和系统管理员可调整任一层级；市场副总可调整区域目标；区域总监可调整本人主管区域内 PM 目标。全部有权调整在当前月/未来月、上下级守恒、调整原因和并发校验通过并二次确认后直接生效。
5. 校验或确认完成前继续使用最近生效版本；失败不改变当前目标或生成新版本。
6. 销售负责人、人员、区域或责任变化不改写历史月份目标；只允许另行调整当前月及未来月份，且调整后继续满足守恒。目标按 PM 员工 ID 归属，同一员工只计一次。
7. 版本保留调整前后值、差额、原因、操作人和生效时间，只追加不覆盖；不保存审批实例。

## 7. 销售仪表盘

仪表盘把“所选周期”和“当前快照”明确分开：

- 所选周期：商机数量目标、完成、差额、完成率和新建商机趋势；
- 当前快照：全部商机数、活跃商机数/金额、中选数/预计金额、落选数/预估金额、阶段漏斗、客户商机覆盖和区域对比。

规则：

1. 时间范围支持年、季度、月，默认当前月；年度和季度趋势按月展示，月度趋势按日展示。
2. 所选周期卡片展示目标、完成数、差额和完成率，计算口径见“6.1 当前指标维度”；下级未分配时展示`未分配`且不计算其完成率。

3. 活跃商机为商机录入、需求确认、方案支撑、比选或中选阶段；落选不属于活跃商机。
4. 活跃金额在商机录入至比选阶段使用`预估金额（含税，元）`，中选阶段使用`预计签约金额（含税，元）`。
5. 中选率为中选结果数除以中选与落选结果数；未形成结果的活跃商机不进入分母。
6. 客户单位当前存在至少一条活跃商机时视为有商机覆盖；只有历史落选商机不构成当前覆盖。
7. 趋势展示新建和中选事件，支持数量/金额切换；金额统一为含税人民币，合同或财务事件不进入 Current M12 趋势。
8. 仪表盘的指标卡、阶段漏斗和区域对比仅用于概览，不提供商机明细下钻，不向商机列表传递筛选条件，也不改变商机列表已有筛选状态；需要查看商机时从页面顶部`商机列表`入口进入。
9. 无数据时数值可显示 0、比率显示 0%；查询失败或外部数据未接入不能显示为 0。

## 8. 商机列表与新建

### 8.1 列表

列表默认按最近更新时间倒序，同一最近更新时间按商机编号倒序。创建、阶段推进、新增跟进、发起方案支撑或支撑状态变化、负责人改派、商机基本信息成功编辑均更新最近更新时间。列表独立展示：商机编号、商机名称、商机类型、阶段、客户单位、`当前有效金额（含税，元）`、优先级、当前阶段停留时间、负责人、创建时间、最近更新时间、创建人和操作。商机编号和商机名称仅作信息展示，不承担详情下钻；有权用户统一通过操作列中的`详情`按钮进入商机详情。

筛选项：商机编号、商机名称、商机类型、阶段、客户单位、业务责任区域、负责人、优先级、预计成交日期起止、创建日期起止、跟进是否逾期。两个日期区间均包含起止当天；商机名称模糊匹配，商机编号精确匹配，多个已应用条件取交集。

4. 保存时重新校验客户状态、业务责任、负责人有效性和全部已选关键人；任一事实变化时不创建商机，保留可继续修正的输入。

### 8.3 编辑

落选前仅当前负责人可编辑商机名称、优先级、`预估金额（含税，元）`、关键人、需求描述和预计成交日期；关键人继续从当前客户有效关键人中可搜索多选且至少 1 人，保存时重新校验。客户单位、商机类型不可编辑，负责人只可通过改派变化。进入中选后`预估金额（含税，元）`只读。每次成功编辑更新最近更新时间并记录发生时间、操作人、变更字段及前后值；失败不改变商机或生成历史。

## 9. 商机阶段与改派

当前阶段主链路：

```text
商机录入 -> 需求确认 -> 方案支撑 -> 比选 -> 中选
     \           \           \        \       \
      +-----------+-----------+--------+------> 落选
```

1. 主链路只能逐级前进，不允许跳过或退回。
2. 任一未落选阶段可进入落选；进入落选必须填写落选原因、竞争对手和复盘说明。
3. 进入中选必须填写中选日期和`预计签约金额（含税，元）`。中选仍可跟进，等待未来独立合同能力；M12 不提供已签约按钮或状态。
4. 落选是 Current M12 终态，不再显示阶段推进或新增跟进入口。
5. 每次变化保留原阶段、新阶段、生效时间、操作人和阶段必填事实，不覆盖历史。
6. 当前阶段停留时间从最近一次阶段生效时间自动计算；落选后冻结。
7. 仅当前负责人可正常推进和跟进；区域总监作为省级业务责任客户商机的自动匹配负责人时可直接编辑、推进、跟进和发起方案支撑，监管的其他商机必须先合法改派给新负责人。系统管理员代操作保留真实身份，不改写负责人。
8. 改派保留前后负责人、原因、操作人和生效时间；过程指标按事件发生时负责人归属，后续改派不改写历史。

客户停用、负责人停用或负责人失去范围时，不允许继续推进；有权管理者先完成合法改派或处理客户状态。

M08 交接或直接调整城市 PM 负责人时，该城市全部未落选商机必须原子改派给新 PM 负责人并记录来源责任变更编号、前后负责人、操作人和生效时间；已落选商机不迁移。任一未落选商机无法迁移时，PM 地市责任变更整体不生效。

## 10. 方案支撑

1. 商机创建时或创建后可向一名或多名在职、账号有效且具有商机支撑角色的员工发起支撑请求；同一员工按稳定员工 ID 去重，每名支撑人员生成一条独立请求并记录交付截止时间。市场副总、区域总监只有兼任上述角色时才进入候选；admin 可代操作但不作为普通候选。
   新建商机附带支撑与详情发起支撑在提交时重新校验全部已选员工；角色移除、停用或伪造候选时拒绝整个提交，不生成商机或请求。提示“支撑人员已不符合当前候选条件，请重新选择”。角色移除后不再具备本人支撑接收与处理资格，不能凭旧请求继续操作；无权或不合法状态操作提示“当前无法执行该支撑操作”，不改写请求。负责人验收与 admin 代操作沿用既有授权。

2. 每次发起必须填写`支撑需求`和交付截止时间；缺少任一项不创建请求。
3. 状态依次为：待响应、进行中、已交付、已关闭。
4. 支撑人员点击“确认接收”时先打开二次确认弹窗，最终确认后才由待响应进入进行中；不提供过程提交、过程文件或单独已响应状态。进行中点击“提交支撑文件”，必须填写文件说明并上传至少一个文件附件，成功后为已交付；商机负责人确认接收后为已关闭。
5. 负责人要求补充时退回进行中并保留意见；待响应可撤回，接收后关闭原请求并重新发起，不覆盖历史。
6. 不设置回应截止时间，不判断首次回应超时，不发送回应超时消息，不展示回应超时标签或列。交付截止时间只表达文件交付约定；本次不增加交付逾期状态、标签、自动提醒、自动关闭或超时禁止提交规则。
7. 被指派员工通过`我的方案支撑`查看完成支撑所需的客户单位、商机名称与编号、支撑需求、交付截止时间、剩余时间和当前状态，已交付内容通过操作栏“查看交付”打开；可从操作列“商机详情”进入被指派商机的既有详情页，只读查看支撑所需商机背景，采用下述“支撑视角商机详情”，不展示跟进记录、阶段历史或方案支撑 Tab。返回“我的方案支撑”，不获得商机列表、销售指标、其他商机或客户经营权限；不允许编辑、推进、改派、跟进或发起支撑。兼任角色已有独立业务权限继续生效。角色撤销、停用或无本人指派时，详情及附件直接访问均拒绝。
8. 支撑人员处理中停用时，原请求保留历史，负责人关闭原请求并向有效员工重新发起；不新增自动转交状态。
9. admin 通过`方案支撑管理`查看公司全量请求并代执行原请求已定义的合法动作；内部操作留痕继续保留原负责人/支撑人员和 admin 真实操作身份；支撑列表与商机详情方案支撑 Tab 均不展示操作历史列、列表或替代入口。admin 不进入普通候选，不成为请求受理人，`我的方案支撑`不展示公司全量请求。

2026-09-11 Product Owner 要求增加剩余时间并按临近截止优先排列，确认以下已交付处理、超时展示和四项筛选；适用于“我的方案支撑”及 admin 的“方案支撑管理”，原可见请求范围不变。

## 11. 商机跟进

跟进记录字段：跟进时间、跟进方式、参与关键人、跟进内容与结果、当前风险、下一步行动、下次跟进日期和可选附件。除附件外均为必填。

`当前风险`为固定九项必填单选：`暂无风险`、`需求不明确或发生变化`、`预算风险`、`决策推进风险`、`竞争风险`、`方案或交付风险`、`商务条件风险`、`预计成交延期`、`其他`。选择`其他`时必须填写风险说明；`暂无风险`与其他选项互斥。当前风险是跟进记录事实，不形成商机状态，不改变六阶段生命周期。

规则：

1. 跟进时间不得晚于提交时间；参与关键人从商机当前有效关键人中选择。
2. 下次跟进日期必须晚于本次跟进时间；新记录保存后，上一条承诺闭环，新日期成为当前承诺。
3. 到达下次跟进日期当日上午提醒负责人，但当天仍是到期提醒而非逾期；仅当下次跟进日期早于今天且没有新有效跟进时才认定逾期，从次日起每日一次，逾期满 3 个自然日时同时提醒所属区域总监，节假日不顺延。
4. 新增有效跟进后停止旧承诺提醒；提醒失败不改变逾期事实。
5. 落选后不再要求或允许新增跟进；已有跟进历史继续只读可见。

商机跟进记录与 M03 维系记录是不同业务对象，不互相替代或复制。

## 12. 状态与失败保护

- Loading、Empty、Empty Result、Error、PermissionDenied、Submitting 和 Success 是页面反馈，不是商机状态。
- 必填缺失、关键人失效、范围变化或阶段不合法时不创建记录、不改变阶段，并保留用户可继续修正的输入。
- 并发阶段推进按当前版本拒绝后到请求，不覆盖已生效结果。
- 越权直接访问返回 403，不透露对象名称、状态、数量或是否存在。
- 指标发布不守恒时明确指出月份和差额，不生成生效版本。
- 消息失败不回滚商机、跟进或支撑事实，并按 P01 规则重试。
