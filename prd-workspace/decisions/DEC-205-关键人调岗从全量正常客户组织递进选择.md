# DEC-205 关键人调岗从全量正常客户组织递进选择

- 状态：已确认
- 日期：2026-09-05
- 决策人：Product Owner
- 主要 Owner：M02 客户经营
- 影响：M09 客户基础配置提供既有客户组织主数据；M03、M08 继续消费调岗生效结果

## 背景

现行关键人跨范围调岗使用“权限内选择 / 精确信息查找”双模式。精确信息查找要求输入客户公司完整名称、信用代码，或集团与完整区划，操作人不能直接从完整客户组织中选择目标。Product Owner 确认客户组织主数据不属于需要在调岗场景隐藏的业务数据，目标公司可从全量客户公司选择。

## 决策

1. 关键人调岗删除“目标单位定位方式”，不再区分“权限内选择”和“精确信息查找”。
2. 跨单位调岗统一按“行业 -> 集团 -> 客户公司 -> 部门 -> 岗位”递进单选；只提供 M09 当前正常且上下级关系有效的客户组织候选。
3. 行业、集团、客户公司、部门或岗位任一上级发生变化时，立即清空其全部下级选择；前置项未选择时，下级控件不可选择。
4. 同单位任职变更固定并只读当前客户公司及其行业、集团，只允许从当前公司正常部门和对应正常岗位中选择；新部门或新岗位至少一项必须变化。
5. 提交确认和未来计划日期实际生效前，均按稳定 ID 重新校验行业、集团、客户公司、部门和岗位处于正常状态且构成同一完整路径。路径不完整、对象失效或上下级不一致时不生效，原任职保持不变。
6. 全量候选只适用于关键人调岗目标组织选择器，只返回完成目标职业路径选择所需的客户组织主数据。它不扩大关键人、任务、维系记录、客户负责人、客户详情或其他经营数据的查看、搜索、统计、下钻和操作权限。
7. 调岗发起人、原对象权限、影响摘要、计划生效日、同一未结束记录限制、直接/待生效、任职原子衔接、任务与覆盖 KPI 处理及历史保留继续执行现行规则。

## 替代关系

- 局部替代 DEC-017 中“跨范围调岗不得返回目标单位候选、只能提交完整目标单位信息后精确校验”的语义；DEC-017 的其他 PM 数据范围规则继续有效。
- 局部替代 DEC-097 中“通过完整名称加信用代码或集团加完整区划精确定位目标单位”的语义；DEC-097 的其他三栏、关键人、影响摘要和健康率规则继续有效。
- DEC-161 的客户公司、客户部门、标准岗位严格归属关系继续有效。
- DEC-204 的调岗无审批、直接或待生效及到期复核规则继续有效。
