## 产品介绍

### 产品目标

- 使用稳定对象沉淀客户、关键人、任职、维系动作和历史记录，避免人员变动造成客户资产丢失。
- 以组织员工、系统角色、区域与地市责任形成账号权限和客户责任的产品事实。
- 支持维系任务生成、执行、统计和追溯；当前异常处理和逾期补录由 M03 按既有权限与校验直接生效。
- 以统一项目对象承接培训与 AI 软件项目的立项、交付、资料、评价、责任和商业快照。
- 以销售指标、商机、跟进和方案支撑形成可核对的销售推进事实，不重复建设独立线索对象。
- 让列表、搜索、详情、附件、导入和直接访问使用一致的数据范围。
- 为用户可见的表单、状态变化和异常提供明确反馈。

### 使用范围

Current Product Source 覆盖登录、工作台、客户经营、维系管理、审批中心及已确认企业微信审批对接定义、M05 移除边界、消息、组织员工、权限授权、区域地市配置、客户基础配置、数据导入、项目管理、销售与商机管理和培训老师管理。M04 审批中心仍为未评审、未研发的 Working Demo 范围，但已确认七类业务审批的产品规则；平台提供独立一级菜单、列表/详情、动态发起表单及来源业务入口，真实企业微信接入和模板路线仍待评审/验证。M05 独立停用记录能力已取消并保留编号，不提供菜单、页面、路由、权限或统一历史中心。

本期不包含独立线索对象或菜单、合同管理、回款、开票、成本、毛利、项目取消/中止审批或项目经营分析。财务角色仅纳入公司全部项目只读和现有项目看板，不开放财务核算或商业配置管理，准确边界见 [`DEC-245`](../decisions/DEC-245-财务角色全项目只读与项目看板.md) →“当前规则”。客户组织路径由显式组织上级决定，业务责任层级及业务责任省/市/区县独立驱动区域、负责人、权限、任务、非平台师资合作项目责任和商机范围；普通资源项目和普通类型商机通过稳定客户公司 ID 和业务责任关联既有事实，平台师资合作项目及商机改为引用平台公司稳定编号，不复制客户或区域主数据。M12 上线本身不改变 M11 当前人工创建项目的规则。

全部员工停用由 HR/人事或 admin 发起；确认前查询未完成及需交接事项，必须选好并校验地区责任、方案支撑、生态项目及个人目标的有效接替人。确认后先立即停用员工和账号并使会话失效，再由系统自动执行各项交接；失败不恢复账号或撤销其他成功项，失败项由有权管理者继续处理。仅移除商机支撑或生态合作员角色仍先交接成功再移除。PM 地市和区域中心责任分别选择当前有效的对应角色接收人；区域总监接收人自动成为对应部门主管，多个责任组可选同一或不同人员。未完成 M03 任务关闭原执行项并在同一父任务下为接收人新建；M11 非平台师资合作项目在员工停用、普通 PM 地市交接、区域责任交接和直接调整中均迁移六个阶段，项目终态、资料、快照和历史保持；M12 普通类型未落选商机随PM 地市或省级区域责任迁移；平台师资合作商机不随地区迁移，复用生态项目同一有效接替人交接未落选商机，已落选商机不迁移。已成功责任组不因其他组失败而回滚，恢复不重开旧执行项或取回原责任。本期不新增员工交接审批、独立交接模块、交接编号或处理状态。

### 用户角色

| 角色 | 主要产品立场 |
| --- | --- |
| 总裁 | 公司全局经营和管理查看 |
| 市场副总 | 全国市场执行、规则查看、专项及区域相关管理 |
| 区域总监 | 本人主管区域的监管、地市责任、省级业务责任客户和项目监管/执行 |

| 商机支撑 | 处理本人被指派的方案支撑请求；可与其他业务角色兼任，不获得客户经营或销售管理权限 |

| 财务 | 仅查看公司全部六阶段项目、项目资料附件及历史，工作台为现有项目看板；无项目维护和框架/采购包/平台公司管理权限 |
| HR/人事 | 公司组织、员工、账号和人员异动维护，无客户经营权限 |
| 系统管理员 | 公司全局全部业务和技术维护权限，独占权限授权 |

## 核心原则

### 权限边界

- 权限同时受菜单/页面、操作、字段、附件和对象数据范围约束。
- 无权入口不可见，伪造请求不得返回越权对象信息。
- 系统管理员为公司全局全权限账号，但操作必须记录真实管理员身份，不改写业务责任快照。
- 权限授权仅系统管理员可访问；其他角色不能通过兼任获得该入口。

### 数据可见性

- 总裁使用公司全局范围，市场副总使用全国市场范围。
- 区域总监使用本人主管的全部区域中心并集。
- PM 使用当前有效负责地市范围。
- HR/人事使用公司组织范围，不获得客户业务范围。
- 搜索、列表、计数、详情、附件、导入和直接访问使用相同范围。

### 产品事实所有权

- 内部组织与员工事实归 M06。
- 角色模板权限归 M07。
- 区域与地市责任归 M08。
- 客户主数据、显式客户组织上级、客户组织树和业务责任字段配置归 M09；业务责任对应的区域与地市人员关系归 M08。
- 客户资产日常使用归 M02，任务生命周期归 M03；已确认进入审批的业务由来源模块准备申请、M04承载企业微信审批状态并在通过后触发原规则，未列入事项仍由来源模块直接处理。
- M05 独立停用记录已移除；M02、M06、M09 保留各自对象的停用/恢复历史，M03、M11、M12 只记录停用对本模块对象造成的结果。
- 关联关系不自动授权跨模块修改。
- 项目、采购包、平台公司、项目资料、满意度和项目责任历史归 M11；客户与地区责任仍归 M09/M02 和 M08。
- 销售指标版本、商机、商机跟进和方案支撑归 M12；客户、关键人、员工和区域责任继续由 M02/M06/M08/M09 提供。

- 老师档案、渠道、方向目录、人工不可用和教学管理范围归M13；M11拥有项目占用，M06拥有员工及角色关联，M07拥有模板，均不得相互绕过权限上限。

### 状态与反馈

- 页面必须表达正常、加载、空、错误和无权限等可见结果。
- 操作必须表达提交中、成功、失败、阻断和冲突反馈。
- 页面反馈状态不替代业务对象生命周期，也不新增业务规则。
