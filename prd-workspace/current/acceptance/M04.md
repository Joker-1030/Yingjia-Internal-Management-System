# M04 Acceptance Criteria

> M04 审批中心当前为 `NOT REVIEWED / NOT STARTED / DEFERRED`。本地 Working Demo 已表达下列未评审范围，本文不构成产品评审通过或研发授权。稳定 AC 编号保留历史 `WECOM` 后缀，当前语义和验收均按企业微信执行。

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F011-37 | PM、区域总监或市场副总在自身客户数据范围内执行已确认进入审批的关键人停用，或有权用户执行任务延期/暂停/取消、已开始项目中止、地市交接或销售指标调整 | 来源模块完成既有权限、数据、状态、影响和并发校验 | 生成平台发起审批实例并进入审批中；原业务对象保持原状态，企业微信通过后才执行来源模块变更，驳回/撤回不改变业务对象；admin 对关键人停用不生成审批并按 M02 直接生效规则处理 | P0 |
| AC-F011-38 | 当前用户执行项目取消、关键人恢复或其他未列入事项 | 点击原业务操作 | 继续按来源模块现有直接生效规则处理，不生成审批实例 | P0 |

## 已确认企业微信专项定义的分项验收（未评审、未研发）

以下仅覆盖M04 §3已确认部分，不代表审批中心已开放或已具备完整上线验收。具体模板和接口能力的缺口不得以Demo或假接口通过；既有AC-F011-37/38运行边界保持。

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-M04-WECOM-BINDING-20261118 | 双方已有员工 | HR/admin核对绑定 | 一对一且不重复；同名只辅助；不自动创建或覆盖部门/角色/账号，不因此增加企业微信登录 | P0 |
| AC-M04-WECOM-IDENTITY-20261118 | 申请员工未绑定或存在冲突 | 从平台发起审批 | 阻止并提示先处理身份，不用admin或其他员工替代提交 | P0 |
| AC-M04-WECOM-UI-20261120 | 已登录用户进入审批中心 | 查看菜单、列表和发起入口 | 审批中心作为独立一级菜单显示；可查看四类参与关系、筛选和详情；点击“发起审批”进入审批事项动态表单 | P0 |
| AC-M04-WECOM-LAUNCH-20261120 | 当前员工已完成一对一企业微信绑定 | 先选择审批事项，再填写该事项要求的字段；已映射业务字段从平台下拉选择并提交 | 字段随审批事项变化并按事项校验；审批人和抄送人由企业微信模板路线预设，平台不提供选择；新增一条平台发起审批记录，保存事项及字段值，进入“我发起的”，状态为审批中 | P0 |
| AC-M04-DETAIL-SIMPLIFY-20261127 | 用户有权查看审批 | 打开审批详情 | 保留申请内容、必要业务影响、流程编号、发起人及时间、进度、处理人、抄送人和流程节点；不展示数据范围、处理位置、重复类型/状态、重复发起记录及内部规则注释；完成时间仅有值时显示；关键人停用影响仅保留任务处理方式及未完成任务数；不改变权限、审批状态或生效逻辑 | P1 |
| AC-M04-NODE-OVERVIEW-20261127 | 已同步企业微信审批路线和节点记录 | 查看审批详情 | 处理人展示同步姓名，结束后展示实际最后处理人，缺失时为空值而非路由/角色文案；完整路线按顺序展示，完成绿色、审批中黄色、待审批灰色、驳回红色；名称/状态、处理人、实际时间、意见分行，长内容换行；驳回展示实际驳回时间，未处理不伪造时间/意见；不按平台组织自行增加审批节点 | P1 |
| AC-M04-WECOM-BINDING-UI-20261120 | HR/admin进入M06企业微信绑定页签 | 搜索、筛选、绑定、修改或解绑 | 展示系统员工与企业微信员工/部门、状态、时间和操作人；重复企业微信身份拒绝保存，解绑不改历史审批申请人 | P0 |
| AC-M04-WECOM-CONFIG-20261118 | HR仅有绑定权限 | 尝试维护连接/模板接入 | 不获配置权；仅admin配置，模板表单/路线在企业微信维护，无平台引擎/设计器 | P0 |
| AC-M04-WECOM-SCOPE-20261118 | 企业微信存在平台发起与原生发起单 | 同步/查询审批 | 仅纳入平台发起单及其后续变化；同模板/员工不扩大导入范围 | P0 |
| AC-M04-WECOM-READ-20261118 | 申请人、审批人、抄送人、HR、领导及admin访问 | 读取审批 | 本人申请/参与/抄送关系控制，admin全量核查仅指同步集合；HR和领导不因身份/职级自动扩大读取 | P0 |
| AC-M04-WECOM-ACTION-20261118 | 平台已发起并同步的审批单 | 审查同意/驳回/撤回操作分工 | 三项均在企业微信按当前权限及规则执行，平台不提供直接处理操作；admin不代审批，平台只同步真实过程和结果 | P0 |
| AC-M04-WECOM-SYNC-20261118 | 平台发起的审批在企业微信发生处理，或通知重复 | 更新同步记录 | 反映企业微信确认的过程和结果，重复不建单或覆盖历史；不自动生成实际付款/回款事实 | P0 |
| AC-M04-WECOM-REAPPLY-20261118 | 审批被撤回或驳回 | 定义修改/重提流程 | 依选定模板企业微信实际规则；样单明确前不固定原单/新单，不声称已实现修改重提 | P0 |
| AC-M04-BUSINESS-SCOPE-20261123 | 用户从审批中心或来源业务页面发起已确认业务事项 | 选择事项或点击业务操作入口并完成动态表单 | 支持 PM、区域总监和市场副总按各自客户数据范围发起关键人停用，支持有权用户发起任务延期/暂停/取消、已开始项目中止、地市责任交接、销售指标调整；admin 关键人停用走来源模块直接生效；地市交接和指标调整可批量，整批通过后一次生效 | P0 |
| AC-M04-BUSINESS-EFFECT-20261123 | 业务审批处于审批中、通过、驳回或撤回 | 查看业务对象和审批详情 | 审批中原状态不变；通过后执行原业务规则；驳回/撤回保留历史且不改变对象；列表和详情显示企业微信当前处理人姓名与文字流程进度 | P0 |
| AC-M04-WECOM-BOUNDARY-20261118 | 具体企业微信模板、财务字段及剩余产品规则尚未闭环 | 审查本轮交付 | 保持未评审/未研发；Demo表达通用审批与绑定链路，并表达已确认的关键人停用、任务延期/暂停/取消、已开始项目中止、地市交接、销售指标调整七类事项；不自动纳入未确认的财务结算、回款、关账或核算规则 | P0 |

## AC-M04-CITY-LOOP-20261127

当前审批人无旧平台审批处理权限也可只读查看参与单，非参与主管不可读取；模拟企微通过、驳回、撤回及到期生效，地市责任与入口按原规则更新，重复结果不重复迁移，失败保持原责任，平台无审批处理按钮。
