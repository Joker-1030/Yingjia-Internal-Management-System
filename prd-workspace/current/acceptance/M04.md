| AC-F011-22 | 任一业务成功提交审批实例 | 查看审批列表和详情 | 服务端生成唯一 `WF` + 8 位数字，列表首列和详情一致且不可编辑；内部实例 ID 不作为用户流程编号展示 | P0 |
| AC-F011-23 | 审批提交响应超时后使用相同幂等键重试，或多个请求并发提交 | 查询流程 | 相同业务提交仅返回一个实例及原流程编号；不同实例编号不重复，失败取号允许断号 | P0 |
| AC-F011-24 | 审批通过、驳回或业务处理失败 | 查看历史并对允许创建新实例的其他业务动作提交；同时对仍处业务处理失败的同一对象重发停用/恢复 | 已分配流程编号永久保留且不回收；允许的新审批获得新编号；相同幂等提交返回原流程，同对象停用/恢复在受控重试成功前被拒绝且不分配新编号 | P0 |

| AC-F011-26 | 当前流程到达 3 人会签节点 | 两人通过、一人未处理或驳回，并分别查看列表和详情 | 未全员通过时不进入下一节点；成员已通过为绿色、待处理为黄色、驳回为红色，两处一致；任一驳回立即结束为已驳回，并保留三名成员各自状态、时间和意见 | P0 |
| AC-F011-27 | 当前单人审批人查看审批动作并伪造运行中加签请求 | 尝试增加审批人 | 页面不显示动态加签入口；伪造请求被拒绝；流程定义中的预设会签仍按 AC-F011-26 执行 | P0 |

| AC-F011-31 | 总裁、市场副总、区域总监、PM、admin 在各自真实业务范围内发起客户主数据停用/恢复，或 HR 尝试发起 | 查看入口、对象范围和实际审批人 | 前五类角色按对象责任与业务上级路由且不得自审；admin 按公司全局对象责任路由；HR 无入口，直接请求返回 403 且不泄露对象、数量或流程信息 | P0 |

| AC-F011-33 | 当前单人审批人或预设会签成员在处理中停用、账号停用或失去资格 | 查看流程并分别执行合法替换、无候选和恢复后处理 | 流程暂停且节点标记处理人失效，不自动通过或重算；admin 按原节点资格选择替换人并保留完整前后审计，无候选时持续暂停告警且业务对象不变 | P0 |

> Source Governance（2026-08-24，DEC-165）：AC-F011-18/19/21/32 先前将员工停用/恢复作为部门主管审批、计划生效、业务回调和组织链转交的措辞均为 Historical / Replaced Evidence。当前员工停用/恢复由 M06 的 HR/admin 直接生效；M04 只保留员工停用导致既有审批处理人失效后的暂停和受控替换能力。DEC-163 对客户侧对象停用/恢复的发起和路由规则不受影响。稳定 ID、优先级和位置不变。

> Customer Deactivation Retry Current Rule（2026-08-31，DEC-184）：客户对象的已通过-业务处理失败只属于 M04 实例，业务对象保持原状态；admin 受控重试成功前锁定同对象停用/恢复重复发起。

> MVP Action Scope（2026-08-31，DEC-187）：普通审批动作只保留提交、通过、驳回；撤回、普通转交、动态加签、追加抄送和普通管理员代办已从 Current 移除。预设会签、提交时预设抄送、回调重试和失效处理人受控替换继续有效。
