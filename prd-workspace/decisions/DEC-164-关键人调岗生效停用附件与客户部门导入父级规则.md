# DEC-164：关键人调岗生效、停用附件与客户部门导入父级规则

- 日期：2026-08-24
- 状态：已确认
- 决策来源：Product Owner 在 Product Owner Confirmation Mode 中对 Q1、Q2、Q3 的明确回答（Q1=B、Q2=A、Q3=A）
- 背景：关键人调岗的审批通过与计划日期先后关系、客户主数据停用/恢复附件，以及客户部门导入父公司的定位字段仍在 Candidate 或旧完整 PRD 中保留 Clarification / Conflict，阻塞最终产品规则收口。
- 决策：
  1. 关键人调岗实际生效时刻取审批通过时刻与计划调岗日 00:00 的较晚值。审批已经通过但计划调岗日尚未到达时，来源业务关联展示为“已通过待生效”；审批结论仍为“已通过”，原任职继续有效。到达实际生效时刻后，M02 原子结束原任职并建立新任职。该规则确认 DEC-107 和 AC-F007-55，不影响 DEC-159 的员工调岗直接生效规则。
  2. 本期客户主数据停用和恢复均不支持附件。停用申请只保留原因、统一关闭未完成任务规则、级联对象和影响摘要等已确认字段；恢复申请不增加附件。M04 只展示来源业务快照，不复制或新增附件。
  3. M10 V1.5 `客户单位` 工作表必须承载必填“客户公司编码”，`客户部门` 工作表必须包含必填“所属客户公司编码”。系统使用 M09 已有的稳定客户公司编码定位唯一父公司；同批次新客户公司先以该编码建立成功结果，后续客户部门行再引用同一编码。客户公司名称仅用于展示或一致性校验，不得替代稳定编码定位父公司。编码缺失、未知或与名称不一致时，该行失败且不写入客户部门。
- Historical / Replaced：旧 F012 按钮表“申请停用”中的附件字段由本决策替代；旧 F015 `客户部门` 字段表省略“所属客户公司编码”并依赖名称、集团、层级和区划定位父公司的表达由本决策替代；DEC-163 对关键人调岗实际生效时点保留的 Clarification 由本决策关闭。
- 未采用方案：审批通过即忽略未来计划日立即生效；将“已通过待生效”扩张为所有审批的通用实例状态；本期为停用或恢复增加附件；仅按客户公司名称或名称组合定位客户部门父公司。
- 原因：较晚时点规则同时尊重审批结论和计划日期，且已有 DEC-107/AC-F007-55 机械证据；无附件可消除未定义的必填、格式和数量边界；稳定公司编码可避免同名公司或展示字段变化导致父级误匹配。
- 决策人：Product Owner
