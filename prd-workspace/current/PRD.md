- 文档类型：模块化 PRD 人类阅读入口

## 产品介绍

### 产品目标

- 使用稳定对象沉淀客户、关键人、任职、维系动作和历史记录，避免人员变动造成客户资产丢失。
- 以组织员工、系统角色、区域与地市责任形成账号权限和客户责任的产品事实。
- 支持维系任务生成、执行、审批、统计和追溯。
- 以统一项目对象承接培训与 AI 软件项目的立项、交付、资料、评价、责任和商业快照。
- 让列表、搜索、详情、附件、导入和直接访问使用一致的数据范围。
- 为用户可见的表单、状态变化和异常提供明确反馈。

### 使用范围

本期覆盖登录、工作台、客户经营、维系管理、审批、停用记录、消息、组织员工、权限授权、区域地市配置、客户基础配置、数据导入和项目管理。

本期不包含当前商机/合同菜单、完整财务回款、正式讲师管理、项目取消审批或项目经营分析。客户组织路径由显式组织上级决定，业务责任层级及业务责任省/市/区县独立驱动区域、负责人、权限、任务和项目责任；项目管理通过稳定客户公司 ID 和业务责任关联既有事实，不复制客户或区域主数据。未来商机与合同能力上线后按 M11 规则接管项目创建入口。

当前阶段员工停用不选择交接人、不做待办或责任阻断校验；停用与该员工全部未完成 M03 任务取消同次直接生效，员工名下项目保留且不自动取消。完整版本才要求停用时选择交接人、完成适用责任/任务/项目交接并清除阻断，该能力不属于当前版本。

### 用户角色

| 角色 | 主要产品立场 |
| --- | --- |
| 总裁 | 公司全局经营、审批和管理查看 |
| 市场副总 | 全国市场执行、规则查看、专项及区域相关管理 |
| 区域总监 | 本人主管区域的监管、地市责任、省级业务责任客户和项目监管/执行 |
| PM | 本人负责地市的客户、关键人、维系任务和项目执行 |
| HR/人事 | 公司组织、员工、账号和人员异动维护，无客户经营权限 |
| 系统管理员 | 公司全局全部业务和技术维护权限，独占权限授权 |

完整权限和数据范围见 [角色、权限与数据范围](./shared/01-roles-permissions-and-data-scope.md)。

## 核心原则

### 权限边界

- 权限同时受菜单/页面、操作、字段、附件和对象数据范围约束。
- 无权入口不可见，伪造请求不得返回越权对象信息。
- 系统管理员为公司全局全权限账号，但操作必须记录真实管理员身份，不改写业务责任快照。
- 权限授权仅系统管理员可访问；其他角色不能通过兼任获得该入口。

### 数据可见性

- 总裁使用公司全局范围，市场副总使用全国市场范围。
- 区域总监使用本人主管的全部区域中心并集。
- PM 使用当前有效负责地市范围。
- HR/人事使用公司组织范围，不获得客户业务范围。
- 搜索、列表、计数、详情、附件、导入和直接访问使用相同范围。

### 产品事实所有权

- 内部组织与员工事实归 M06。
- 角色模板权限归 M07。
- 区域与地市责任归 M08。
- 客户主数据、显式客户组织上级、客户组织树和业务责任字段配置归 M09；业务责任对应的区域与地市人员关系归 M08。
- 客户资产日常使用归 M02，任务生命周期归 M03，通用审批处理归 M04。
- 关联关系不自动授权跨模块修改。
- 项目、采购包、平台公司、项目资料、满意度和项目责任历史归 M11；客户与地区责任仍归 M09/M02 和 M08。

### 状态与反馈

- 页面必须表达正常、加载、空、错误和无权限等可见结果。
- 操作必须表达提交中、成功、失败、阻断和冲突反馈。
- 页面反馈状态不替代业务对象生命周期，也不新增业务规则。
