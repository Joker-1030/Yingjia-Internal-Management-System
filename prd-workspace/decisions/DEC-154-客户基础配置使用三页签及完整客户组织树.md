## DEC-154：客户基础配置使用三页签及完整客户组织树

- 日期：2026-08-20
- 状态：部分被 DEC-161 替代；三页签和完整客户组织树继续有效，部门/岗位跨公司复用改为严格公司归属
- 背景：DEC-152 写成“两个页签”会遗漏仍需维护的生日/节假日预置规则，同时其树层级缺少客户公司，与已确认的“行业→集团→客户公司→部门→岗位”页面结构和 Demo 不一致；研发还需要明确树节点背后的稳定对象关系，不能只按名称拼树。
- 决策：客户基础配置固定三个页签：职级周期与提醒、客户组织树、生日/节假日规则。客户组织树展示层级固定为“行业→集团→客户公司→客户部门→标准关键人岗位”，右上角新增菜单包含新增行业、集团、客户公司、部门、岗位。客户公司与 F006 复用同一档案；部门和岗位均保存稳定 ID、所属集团及显式适用公司集合，同一对象可在同集团多家公司复用，但系统不得按同名自动合并。新增部门必须确定客户公司，新增岗位必须确定客户公司和部门；部门编码由系统按 `CDEPT` + 8 位全局流水生成，树节点不展示。专项维系和覆盖 KPI 继续只按稳定标准岗位/部门 ID 选择，不允许临时自定义考核口径。仅系统管理员可修改配置，总裁和市场副总只读。
- 未采用方案：继续使用两个页签而把生日/节假日规则隐藏；按“行业→集团→部门→岗位”跳过客户公司；为每个公司复制一套同名部门/岗位且按名称统计；把客户公司在 M09 与 F006 建成两份档案。
- 原因：三个页签完整覆盖当前配置对象；完整树符合评审讲解顺序；稳定 ID 与显式适用关系兼顾公司层级展示、跨公司复用和 KPI 可复算性。
- 决策人：产品经理（2026-08-20 评审意见与 Demo 实现复核）
- 影响范围：F005、F006、F007、F009、F015、GLOSSARY、AC-F005-28、DEC-123、DEC-126、DEC-146、DEC-151、DEC-152、DEC-153
