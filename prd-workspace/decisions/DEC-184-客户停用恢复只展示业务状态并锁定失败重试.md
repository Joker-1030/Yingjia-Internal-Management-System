# DEC-184：客户停用恢复只展示业务状态并锁定失败重试

- 日期：2026-08-31
- 状态：已确认
- 背景：既有规则已区分 M09 业务状态和 M04 审批状态，但业务页面仍展示“停用审批中/恢复审批中”流程投影，容易被理解为对象状态；客户单位表单对不适用地区字段采用隐藏，且没有完整表达未选择责任层级时的禁用规则。
- 决策：
  1. 集团公司、客户公司、关键人和客户部门的业务页面、详情状态标签及业务状态筛选只展示对象当前真实业务状态：`正常` 或 `已停用`。不展示 `停用审批中`、`恢复审批中` 关联流程投影。
  2. 停用/恢复审批及其进度继续在 M04 审批实例和 M05 停用记录/审批历史上下文中展示；可以通过既有详情或审批入口查看，但不得写成对象业务状态、对象状态标签或对象业务状态筛选值。
  3. `已通过-业务处理失败` 只属于 M04 审批实例。停用业务处理失败时对象保持 `正常`；恢复业务处理失败时对象保持 `已停用`。失败不会把对象写成第三种状态。
  4. 业务处理失败继续按既有机制自动重试，持续失败通知 admin 并提供按请求标识的受控重试。受控重试成功前，同一对象不得重新发起停用或恢复，不创建第二审批实例；原流程编号、失败原因、重试进度和历史保留。
  5. 新增客户公司时，业务责任省、市、区县三个字段始终可见。未选择业务责任层级时三个字段全部禁用；省级只启用省并清空、禁用市/区县；市级启用省/市并清空、禁用区县；区县级启用省/市/区县。上级字段变化时按既有联动清空下级；禁用字段不提交。
- 替代关系：替代 DEC-163、M05/M09 和 FLOW-04 中将 `停用审批中/恢复审批中` 作为业务对象关联展示投影的当前表达；它们作为 Historical / Replaced Evidence 保留。DEC-163 关于业务处理失败保持原状态、通知 admin、幂等重试且不重复审批的规则继续有效并由本决策补充同对象重发门禁。
- 未改变：停用/恢复对象范围、发起权限、审批路由、自动重试次数、admin 收件人、M05 历史审计、对象稳定 ID、组织上级规则和业务责任解析规则。
- 决策人：Product Owner
- 影响范围：M04、M05、M09、Acceptance、Flow、Shared、Prototype
