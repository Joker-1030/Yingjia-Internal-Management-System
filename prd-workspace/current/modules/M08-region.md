## Quick Overview

- **模块解决什么：** 把 M06 已成立的区域中心组织事实配置为业务区域，并维护省份、驻地和唯一地市负责人关系。
- **谁主要使用：** 市场副总维护区域省份/驻地；区域总监维护本人主管区域并处理地市责任；PM 从独立“地市管理”查看本人区域/地市并发起交接；admin 全局维护；总裁只读。
- **主要页面：** 区域中心与地市配置、PM 地市管理、地市负责人配置、分配/直接调整弹窗、地市交接表单与详情、负责客户 Drawer。
- **核心操作：** 编辑区域映射、分配未负责城市、直接调整负责人、由原 PM 发起交接、区域总监审批、查看负责客户。
- **关键边界：** M06 拥有内部组织员工，M02 拥有客户经营，M04 拥有审批容器，M09 拥有客户主数据，M10 只做受控批量录入，M11 拥有项目；M08 只拥有区域映射和地市责任，并在责任交接时要求 M11 同步迁移项目负责人。
- **未决治理：** 正式行政区划数据源及少量展示细节仍待澄清；DEC-165 已同步员工多部门、主管自动角色和停用责任清空边界。

## 1. 模块目标

M08 维护从内部区域中心到客户责任和数据范围之间的业务配置，分为两个相互关联但边界不同的功能：

1. **F003 区域中心配置**：读取 M06 已成立的区域中心部门事实，维护区域与省份、驻地的结构化映射及配置质量。
2. **F004 地市责任**：维护每个业务城市当前唯一地市负责人，支持未分配城市的分配、已有负责人的直接调整，以及原 PM 发起的计划交接。

区域映射和地市责任变化向下游提供客户责任、数据范围、任务/KPI 责任和工作台展示所需的当前事实。M08 拥有区域映射、地市负责人关系、分配、直接调整、交接业务规则和区域配置异常，不拥有：

- 内部组织部门、部门主管、员工部门或员工系统角色定义；
- 客户和关键人的经营与日常维护；
- 通用审批实例和节点容器；
- 任务、覆盖 KPI 或维系记录生命周期；
- 项目、项目阶段、项目资料或项目商业事实；
- 消息中心的已读/未读生命周期。

## 4. 页面与入口

### 4.1 区域中心与地市配置入口

入口名称固定为“区域中心与地市配置”，仅总裁、市场副总、区域总监和系统管理员按既有范围可见；PM 不显示该菜单，直接访问返回 403 且不返回区域列表、数量或配置详情。页面采用左侧区域列表、右侧区域详情与地市责任的主从结构：

- 左侧区域列表支持区域名称、部门编码、区域总监和省份独立筛选，按部门排序、名称、稳定 ID 依次排序，不分页；每个区域直接展示“待配置/已配置/配置异常”状态，异常区域不得继续显示为“已配置”。
- 右侧随当前区域切换，展示区域基础信息、配置摘要、区域映射和地市负责人配置。
- 用户无可见区域时展示对应 Empty；筛选无结果与尚无同步区域使用不同空态。

### 4.2 PM 地市管理入口

入口名称固定为“地市管理”，仅当前有效角色集合包含 PM 的账号可见；其他角色不显示该菜单，直接访问返回 403。该固定角色边界不通过 M07 模板向非 PM 放宽。

- 页面按本人当前所属区域分别展示区域基础信息和本人责任，不把多个区域合并为一个对象；仅有一个区域时直接展示该区域。
- 区域基础信息只读展示区域名称、部门编码、区域总监、关联省份、驻地和配置状态；不展示编辑区域、分配、直接调整、按 PM 查看或其他后台配置入口。
- 每个区域的摘要只统计本人当前负责地市数、相关客户数和关键人数；不得通过摘要、筛选、空态、数量或直接访问泄露区域内其他 PM 或其他地市。
- 地市列表只展示本人当前有效负责地市，字段为省份、城市、负责起始时间、客户数、关键人数、当前交接状态和操作。
- 本人是当前原负责人且不存在进行中交接时显示“发起交接”；已发起申请只查看进度，不提供撤回。交接表单、审批人、计划生效、失败保护和历史规则继续使用现行 F004 规则。
- 本人无所属区域时显示“当前账号暂无所属区域”；有所属区域但无当前负责地市时显示“当前暂无负责地市”。两种空态不展示其他区域或待分配地市。

### 4.3 区域中心配置

区域中心配置展示区域名称、部门编码、区域总监、关联省份、驻地、配置状态、配置异常原因、备注和时间。配置状态为“配置异常”时，左侧区域列表直接显示“配置异常”；用户点击该区域后，右侧区域详情只展示当前异常原因，不展示异常影响、影响数量或处理入口。异常原因只使用四类已确认表达：“区域中心主管缺失或停用”、“主管不具备区域总监角色”、“关联省份或驻地失效”和“有客户的地市缺少有效 PM”。第四类只适用于原有有效 PM 责任关系因员工停用、离职、失去 PM 角色或脱离负责范围而失效；从未分配 PM 的地市不触发区域异常。详情顶部展示关联省份、驻地、已分配地市、地市客户、关键人五项摘要。

Demo 的异常测试数据必须作为左侧区域中心列表中的实际区域记录呈现，并可点击进入右侧详情；不得另建“配置异常测试数据”表格。测试数据应覆盖四类异常，同时保留正常区域场景。异常测试数据必须使用不改变既有区域映射、客户归属或当前/历史责任事实的独立样例；不得拆分原江苏区域的江苏/安徽映射，不得改写合肥等已有客户地市的负责人来制造异常。

五项摘要在宽屏按五列展示，中等宽度按 3+2 排布，移动宽度按 2/1 列排布，不出现悬空分隔、重叠或横向溢出。编辑区域弹窗只保留关联省份、驻地、备注等可编辑字段，不展示“映射影响预览”“新增省份”“移除省份”“移除影响”等内联预览字段。

### 4.4 地市负责人配置

“按地市”和“按 PM”是同一个地市负责人配置页面的两种视图，共享同一负责人关系、筛选、权限和校验：

- **按地市**：查看省份、城市、当前负责人、工号、部门、负责起始时间、状态和操作。
- **按 PM**：查看 PM 姓名、工号、所属区域、负责城市数、城市标签、待审批交接数和操作。
- 按地市视图支持省份、城市、PM 姓名、PM 工号和分配状态独立筛选；按 PM 视图支持 PM 姓名和 PM 工号独立筛选。各项只匹配自身字段。
- 从未分配 PM 的“待分配”地市可按既有权限执行分配。原责任失效后的“待分配”地市不得进入初次分配候选；区域总监/admin 可复用既有直接调整建立新责任，必须关联并保留原失效责任历史，不得覆盖原 PM、原生效时间或历史。

### 4.5 分配弹窗

用于把未分配城市分配给本区域合格 PM。省份多选后联动未分配城市，用户选择 1-50 个城市、目标 PM 和备注，查看确认信息后二次确认。

### 4.6 直接调整弹窗

用于即时更换已有负责人的城市。弹窗展示原负责人、目标 PM、原因，以及客户、关键人、未完成任务、覆盖 KPI、当前审批和权限影响摘要；影响可计算后才允许二次确认。

### 4.7 地市交接表单与详情

原 PM 从本人当前负责城市发起交接，填写目标 PM、城市、计划生效日期和原因，查看影响摘要后提交。详情展示申请、审批、计划生效、业务迁移和失败结果；不设置目标 PM 接收节点。

### 4.8 负责客户 Drawer

区域总监或 admin 可从地市或 PM 责任关系查看负责客户。下钻最多进入客户单位详情，客户单位详情不继续进入关键人详情，并提供返回客户经营的提示入口。

## 5. 用户操作

| 操作 | 执行角色与前置条件 | 确认与生效 | 成功结果 | 失败反馈 |
| --- | --- | --- | --- | --- |
| 切换区域 | 当前用户选择有权区域 | 无提交确认；右侧立即切换当前上下文 | 区域详情、摘要和责任视图同步刷新 | 其他区域不出现；越权直接访问返回 403 且不泄露名称 |
| 查看地市管理 | PM 进入专属菜单 | 无提交确认；按本人当前所属区域分别加载 | 展示区域基础信息、本人责任摘要和本人当前负责地市 | 无所属区域或无负责地市分别显示明确空态；不返回其他 PM、其他地市或后台配置 |
| 编辑区域映射 | admin 或市场副总；区域来自 M06 且用户具有写权限 | 编辑省份/驻地后执行省份唯一性、业务引用和字段有效性校验；保存时二次确认，通过后整体生效 | 显示“配置保存成功”，更新映射时间、配置状态、责任和范围结果并记录真实操作者 | 省份冲突、业务引用阻断、驻地失效或并发变化时不能保存；任一步失败保持全部原值 |
| 分配 | admin 或本人主管区域的区域总监；城市未分配，目标 PM 当前合格 | 选择省份、1-50 个城市和目标 PM后二次确认；立即生效 | 每个城市形成一条当前责任，生成已通过流程记录和审计，显示“分配成功” | 城市越权、已被分配、候选失效或并发变化时拒绝，原责任不变 |
| 直接调整 | admin 或本人主管区域的区域总监；城市已有负责人，目标 PM 当前合格 | 查看影响摘要、填写目标 PM/原因并二次确认；一次性迁移后立即生效 | 负责人切换，形成已通过记录，通知原任/新任，历史责任不改写，显示“直接调整成功” | 影响无法计算、候选失效、负责人变化或迁移失败时保持原值，不显示部分成功 |
| 发起交接 | 仅当前原 PM；选择本人当前负责且同属本人责任的 1-50 个城市 | 填写目标 PM、计划日期、原因并确认提交；进入所属区域总监审批 | 形成待审批交接，生效前原 PM 继续负责 | 非原 PM、城市越权、候选失效或影响无法计算时不提交 |
| 审批交接 | 交接所属区域总监；申请仍有效且本人是当前审批人 | 通过或驳回；通过后立即生效或等待计划日 | 驳回保持原责任；通过且到期后一次性迁移并更新流程结果 | 负责人并发变化或生效失败时不基于旧责任迁移，显示状态冲突或业务处理失败 |
| 查看负责客户 | 区域总监或 admin 在有权地市/PM 责任关系中查看 | 无业务提交 | 打开负责客户 Drawer，可继续到客户单位详情 | 加载失败保留当前区域/责任上下文；无权客户不返回信息 |

责任迁移成功后若消息发送失败，不回滚已经生效的责任关系；系统保留迁移结果并进入消息重试。

### 7.1 页面状态

### 7.2 区域配置状态

| 状态 | 产品含义 |
| --- | --- |
| 待配置 | M06 已同步合格区域中心，但 M08 区域映射从未完成 |
| 已配置 | 当前区域映射满足已确认配置条件 |
| 配置异常 | 已配置区域出现以下任一条件：区域中心主管缺失或停用；主管不具备区域总监角色；关联省份或驻地失效；原有 PM 责任关系失效后有客户的地市缺少有效 PM。左侧区域列表显示“配置异常”，右侧详情只展示具体原因 |

配置状态实时计算且不可手工修改。首次尚未完成关联省份或驻地配置属于“待配置”；已完成配置后关联省份或驻地失效属于“配置异常”。城市从未分配 PM 时只把该地市标为“待分配”，区域仍按其他区域配置条件判定，不因该城市有客户而升级为“配置异常”。只有原有有效 PM 责任关系后来失效并导致有客户地市缺少有效 PM 时，才触发第四类区域配置异常。异常修复后 5 分钟内按当前事实恢复已配置，并保留异常开始、恢复时间和影响记录。

### 7.3 地市责任展示状态

| 状态 | 产品含义 |
| --- | --- |
| 待分配 | 城市当前没有有效 PM，明确显示“待分配”；有客户时整行使用黄色警示底色或等价黄色警示样式，无客户时不使用黄色行底色 |
| 已分配 | 城市当前存在唯一有效 PM |

这些是责任页面的展示和筛选状态，不是审批生命周期。地市负责人配置不存在“交接中”状态；存在未结束交接时，交接生效前原 PM 仍是当前有效负责人，因此该地市继续显示“已分配”。状态单元格只显示责任状态，不在状态下方展示流程编号；交接进度可在查看交接等独立流程入口中展示。

“从未分配”和“原责任失效”不能仅凭当前 `PM` 是否为空判断。M08 必须保留并使用责任历史或已有生效事实区分两者：从未分配不触发第四类区域配置异常；原有有效责任后来失效且该地市有客户时，才触发“有客户的地市缺少有效 PM”。两者在当前无有效 PM 时均显示“待分配”，黄色行底色只由当前客户数是否大于 0 决定。

原责任失效后的“待分配”不得进入批量初次分配候选，也不得由提交逻辑覆盖原 PM、原生效时间和责任历史。区域总监/admin 可使用现有直接调整能力选择合格目标 PM，经影响确认后建立新责任，并把新责任与原失效责任历史关联；不新增责任恢复中心、修复模块或新审批。从未分配的“待分配”继续使用既有分配流程。

| 状态 | 产品含义 |
| --- | --- |
| 待审批 | 原 PM 已提交，等待所属区域总监处理 |
| 已通过待生效 | 审批通过，但计划生效日期未到；原责任继续有效 |
| 已通过 | 责任迁移已经成功；分配和直接调整也形成已通过记录但不建立审批节点 |
| 已驳回 | 审批人驳回，原责任不变 |
| 业务处理失败 | 审批结论或直接动作记录保留，但迁移失败，业务对象保持生效前结果并进入受控重试 |

### 7.5 操作结果

- **配置保存成功**：区域映射、更新时间、配置状态和下游解析使用新结果。
- **分配成功**：城市形成唯一当前负责人和已通过记录。
- **直接调整成功**：负责人及关联责任一次性迁移，历史责任不改写。
- **失败**：显示具体阻断或失败原因，保留原配置/责任，不展示部分成功。
- **冲突**：负责人或配置已被其他动作改变时要求刷新，不基于旧数据继续提交。

### 7.6 错误反馈

- 省份已被其他区域占用：禁选并指出冲突区域；伪造提交同样拒绝，不写入关系。
- 驻地失效：所选城市已不在当前标准城市候选中时提示重新选择；驻地是否属于关联省份不参与校验。
- 移除省份仍存在业务引用：展示客户和地市责任明细并阻止保存。
- 影响摘要无法计算：不进入确认或提交，保留当前输入并提供重试。
- PM 候选失效：候选不出现；伪造或过期提交被阻止，原责任不变。
- 负责人并发变化：显示状态/版本冲突并要求刷新，不重复迁移。
- 区域映射或责任迁移任一步失败：整体保持原值，不显示部分成功。
- 消息失败：责任迁移不回滚，保留成功结果并进入消息重试。
- 越权请求：返回 403，不泄露区域、责任、候选或对象是否存在。

## 8. 用户流程

### 8.1 区域映射保存

1. admin 或市场副总选择有权区域，编辑关联省份和驻地；驻地从标准城市中独立选择。
2. 编辑弹窗不展示映射影响预览、新增/移除省份或移除影响字段。
3. 系统校验省份唯一性、待移除省份的当前业务引用、驻地自身有效性和并发版本。
4. 无阻断时，用户在保存动作中完成二次确认；确认不重新引入内联影响预览字段。
5. 全部成功后一次性保存映射，并按客户公司的业务责任层级及业务责任省/市/区县重算负责人和数据范围；任一步失败则完整保留原映射。

### 8.2 分配

1. admin 或本人主管区域的区域总监选择一个或多个省份。
2. 系统联动展示未分配城市，用户选择 1-50 个城市和一个合格目标 PM。
3. 用户填写可选备注并二次确认。
4. 系统重新校验范围、城市未分配和 PM 资格。
5. 全部成功后立即生效，形成已通过流程记录和审计。

### 8.3 直接调整

1. admin 或本人主管区域的区域总监选择已有负责人的城市。
2. 系统展示客户、关键人、任务、KPI、审批和权限影响摘要。
3. 用户选择合格目标 PM、填写原因并二次确认。
4. 系统重新校验当前负责人和目标资格，一次性迁移责任。
5. 成功后形成已通过记录并通知原任/新任；失败时原责任完整保留。

### 8.4 地市交接

1. 当前原 PM 选择本人负责的 1-50 个城市，填写目标 PM、计划日期和原因。
2. 系统计算影响，校验通过后提交给所属区域总监审批。
3. 驳回时原责任不变；本期不提供撤回。
4. 审批通过但日期未到时进入已通过待生效，原 PM 继续负责。
5. 到达计划日后重新校验当前负责人和目标资格，一次性迁移客户、关键人、未完成任务、覆盖 KPI、当前审批、数据范围，以及 M11 中该地区全部`已立项`、`进行中`、`已交付`、`已完成`项目的当前负责人；`已取消`和`已中止`项目不迁移。
6. 迁移成功进入已通过；迁移失败进入业务处理失败并保留生效前责任。

### 8.5 FLOW-06 / FLOW-10 治理说明

- [FLOW-06 M08 city handover](../user-flows/FLOW-06-M08-city-handover.md) 是机械迁移的历史冲突证据，仍写“PM 或区域总监提交”和“admin 提交并二次确认”；其原文保持不变，不得据此恢复区域总监/admin 发起普通交接。
- [FLOW-10 M08 city handover approval](../user-flows/FLOW-10-M08-city-handover-approval.md) 与当前 DEC-143 路径一致：仅原负责 PM 发起，所属区域总监审批，区域总监/admin 即时换人使用直接调整。
- [FLOW-16 M11 project responsibility handover](../user-flows/FLOW-16-M11-project-responsibility-handover.md) 是当前项目责任联动分支：地区责任和全部适用项目负责人必须同一次生效，任一项目迁移失败时整体阻断。
- FLOW-06 已标为 Historical / Replaced Evidence，FLOW-10 为 Current Product Flow；两份图正文均保留，不再形成平级 Current 冲突。
