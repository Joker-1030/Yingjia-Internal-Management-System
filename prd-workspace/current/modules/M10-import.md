## Quick Overview

- **模块解决什么：** 通过模板、预校验、确认和结果报告完成受控批量录入。
- **谁使用：** admin 处理公司范围导入；PM 处理本人范围关键人和初始化项目导入；区域总监长期处理本人省级业务责任客户关键人，并在初始化期处理本人负责省级业务责任客户项目。
- **主要页面：** 批次列表、上传与预校验、批次详情、确认导入、导入中、结果报告。
- **关键操作：** 下载模板、上传、查看问题、确认导入、查询进度、查看或下载报告。
- **最大边界：** M10 不建立第二套主数据规则，也不覆盖既有关键人任职或地市负责人。
- **治理边界：** 单工作表 5,000 行、单行原子、允许部分成功和 POS+8 系统全局唯一已确认；DEC-164 已确认 V1.5 客户部门必填所属客户公司编码。

## 1. 模块目标

M10 是受控批量录入流程。系统管理员通过它批量建立客户主数据和初始化项目；PM 通过它批量新增本人当前负责市级/区县级业务责任客户下的关键人，并在初始化期导入本人项目；区域总监可长期导入本人负责省级业务责任客户关键人，并在初始化期导入本人负责省级业务责任客户项目。所有正式写入都必须经过当前账号模板、文件选择、上传、预校验、问题查看和用户确认，任何角色不得跳过预校验直接写入正式对象。

M10 只拥有模板、文件、批次、预校验、确认、异步执行和结果报告的产品事实，不重新定义被导入对象：

模板中的字典和下拉只降低填写错误，不替代上传时对最新权限、对象状态、层级、引用和唯一性的检查。导入命中存量关键人、客户关系或地市负责人时按本模块的重复/冲突规则跳过或阻断，不覆盖既有事实。

| 可导入行 | 格式、权限、引用和唯一性均通过，可在确认后写入的行 | M10 拥有结果分类 | 写入同一正式业务对象 |
| 疑似重复行 | 命中存量唯一字段或关键人手机号/微信号、默认跳过的行 | M10 拥有结果分类和报告 | 唯一性事实由 M02/M09 提供，不自动覆盖 |
| 阻断错误行 | 存在必填、格式、枚举、范围、父引用或文件结构错误的行 | M10 拥有结果分类和修复反馈 | 具体错误规则来自对象拥有模块 |

## 4. 页面与入口

数据导入入口按以下区域组织：

1. **批次列表**：展示当前账号有权批次、筛选、分页、空态、加载失败、详情和结果报告入口。
2. **模板下载与文件选择**：按角色提供模板；用户一次选择一个 `.xlsx` 并发起上传。
3. **上传与预校验**：展示文件/结构检查和逐行校验过程；尚未写入正式对象。
4. **批次详情 Drawer**：按工作表展示行数、可导入、疑似重复、阻断错误和警告，提供逐行问题明细。
5. **确认导入容器**：展示各工作表统计和预计新增对象数，用户勾选确认后提交。
6. **导入中**：展示异步等待状态；前端等待超时后可离开或刷新，后台继续处理。
7. **结果报告**：展示批次结果、分工作表结果、成功率和报告查看/下载入口。

### 批次列表

默认展示当前账号有权查看的全部批次，按“创建时间倒序 + 批次稳定 ID 倒序”排列。列表字段：

- 批次编号；
- 文件名；
- 模板类型和模板版本；
- 创建人和创建时间；
- 导入范围；
- 可导入数、疑似重复数、阻断错误数和警告数；
- 批次状态和完成时间；
- 结果报告和可用操作。

每页默认 20 条，可切换 20/50/100 条。

### 筛选

| 字段 | 控件/候选 | 必填 | 默认值 | 查询规则 |
| --- | --- | --- | --- | --- |
| 批次编号 | 单行输入，0-100 字 | 否 | 空 | 去首尾空格；只按批次编号前缀匹配 |
| 文件名 | 单行输入，0-100 字 | 否 | 空 | 去首尾空格；只按完整文件名模糊匹配，不搜索工作表内容 |
| 模板类型 | 全部/客户主数据全量模板/关键人模板/项目模板 | 否 | 全部 | 按批次上传时保存的模板类型过滤；项目模板只在初始化期提供新下载和上传 |
| 批次状态 | 多选 | 否 | 全部 | 同一状态维度多选取并集；已关闭可与其他状态同时选择 |
| 创建人 | 可搜索员工单选 | 否 | 空 | 仅 admin 显示；支持姓名/工号，停用员工保留“已停用”标记 |
| 创建开始日期 | 日期 | 否 | 空 | 可单独填写；按 `Asia/Shanghai` 自然日包含所选日期 |
| 创建结束日期 | 日期 | 否 | 空 | 可单独填写；同时填写时不得早于创建开始日期，按 `Asia/Shanghai` 自然日包含所选日期 |
| 异常情况 | 全部/含阻断错误/含疑似重复/含警告/无异常 | 否 | 全部 | “含”表示对应数量大于 0；无异常表示三类数量均为 0 |

点击“查询”后返回第 1 页；同一维度按字段规则计算，不同维度取交集。批次编号或文件名输入框回车均可查询。“重置”恢复当前账号授权范围内全部批次，不扩大权限。筛选只保留在当前页面会话，从详情或报告返回时恢复；退出登录、关闭页面或切换账号后不保留。

### 空态和失败

- 当前范围从未创建批次：显示“暂无导入批次”，并按权限提供下载模板或上传入口。
- 有历史批次但筛选无结果：显示“未找到符合条件的批次”和“重置筛选”，不显示上传引导。
- 列表读取超时：保留当前筛选并提供“重试”。
- 单个筛选候选加载失败：只禁用对应筛选并提示失败，列表仍可按其他条件查询。
- 批次详情或结果报告加载失败：保留当前批次上下文，提示重试；不得显示不完整结果为成功。

## 6. 字段与业务规则

### 文件与模板

#### 已确认文件规则

- 每次只选择和上传 1 个 `.xlsx`。
- MIME 为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
- 单文件最大 20 MB。
- 不接收 `.xls`、`.csv`、宏工作簿、加密/密码保护工作簿、外部链接、嵌入对象或公式单元格。
- 所有隐藏非空行仍参与校验；空行不计业务行；禁止使用合并单元格。
- 文件级限制不满足时批次级拒绝并指出原因，不解析或写入任何业务数据。

#### 行数限制 Current Rule

单工作表最多 5,000 条业务行，空行不计：5,000 行允许，5,001 行及以上在预校验前批次级拒绝，并明确指出超限工作表、当前业务行数和 5,000 行上限。旧 F015 的 10,000/工作表和 50,000/工作簿作为 `Historical / Replaced Evidence` 保留，不再与 Current Rule 并列。

#### 模板类型与版本

| 模板 | 角色 | 当前版本 | 业务工作表 |
| --- | --- | --- | --- |
| 客户主数据全量模板 | admin | `CUSTOMER_MASTER_IMPORT_V1_5` | 集团公司、地市负责人、客户单位、客户部门、关键人 |
| 关键人模板 | admin、区域总监、PM | `CONTACT_IMPORT_V1_5` | 关键人 |
| 项目模板 | admin、区域总监、PM | 初始化期当前版本 | 项目基本信息 |

- 全量模板五个业务工作表必须全部存在；没有数据的工作表保留表头。
- PM 和区域总监的关键人模板不得增加集团公司、客户单位、地市负责人或客户部门工作表来绕过权限。
- 未知业务工作表或未知附加列只生成警告，绝不作为业务字段写入。
- V1.5 的模板类型、版本、下载员工 ID 和下载时间写入只读模板信息。
- PM 和区域总监只能上传本人下载的当前关键人模板，并分别按本人市级/区县级业务责任客户和本人省级业务责任客户范围重新鉴权；admin 可上传任一当前版本模板并按公司全局权限检查。
- 旧 V1.4 不进入确认导入。

#### 字典和联动

模板包含受保护字典工作表：

- 固定下拉：组织上级类型、业务责任层级、性别、是否采购决策人、职级。
- 账号范围下拉：行业、集团、同集团客户公司、标准业务责任省/市/区县、PM 工号、客户公司、该公司所属客户部门编码、该部门所属标准关键人岗位编码。
- 联动路径：省 -> 市 -> 区县，以及客户公司 -> 客户部门 -> 标准岗位。

PM 模板只提供本人当前有权的市级/区县级业务责任客户公司及其严格归属部门、岗位候选；区域总监模板只提供本人负责的省级业务责任客户及其严格归属候选；admin 模板提供公司全局当前正常候选。切换上级后下级候选收敛，手工绕过下拉填写不存在或不匹配的路径时整行报错。旧模板中的候选不获得持续有效资格，上传时重新鉴权和检查状态。

#### V1.5 客户部门父级定位 Current Rule

DEC-164 已确认：`客户单位` 工作表必须包含必填“客户公司编码”，`客户部门` 工作表必须包含必填“所属客户公司编码”，使用 M09 已有稳定客户公司编码定位存量或同批次唯一父公司。客户单位名称仅用于展示或一致性校验，不得替代编码定位。旧 F015 字段表省略该列并依赖名称组合定位的表达保留为 Historical / Replaced Evidence。

### 工作表字段

表头必须与最终治理后的当前模板完全匹配；带 `*` 的字段必填。未知附加列忽略并警告，不写入正式对象。

#### 工作表 `集团公司`

| 字段 | 格式 | 必填 | 默认/只读 | 当前规则 |
| --- | --- | --- | --- | --- |
| 行号 | 正整数 | 是 | 无 | 工作表内唯一，只用于错误定位 |
| 集团名称 | 2-100 字 | 是 | 无 | 使用当前客户主数据唯一规则 |
| 行业名称 | 2-50 字 | 是 | 无 | 必须匹配正常行业；停用行业报错 |
| 统一社会信用代码 | 18 位 | 否 | 无 | 填写时在全客户组织中唯一 |

集团编号不作为导入模板输入列。集团公司行成功创建同一 M09 集团对象时，系统按 M09 规则生成 `CG` + 8 位全局流水编号；匹配存量集团时沿用原编号。失败行不成立集团对象且不显示成功编号，已经成功分配的编号不因批次关闭、对象停用、恢复或后续状态变化而回收。结果报告返回该正式集团编号。

M10 不在此重新定义行业、集团字段、编号或停用规则；导入时复用 M09 当前产品事实。

#### 工作表 `地市负责人`

| 字段 | 格式 | 必填 | 默认/只读 | 当前规则 |
| --- | --- | --- | --- | --- |
| 行号 | 正整数 | 是 | 无 | 工作表内唯一 |
| 省份 | 标准区划精简名 | 是 | 无 | 必须属于导入人范围 |
| 城市 | 标准区划精简名 | 是 | 无 | 必须属于所填省份及同一区域 |
| PM 工号 | 2-32 字 | 是 | 无 | 必须匹配该区域当前在职且具有 PM 角色的员工 |

该工作表只允许 admin 为尚无负责人的城市初配 PM。已存在负责人时不覆盖，提示进入 M08 的 F004 责任变更流程；其他可处理行不因该行受影响。

#### 工作表 `客户单位`

| 字段 | 格式 | 必填 | 默认/只读 | 当前规则 |
| --- | --- | --- | --- | --- |
| 行号 | 正整数 | 是 | 无 | 工作表内唯一 |
| 客户公司编码 | 稳定客户公司编码 | 是 | 无 | 匹配存量公司时必须一致；新公司在本工作簿内唯一，供后续客户部门行引用 |
| 集团名称 | 2-100 字 | 是 | 无 | 匹配存量或本批次可成功集团 |
| 组织上级类型 | 集团公司/客户公司 | 是 | 无 | 不接收其他值；只决定组织上级引用的解析方式 |
| 上级客户公司编码 | 稳定客户公司编码 | 条件必填 | 无 | 组织上级类型为客户公司时必填并解析同集团正常公司或同批次前置成功公司；类型为集团公司时必须为空并以本行所属集团为上级；两种情况都保存解析后的显式上级稳定 ID |
| 单位名称 | 2-100 字 | 是 | 无 | 使用当前组合唯一规则 |
| 业务责任层级 | 省级/市级/区县级 | 是 | 无 | 不接收其他值；不决定组织上级 |
| 业务责任省份 | 标准区划精简名 | 是 | 无 | 必填，不表示公司所在地 |
| 业务责任城市 | 标准区划精简名 | 条件必填 | 无 | 市级/区县级必填，省级必须空 |
| 业务责任区县 | 标准区划精简名 | 条件必填 | 无 | 区县级必填，省级/市级必须空 |
| 统一社会信用代码 | 18 位 | 否 | 无 | 填写时在全客户组织中唯一 |

客户公司的所属集团、显式组织上级、业务责任、唯一性和防环规则由 M09/M02 当前事实定义；M10 只校验并写入同一正式对象。上级客户公司编码跨集团、指向自身或后代、无法唯一解析或形成环时整行失败；业务责任无法唯一解析区域/负责人时同样失败，两类校验互不替代。

#### 工作表 `客户部门`

| 字段 | 格式 | 必填 | 默认/只读 | 当前规则 |
| --- | --- | --- | --- | --- |
| 行号 | 正整数 | 是 | 无 | 工作表内唯一 |
| 所属客户公司编码 | 稳定客户公司编码 | 是 | 无 | 使用 M09 已有公司编码唯一定位存量或本批次已成功客户公司；缺失或未知时该行失败 |
| 客户单位名称 | 2-100 字 | 否 | 可由编码对应字典展示 | 仅用于展示或一致性校验，不参与父公司定位；填写时必须与编码一致 |
| 部门临时标识 | 1-32 位字母或数字 | 是 | 仅批次使用 | 本工作表内唯一，只用于行间引用，不写入正式部门编码 |
| 部门名称 | 2-100 字 | 是 | 无 | 同一客户公司、同一上级部门下唯一 |
| 上级部门编码/临时标识 | 2-32 字 | 否 | 空表示客户公司直属部门 | 匹配存量 `CDEPT` 编码或本批次前置行临时标识；上级必须属于同一客户公司 |

部门正式编码不是导入输入。成功时生成 `CDEPT` + 8 位流水；失败或回滚时已经取用的编号不回收。客户部门必须严格属于一个客户公司，下级部门与上级部门属于同一公司。所属客户公司编码是定位父公司的唯一业务键；同批次新客户公司先按 `客户单位` 工作表中的客户公司编码建立成功结果，再由客户部门行引用。客户单位名称不能单独定位或覆盖编码结果。

#### 工作表 `关键人`

| 字段 | 格式 | 必填 | 默认/只读 | 当前规则 |
| --- | --- | --- | --- | --- |
| 行号 | 正整数 | 是 | 无 | 工作表内唯一 |
| 集团名称 | 2-100 字 | 是 | 无 | 用于客户公司精确定位 |
| 客户单位名称 | 2-100 字 | 是 | 无 | 与客户公司编码共同校验目标客户 |
| 业务责任层级 | 省级/市级/区县级 | 是 | 无 | 必须与目标客户当前业务责任一致 |
| 业务责任省份 | 标准区划精简名 | 是 | 无 | 必须与目标客户当前业务责任一致 |

| 邮箱 | 最长 254 字 | 否 | 无 | 标准邮箱格式 |
| 性别 | 男/女/未说明 | 否 | 空值按“未说明” | 只接收固定枚举 |

| 是否采购决策人 | 是/否 | 是 | 无 | 不接收 1/0 等自由值 |
| 部门编码/临时标识 | 1-32 字 | 是 | 无 | 匹配目标客户公司的正常部门或本批次同公司可成功临时标识 |

关键人工作表只新增关键人及首条任职。手机号或微信号命中存量身份时整行归为疑似重复并默认跳过，即使客户公司、部门或岗位不同，也不得通过导入更新任职或自动发起调岗。历史维系记录没有模板工作表，附加同名内容不得写入。

标准岗位 `POS` + 8 编码由系统生成并在系统内全局唯一、不可编辑、不回收。M10 只引用当前稳定岗位候选，不允许按客户公司或集团重复生成相同编码。

### 预校验与问题明细

#### 预校验层次

1. **文件级**：格式、MIME、大小、数量、宏、加密、外链、嵌入、公式、合并单元格和单工作表 5,000 行上限。
2. **模板结构级**：模板类型、版本、下载身份、必需工作表、表头和未知工作表。
3. **行字段级**：必填、长度、格式、枚举、默认值和业务责任区划深度。
4. **权限与状态级**：上传时重新检查导入人范围、PM 资格、对象状态和候选有效性。
5. **唯一与引用级**：工作簿内唯一、存量重复、公司/部门/岗位严格路径及父子引用。
6. **依赖级**：父行失败时依赖子行标记“上游行不可用”，不创建孤立数据。

预校验阶段不写入正式对象。工作簿内部重复唯一键是阻断错误，不允许依赖行顺序覆盖；命中存量唯一字段为疑似重复并默认跳过。

#### 行结果分类

| 分类 | 定义 | 用户处理 | 是否写入 |
| --- | --- | --- | --- |
| 可导入 | 格式、权限、引用、状态和唯一性均通过 | 可在待确认批次中勾选确认 | 确认后写入 |
| 疑似重复 | 命中存量唯一字段或关键人手机号/微信号 | 默认跳过，报告给出依据 | 否 |
| 阻断错误 | 必填、格式、枚举、范围、父引用或结构错误 | 修正文件后新建批次 | 否 |
| 警告 | 未知附加列或可安全采用默认值 | 用户确认后继续 | 按正常行处理 |

#### 问题明细

批次详情 Drawer 按工作表展示行数及四类结果数量。每条行级问题至少展示：

- 工作表；
- 行号；
- 字段；
- 错误码；
- 原因；
- 修复建议。

文件或结构级失败作为批次级问题展示，不伪造业务行号，也不进入待确认。越权行只返回“超出当前导入范围”和本行区划，不返回冲突客户、关键人、负责人、数量或是否存在。疑似重复展示有权范围内的判定依据，但不自动合并或覆盖。警告明确指出未知内容未写入。

## 7. 状态与反馈

### 页面状态

| 页面状态 | 用户看到什么 | 可执行操作 |
| --- | --- | --- |
| Loading | 批次列表、筛选候选、详情、预校验、导入结果或报告正在加载 | 等待；超时后按所在区域重试 |
| Empty | “暂无导入批次”或“未找到符合条件的批次” | 按空态下载/上传，或重置筛选 |
| Error | 列表、候选、文件、预校验、写入或报告的具体失败提示 | 保留当前上下文，修正、重新上传或重试查询 |
| PermissionDenied | 无入口或直接访问 403 | 不返回模板、批次或对象信息 |

### 批次状态

| 批次状态 | 产品含义 | 当前允许动作 |
| --- | --- | --- |
| 已上传 | 文件已形成批次，尚未完成预校验 | 查看当前处理信息 |
| 预校验中 | 正在检查文件、结构和业务行 | 等待或离开后再查看 |
| 待确认 | 预校验结果可供用户确认 | 查看详情、确认导入 |
| 导入中 | 已确认，正在异步写入 | 查看进度、刷新查询同一结果 |
| 部分成功 | 只有部分可处理源业务行最终写入成功 | 查看/下载结果报告 |
| 全部成功 | 当前确认范围内的可导入源业务行全部成功 | 查看/下载结果报告 |
| 失败 | 文件/结构拒绝或其他当前资料定义的失败结果；完整进入条件尚未穷举 | 查看失败原因；修正后新建批次 |
| 已关闭 | 批次被关闭并保留历史、报告和审计 | 查询历史；需要继续时新建批次 |

上表按当前资料表达用户可见含义，不补充未定义的完整状态转移。只有待确认可发起正式导入；已关闭的具体来源状态尚未在旧 PRD 中穷举，Candidate 不自行扩展。

### 行结果

可导入、疑似重复、阻断错误、警告是预校验/行结果分类，不是批次生命周期状态。

### 操作反馈

- 文件限制失败：批次级拒绝，指出原因，不解析或写入业务数据。
- 模板结构失败：列出缺失工作表、版本或表头，不进入待确认。
- 保存/正式写入失败：结果报告保留成功、跳过和失败明细，不把未知结果显示为成功。
- 范围或对象状态变化：对应行拒绝并建议重新下载模板，不泄露越权对象。
- 已有地市负责人：不覆盖，提示进入 F004。
- 重复命中：默认跳过，不自动合并，不提供覆盖开关。
- 前端超时：后台继续；刷新返回同一批次结果，不重复创建。
- 报告无权：返回 403，不泄露文件名、状态、数量或是否存在。
- 批次关闭：保留报告和审计；继续处理需重新上传创建新批次。

### 结果报告

结果报告为受批次权限控制的 `.xlsx`，包括：

- 全批次汇总；
- 每个原工作表的可导入行、成功行、失败行和成功率；
- 每个源业务行的行号、处理结果、对象 ID、正式业务编号、错误字段、错误码、原因和修复建议；成功创建或匹配集团时正式业务编号为 M09 同一集团编号；
- 成功、跳过和失败明细。

结果报告的查看和下载每次按当前批次权限重新鉴权。admin 可访问公司有权批次报告；区域总监可访问本区域项目导入报告，关键人导入报告仅限本人创建；PM 只可访问本人有权批次报告。失权或请求他人报告时返回 403，不泄露报告或批次信息。

客户档案导入成功率按源业务行计算：

- 分子：本批次最终成功写入的源业务行数。
- 分母：用户确认导入的全部可导入源业务行数。
- admin 汇总集团公司、地市负责人、客户单位、客户部门和关键人五张工作表；PM 和区域总监的关键人导入只汇总关键人工作表。项目导入按项目基本信息工作表独立统计。
- 一行即使建立身份、任职、责任等多个关联对象，成功时仍只计 1 行；任一必需写入失败，该行不计成功。
- 表头、说明、空行、未知工作表、疑似重复、预校验阻断和未确认行不进入分母。
- 全批次汇总等于各工作表数量之和；百分比保留 1 位，分母为 0 显示 `--`。

## 8. 用户流程

### 确认导入与异步执行

#### 确认导入

只有状态为“待确认”的批次可发起正式导入。确认容器按工作表展示：

- 可导入行数；
- 疑似重复行数；
- 阻断错误行数；
- 警告行数；
- 预计新增对象数。

用户必须勾选确认后提交。重复提交使用同一批次 ID 和幂等标识返回同一最终结果，不重复创建客户、关键人或责任关系。

导入成功后的 M03 任务生成规则：

- 成功写入且适用当前 M03 规则的正式对象，在该行导入成功后 5 分钟内生成适用任务。
- 失败行不生成 M03 任务。
- 任务生成失败不推翻或回滚已经成功的导入行；批次和行结果继续保持导入成功。
- 任务生成重试使用同一业务唯一关系，不得重复生成父任务或任务执行记录。

#### 处理顺序

admin 全量模板按以下依赖顺序处理：

`集团公司 -> 地市负责人分配 -> 客户单位 -> 客户部门 -> 关键人`

PM 和区域总监的关键人模板只处理关键人。地市负责人先处理，以便市级/区县级业务责任客户建立时解析当前负责人。已存在负责人且模板值不同的城市不得覆盖，作为冲突行跳过并提示进入 F004；其余行按当前规则继续处理。

#### 异步执行与超时

- 用户确认后批次进入“导入中”，预校验结果不等同于正式对象已写入。
- 性能验收只适用于满足单工作表 5,000 行上限的合法文件；旧“50,000 行 P95”不构成允许导入 50,000 行的产品阈值。
- 超过前端等待时间时后台继续运行，并通过 P01 系统内消息通知。
- 用户刷新、重新进入批次或再次确认时，系统查询并展示同一批次结果，不重复导入。
- 本期不提供取消、暂停或“重新写入当前批次”按钮；继续处理已关闭或需修正的内容必须重新上传并创建新批次。

#### 部分成功与单行原子 Current Rule

以下当前事实必须保留：

- 正确行可以写入，错误和重复行不写入。
- 混合存在可导入、重复和错误行时，只写可导入行，批次可以是“部分成功”（AC-F015-12）。
- 确认可导入行在正式处理时部分失败，成功率和报告按逐行最终结果计算（AC-F015-21）。

“原子”固定以单行作为最小产品处理单位。每一业务行独立成功或失败，某行失败不回滚其他成功行；100 行可形成 80 行成功和 20 行失败。单行对应业务对象的必需产品事实必须一起成功，否则该行失败，不产生半成品；本规则不定义数据库事务模型。

[FLOW-07 M10 import](../user-flows/FLOW-07-M10-import.md) 已新增 Current 分支表达 5,000 行上限、单行原子和部分成功；原机械迁移块保留为 Historical / Replaced Evidence，不再把“按工作表顺序原子写入”解释为工作表整体原子。

### 项目初始化导入

- M10 新增`项目`导入类型，只在项目初始化阶段开放；初始化结束后隐藏项目模板并拒绝新上传，历史批次和报告长期保留。
- admin 导入公司范围项目；区域总监只导入本人作为负责人范围内的省级业务责任客户项目；PM 只导入本人负责市级/区县级业务责任客户项目。
- 项目模板只承载项目基本信息：项目名称、项目类型、客户编号/客户公司、开始/结束时间、项目确认天数、资源与合作字段、历史主阶段、原创建时间及 M11 要求的相关基础字段。系统计算天数不作为模板输入。项目资料、满意度等在导入后单独维护。
- 系统按导入时客户的业务责任层级及业务责任省/市/区县匹配项目负责人；客户组织上级不参与。模板不得自由填写其他负责人。无法匹配有效负责人或超出导入人范围时，该行阻断，admin 也不能绕过。
- 可导入历史主阶段仅为`进行中`、`已交付`、`已完成`；`已取消`项目不得导入。阶段与项目类型、开始/结束时间不一致时阻断；填写`已完成`但缺少当前完成条件时，按`已交付`建立并显示资料/评价待办。
- 每行独立成功或失败；成功项目按原创建年份生成新的`XM`年度编号，原历史编号不作为当前项目编号；失败行不取号。
- 命中当前占用项目名称或既有项目时跳过，不覆盖；已取消项目名称可按 M11 复用。项目导入不提供批量编辑或批量取消。
- 导入时根据开始/结束时间计算并写入只读系统计算天数，模板中的项目确认天数写入 M11 同名字段；培训项目按项目确认天数计算项目金额和结账金额并保存商业快照。当前初始化项目导入暂不校验讲师排期；该例外不放宽 M11 人工维护时的排期冲突阻断。
- 区域总监导入本人负责省级业务责任客户关键人是长期独立能力，不随项目初始化导入关闭；不得扩大到市级/区县级业务责任客户关键人。

## 9. 权限边界

权限边界同时适用于菜单、模板字段、字典候选、批次列表、数量、详情、原文件和结果报告：

- admin 可查看公司全部批次；区域总监可查看本人主管区域内项目导入批次，但关键人批次仅限本人创建；PM 只可查看本人创建的批次。
- PM 和区域总监不显示“创建人”筛选；admin 可按曾创建有权批次的员工筛选。
- PM A 下载的关键人模板由 PM B 上传时，批次级拒绝且不解析业务行；admin 上传当前版本模板不受 PM 下载身份限制，但仍按公司全局权限检查。
- 模板下载后发生地市责任变化、对象停用、员工停用或账号失权时，上传预校验按当时最新事实拒绝受影响行，并建议重新下载模板。
- 无权直接访问批次或报告时返回 403，不返回文件名、模板字段、状态、数量、对象候选或对象是否存在。
