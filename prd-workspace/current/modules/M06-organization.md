## Quick Overview

- **模块解决什么：** 维护内部部门、员工、账号和停用/恢复关系。
- **谁使用：** HR/人事、系统管理员负责维护并可查看员工详情，业务角色按公司组织范围只读查看员工目录。
- **主要页面：** 组织树、员工列表、员工详情 Drawer、变动记录。
- **关键操作：** 维护部门和主管、新增或编辑员工的多部门/人工角色关系、直接停用或恢复员工。
- **最大边界：** 本期不使用员工调岗/移动容器；部门、人工角色和停用/恢复均由 HR/人事或 admin 在 M06 直接维护，不创建 M04 审批实例、WF 编号、待办或抄送。
- **未决治理：** 无影响本次规则执行的产品歧义；历史相反证据按 DEC-165/182 保留。

## 1. 模块目标

- 维护英嘉内部部门、部门主管和员工档案。
- 维护员工与系统角色的关联、员工账号及账号可用状态。
- 以普通员工编辑维护一个或多个平级部门和人工系统角色，并直接处理员工停用、恢复。
- 让用户查找组织成员并理解当前组织责任关系。
- 作为员工多部门、系统角色和部门主管关系的组织事实来源，并向 M08 提供区域责任所需的组织、人员资格和有效性事实；区域责任关系本身由 M08 拥有。

## 2. 用户角色

部门主管关系是 M06 的组织事实，不由“市场副总”“区域总监”或“PM”等系统角色天然授予。每个部门同一时点最多一名主管，同一员工可以主管多个部门；字段隐私上限不因主管关系改变。

| 主体 | 可查看 | 可编辑/发起 | 可审批 | 不可操作 |
| --- | --- | --- | --- | --- |
| 总裁 | 公司组织、部门主管、在职员工目录及本人相关变动记录 | 无 M06 维护入口 | 无员工停用/恢复审批 | 不显示或打开员工详情；不可新增/编辑/停用/恢复员工，不可重置他人密码 |
| 市场副总 | 公司组织、部门主管、在职员工目录及本人相关变动记录 | 无 M06 维护入口 | 无员工停用/恢复审批 | 不显示或打开员工详情；系统角色不直接产生组织维护权 |
| 区域总监 | 公司组织、部门主管、在职员工目录及本人相关变动记录 | 无 M06 维护入口 | 无员工停用/恢复审批 | 不显示或打开员工详情；区域范围由 M06 主管关系与 M08 区域/地市责任共同提供，M06 不维护地市责任 |
| PM | 公司组织、部门主管、在职员工目录及本人相关变动记录 | 无 M06 维护入口 | 无员工停用/恢复审批 | 不显示或打开员工详情；当前负责地市由 M08 拥有；无人事维护入口 |
| HR/人事 | 公司完整组织、在职/停用员工目录与员工详情、部门/人员变动；本人既有审批关系 | 维护部门/主管；新增/编辑员工部门与人工角色；直接停用/恢复 | 无员工停用/恢复审批 | 不可重置他人密码；无客户业务、M07 或 M08 写权限 |
| 系统管理员 | 公司全局组织、全部员工目录与员工详情、账号状态、他人最近登录及全部变动信息 | 维护部门/主管；新增/编辑员工部门与人工角色；直接停用/恢复；重置他人密码 | 仅处理 M04 明确路由给本人的节点，并可受控替换失效处理人；不普通代办 | 不伪装业务角色，不以 M06 维护区域/地市或客户责任 |
| 当前部门主管 | 与本人组织关系相关的部门和员工只读信息 | 无组织或员工档案维护权，除非另有 HR/人事或 admin 身份 | 不因主管关系获得员工停用/恢复审批 | 主管关系不赋予客户经营或权限授权能力 |

所有已登录业务角色可按公司组织范围只读查看在职员工目录，但只有 HR/人事和系统管理员可进入员工详情。非 HR/admin 不显示“详情”按钮，直接地址、伪造事件或等价详情请求统一拒绝且不得返回员工详情数据；该限制是 M06 固定能力上限，M07 角色模板不能放宽。停用员工仅 HR/人事和系统管理员可见。员工手机号对所有角色统一脱敏；AC-F001-34 的旧明文口径已完成 Historical / Replaced 治理。账号状态与他人最近登录仅 admin 可见；HR 可在员工本人首次主动修改前受控查看当前系统生成初始密码。

## 3. 核心对象

| 对象 | 产品含义 |
| --- | --- |
| 内部部门 | 公司内部组织层级的唯一事实，可标记为区域中心 |
| 部门主管 | 部门唯一当前主管关系；可自动补齐主管的部门成员关系，并驱动区域中心主管身份 |
| 员工 | 内部人员唯一档案及其一个或多个平级所属部门、系统角色和员工状态 |
| 员工账号 | 以员工手机号登录的账号及其启用/停用状态、密码事件和登录摘要 |
| 系统角色关联 | 员工直接关联的 1-5 个人工业务角色及带来源的自动区域总监角色，不经过内部岗位映射 |
| 人员/组织变动记录 | 部门、主管、员工多部门/角色编辑及员工停用/恢复的直接生效审计 |

## 4. 页面与入口

### 一级页签

页面固定为两个一级页签，不把两部分内容堆叠在同一长页面：

1. **组织与员工详情**：左侧为组织树，右侧在员工列表上方展示当前部门详情。
2. **人员/组织变动记录**：独立展示部门和人员变动、员工直接停用/恢复及其他直接生效审计；一级页签只显示名称，不展示数字角标。

### 组织与员工详情

- 左侧为组织树；右侧在员工列表上方展示当前部门详情。树节点不展示部门编码，编码只在部门详情中只读展示。
- 选择父部门时，右侧员工列表按部门成员关系包含该部门及其全部正常下级部门的员工；同一员工属于多个所选部门时按部门分别展示，不做跨部门去重。
- HR/人事和系统管理员在部门节点右侧可见“管理”快捷入口；点击打开该部门编辑弹窗。其他角色不显示该入口。
- 右侧包括筛选区、员工列表、分页和“新增员工”入口；“详情”按钮及维护入口仅 HR/人事和系统管理员可见。
- 部门详情概要固定展示当前主管；无主管时显示“待设置”。员工列表在主管所负责部门的员工姓名旁显示“主管”标签，不设置独立主管列。

筛选项：

- 姓名：只匹配员工姓名。
- 工号：只匹配员工工号。
- 手机号后四位：只匹配员工手机号后四位，结果继续使用统一脱敏规则。
- 部门。
- 系统角色。
- 员工状态。
- 账号状态：仅系统管理员可见。

员工列表列：姓名、工号、当前行部门路径、全部所属部门、系统角色、脱敏手机号、员工状态、账号状态（仅系统管理员）、最近登录时间（仅系统管理员）和操作。默认仅显示在职员工；停用员工及其状态切换入口只对 HR/人事和系统管理员显示。

### 员工详情 Drawer

员工详情 Drawer 仅 HR/人事和系统管理员可见、可打开。其他角色的员工列表不显示“详情”按钮；直接地址、伪造事件或等价详情请求返回无权限且不返回目标员工详情。具备权限的用户点击员工详情后打开右侧 Drawer，固定包含两个页签：

1. **基础信息**：姓名、工号、统一脱敏手机号、脱敏邮箱、入职日期、所属部门、各部门主管、本人主管的全部部门、系统角色和员工状态。“所属部门”按完整组织路径展示一个或多个平级部门，不在字段标签中展示“全部”“路径”或“平级”等内部规则说明。员工详情不再展示“区域身份”，也不新增“部门角色”等组合字段。系统角色不附加“自动/人工”来源标签，也不展示后台维护规则说明。账号状态与最近登录仅系统管理员可见。员工本人首次主动修改密码前，HR/人事可受控查看当前系统生成初始密码和“无有效期、不强制修改”说明；本人修改后只显示“密码已由本人修改”，任何角色均不得查看本人修改后的密码。
2. **角色与账号记录**：按发生时间倒序展示账号创建及初始角色关联、部门或系统角色变化、账号启用/停用、系统管理员重置密码和本人修改密码。每条只展示事件类型、发生时间、操作人、变更前后或结果；角色名称不附加“自动/人工”来源标注，不展示后台自动维护说明；时间线只读，不提供操作入口。

角色与账号记录不得展示密码明文、密码哈希、验证码、失败次数、会话令牌、设备/IP、完整手机号或人员异动的完整业务详情；非系统管理员不返回最近登录、锁定和会话运行信息。

### 人员/组织变动记录

- 默认按申请/操作时间倒序，每页 20 条，可选 20/50/100 条。
- 列包括：申请/操作时间、对象、类型、变更前后、发起/操作人、生效方式、流程编号、状态、计划生效日期、实际生效时间和操作。
- 员工停用/恢复展示直接生效操作详情，不进入审批详情。
- 部门新增、移动、改名、主管变更和停用展示直接生效审计。
- 员工部门/人工角色编辑展示直接生效审计，生效方式为“HR/admin 直接生效”，流程编号显示 `—`。

### Drawer 与弹窗类型

| 类型 | 用途 | 主要反馈 |
| --- | --- | --- |
| 员工详情 Drawer | 查看基础信息、角色与账号记录 | 按字段权限展示，敏感信息不返回 |
| 本人信息 Drawer | 只读查看姓名、工号、脱敏手机号、邮箱、部门路径、系统角色、员工状态和本人最近登录 | 只提供“修改密码”，不提供组织、角色或账号编辑 |
| 部门新增/编辑弹窗 | 新增、改名、换上级、补设/更换主管、区域中心标记和部门停用 | 保存后更新组织树；部门表单不展示责任影响摘要 |
| 员工新增/编辑弹窗 | 新增或更正员工基础档案，多选一个或多个正常部门并维护 1-5 个人工系统角色 | 字段错误就地提示；合法保存直接生效并记录变更 |
| 停用/恢复弹窗 | HR/人事或 admin 填写 5-500 字原因并确认 | 停用前校验未完成项目已通过既有地区责任调整完成迁移；通过后切换员工/账号状态并取消全部未完成任务；恢复时直接启用；不创建员工停用审批或交接模块 |
| 重置密码成功弹窗 | 仅系统管理员重置他人密码 | 点击入口即完成重置并展示新系统密码；右下角“复制并关闭”复制密码后关闭弹窗 |
| 修改密码弹窗 | 员工本人修改密码 | 校验失败保留当前有效密码；成功后撤销其他会话 |
| 二次确认弹窗 | 区域中心主管变更等仍需确认的组织责任变化 | 明确变更影响，确认成功或返回阻断项；普通员工编辑和停用/恢复不使用 |
| 阻断/错误反馈 | 展示区域责任、版本冲突、责任接收、权限或加载问题 | 告知用户需处理的对象或刷新重试，不产生部分结果 |

## 5. 用户操作

### 部门维护

1. HR/人事或系统管理员从组织树新增部门，或从节点“管理”入口编辑现有部门。
2. 系统校验名称、上级、主管资格、区域中心关联和停用条件。
3. 保存成功后更新组织树和部门详情；新部门显示系统生成编码。
4. 部门表单不展示影响摘要。区域中心主管变更属于责任变化，单独展示影响并要求二次确认。
5. 取消区域中心或停用受阻时，页面列出需要先处理的省份、地市、客户、任务或审批关系。

### 员工新增与编辑

1. HR/人事或系统管理员打开新增或编辑员工弹窗，填写员工字段，多选一个或多个正常部门，并选择 1-5 个人工系统角色。
2. 系统校验手机号、邮箱、日期、部门和系统角色；错误显示在对应字段并聚焦首个错误。
3. 新增成功后，员工、启用账号和角色关联同时可用，并展示初始登录信息。
4. 编辑档案可更正姓名、新手机号、邮箱、入职日期、部门集合和人工系统角色；原手机号只显示脱敏值。部门关系平级，不设主部门；员工状态只通过停用/恢复入口改变。
5. 两名维护人员修改同一员工时，后提交者看到版本冲突和最新修改摘要，刷新后再操作。

### 员工部门与角色编辑

1. 仅 HR/人事或系统管理员可在普通员工编辑中维护；其他角色无入口，直接请求返回 403 且不泄露员工信息。
2. 部门支持多选且至少一个，所有部门关系平级，不设主部门、不设数量上限；用户选择 1-5 个可维护系统角色，系统维护的角色合并显示但不附加“自动/人工”来源标签或后台规则说明。
3. 保存时校验员工版本、正常部门和人工角色；失败时全部保持原值并显示字段或版本错误。
4. 合法保存后部门集合、人工角色及权限立即生效并写入前后值、操作人和时间；不使用独立调岗/移动容器，不要求责任交接、影响摘要或二次确认。
5. 部门范围列表按成员关系逐部门展示，同一员工可出现多次，但始终引用同一员工 ID 和账号。
6. 普通编辑不创建 M04 审批实例、WF 编号、审批待办或抄送。

### 员工停用

1. HR/人事或系统管理员选择在职且非内置 admin 的员工，填写 5-500 字原因并确认。
2. 停用立即生效：员工变为停用、账号变为停用、当前会话失效；不创建审批、WF 编号、待办或抄送。
3. 系统检查该员工名下是否仍有未完成项目。存在时阻止停用，并提示先通过 M08 既有地区责任直接调整完成适用地区责任和项目负责人迁移；M06 不新增交接人字段、交接模块或项目迁移审批。
4. 确认不存在未迁移未完成项目后，系统清空该员工的部门主管、区域/地市和客户当前责任关系；员工、账号和会话停用同次生效。
5. 员工停用与该员工全部未完成 M03 任务取消同次生效；取消保留任务编号、原执行人、停用原因、实际操作人、时间和员工停用关联，不伪记完成、不物理删除、不逐条建立任务取消审批。
6. 已迁移项目及其他历史项目保留，项目主阶段和并行待办不因停用自动取消。部门成员关系、系统角色和当前审批节点保留原员工，审批不自动改派。
7. 既有审批处理人因停用失效时，M04 按“处理人失效”规则暂停并由 admin 后续受控替换。员工、账号、责任清空和全部未完成任务取消任一步失败时整体不生效，不留下部分结果。

### 员工恢复

1. HR/人事或系统管理员选择停用员工，填写 5-500 字恢复原因并确认。
2. 恢复立即将员工改为在职、账号改为启用，并继续使用停用前有效密码；不创建审批、WF 编号、待办或抄送。
3. 恢复保留停用时未删除的部门成员关系、系统角色和审批节点；停用时已取消的任务不恢复，已清空或已迁移的主管、区域/地市、客户责任及项目负责人关系不自动恢复，项目阶段不改变。
4. 系统只按恢复后的当前责任生成未来适用任务，不补造停用期间已经过去的事件任务。

### 系统管理员重置他人密码

1. 只有系统管理员可对非内置 admin 员工使用“重置密码”；HR/人事及其他业务角色无入口，越权请求返回 403。
2. 系统管理员点击“重置密码”后，系统立即生成符合统一复杂度的新密码并完成重置，不再展示确认表单，不要求手工输入新密码或填写重置原因。
3. 重置完成后直接打开“密码重置成功”弹窗，展示本次已重置的密码及“立即生效、无有效期、不强制下次登录修改”说明。
4. 弹窗右下角仅提供“复制并关闭”；复制成功后关闭弹窗。复制失败时保留弹窗和密码，并提示重试。
5. 新密码立即替代旧密码并撤销目标账号全部既有会话。审计只记录目标员工、操作人、时间和成功结果，不保存或展示密码明文。

## 6. 字段与业务规则

### 内部部门字段

| 字段 | 展示/录入 | 必填 | 默认或候选 | 产品规则 |
| --- | --- | --- | --- | --- |
| 部门 ID | 系统字段，不在编辑中展示 | 是 | 自动生成 UUID | 作为稳定部门标识 |
| 部门名称 | 单行输入，2-100 字 | 是 | 无 | 同一上级下大小写不敏感唯一 |
| 部门编码 | 详情只读 | 是 | 保存后生成 `DEPT` + 8 位公司流水号 | 全公司永久唯一，创建后不可修改；编号不重置、不回收；生成失败时不创建部门；组织树不展示 |
| 上级部门 | 树形单选 | 条件必填 | 正常部门，默认当前选中节点 | 公司根节点无上级；不能选择自身或自己的下级 |
| 部门主管 | 员工搜索单选 | 否 | 任意在职且非系统内置员工；默认待设置 | 每部门只有 1 名当前主管；候选可在部门外，保存后自动增加该部门成员关系；更换/解除主管不自动移除成员关系 |
| 排序 | 数字步进，1-9999 | 是 | 100 | 相同排序值按名称排序 |
| 是否区域中心 | 否/是 | 是 | 否 | 可在新增和编辑时选择；主管为空时只保存在 M06，补设合格主管后才同步 M08 |
| 状态 | 只读/状态操作 | 是 | 正常 | 正常/已停用；普通部门无在职员工且无正常下级部门时才可停用 |

普通部门和区域中心均允许“主管待设置”。该状态不产生员工停用/恢复审批路由；员工停用/恢复由 HR/admin 直接操作。

区域中心继续使用当前部门 ID、名称和编码，不生成第二套区域对象标识。区域中心主管可从任意在职非内置员工中选择；保存时自动增加其区域中心部门成员关系，并在缺失时自动增加带来源的区域总监角色，不因人工角色已达 5 个而阻断且不重复。补设成功后该部门同步到 M08 并进入“区域待配置”。同一员工可以主管多个区域中心，M08 按当前主管关系计算所辖区域范围并集。

取消区域中心标记或停用区域中心前，必须已经移除全部关联省份、当前地市负责人、省级业务责任客户责任、未结束区域审批和专项待办；存在阻断项时页面列出明细并引导用户先到 M08 处理。不能通过停用部门绕过责任迁移。

变更区域中心主管时，页面展示省级业务责任客户、关键人和账号范围影响。HR/人事或系统管理员确认后直接生效；旧主管不再主管任何区域中心时，只移除由主管关系自动增加的区域总监角色，人工原有角色保留；更换主管不自动改派既有任务或审批节点。

本期不维护独立的内部岗位库，也不存在岗位到系统角色的映射。员工必须直接关联 1-5 个人工系统角色；区域中心主管可另有带来源的自动区域总监角色，不存在“岗位未映射角色”的账号状态。

新增员工时，员工、唯一账号和系统角色关联作为一个完整结果创建。成功弹窗一次性展示姓名、脱敏登录手机号、系统生成初始密码和固定说明“本期不设有效期，不强制首次修改，请通过安全渠道交付”，并提供“复制全部”；复制内容中的登录手机号同样脱敏。员工本人首次主动修改前，HR/人事可在详情受控查看当前系统生成初始密码；本人修改后只显示“密码已由本人修改”，且任何角色均不能查看本人修改后的密码。

本人修改密码需要当前密码、新密码和确认新密码；密码长度为 12-64 位，并遵守统一密码复杂度与最近 5 次不复用规则。只有系统管理员可重置他人密码；点击入口后系统直接生成新密码并完成重置，不要求手工输入密码或填写原因。成功弹窗展示新密码，右下角“复制并关闭”复制成功后关闭；新密码立即替代旧密码、无有效期且不强制下次登录修改。HR/人事不显示重置入口，无权操作反馈为 403。

### 区域组织与责任边界

- 内部部门及员工-部门成员关系是区域中心和员工组织归属的唯一事实源；一名员工可关联多个平级部门。
- 标记为区域中心但主管待设置的部门只存在于 M06，不进入 M08 待配置列表。
- 区域中心补设主管时，M06 自动补齐部门成员关系和缺失的带来源区域总监角色，再向 M08 输出部门、主管、组织归属和人员有效性事实，M08 建立或更新区域配置。
- 区域中心或其下级部门内，系统角色包含 PM 的在职员工可作为 M08 地市负责人候选；候选资格不等于已经承担地市责任。
- M08 是区域、行政归属、地市负责人、PM 当前责任、责任历史和区域范围的唯一 Owner。M06 不创建、重算或改写这些责任关系。
- 员工详情分别展示所属部门和系统角色，不再组合生成“区域身份”或“部门角色”。员工部门或人工角色经普通编辑改变时，M06 输出组织、角色、有效性和候选资格变化；员工停用前通过 M08 既有直接调整完成适用项目迁移，停用时再清空其剩余区域/地市当前责任。M08 仍拥有责任关系与历史，M06 不建立第二套责任事实。

## 7. 状态与反馈

### 页面状态

| 状态 | 用户看到什么 | 用户可以做什么 | 系统反馈 |
| --- | --- | --- | --- |
| Loading | 组织树、列表、详情或记录处于加载中 | 等待或离开当前视图 | 加载完成后展示内容；不改变筛选和已确认数据 |
| Empty | 当前组织、列表或记录没有数据 | 有维护权限时使用新增入口；无维护权限时继续查看其他范围 | 展示对应空状态，不伪造示例数据 |
| Empty Result | 已设置筛选条件但没有匹配员工 | 调整或清空筛选 | 保留筛选条件并明确无匹配结果 |
| Error | 当前区域加载或提交失败 | 重试、刷新或按阻断提示处理 | 显示可理解错误，不展示部分成功结果 |
| PermissionDenied | 用户无页面、操作或字段权限 | 返回可访问页面 | 无权入口不显示；直接访问或伪造操作返回 403，不泄露对象信息 |
| Submitting | 保存、确认或局部操作正在提交 | 等待结果，不重复提交 | 禁用重复提交；不提前改变对象状态 |
| Success | 当前维护或局部操作成功 | 查看结果或继续操作 | 展示成功反馈和最新事实；不是员工或账号状态 |

| 对象 | 状态 | 说明 |
| --- | --- | --- |
| 部门 | 正常 | 可作为员工所属部门和正常组织树节点 |
| 部门 | 已停用 | 不再作为新增归属候选；历史关系保留 |
| 部门主管 | 待设置 | 普通部门或区域中心允许暂未设置主管；审批上溯，区域中心不同步 M08 |

### 员工状态

| 状态 | 说明 |
| --- | --- |
| 在职 | 可按当前部门、角色和责任使用系统 |
| 停用 | 禁止登录且不能成为新的责任候选；历史标识、部门、角色和记录保留 |

员工只有“在职/停用”两种状态。本期没有离职、重新入职或离职审批入口。

### 账号状态

| 状态 | 说明 |
| --- | --- |
| 启用 | 在满足登录校验和会话规则时可登录 |
| 停用 | 不可登录；员工停用或系统管理员单独停用账号时进入该状态 |

临时登录锁定是安全条件，不是账号状态；账号状态只有系统管理员可见。

### 员工维护操作结果

普通员工编辑及停用/恢复均不建立独立业务状态机或关联审批展示。`Submitting` 只是页面提交阶段；成功后变动记录显示“已生效”，失败时对象保持原值并显示明确操作失败。不存在待审批、已驳回、已通过待生效或已通过-业务处理失败等员工操作状态，也不创建 M04 审批实例。

上述审批实例与节点状态由 M04 拥有；M06 只展示审批结论及其对员工、账号和组织事实的生效结果。“已生效”是 M06 业务操作结果，不是 M04 审批实例状态。

### 错误与操作反馈

- 字段错误：在对应字段下显示明确原因，焦点落到首个错误，不创建或修改对象。
- 字段或版本失败：普通员工编辑保持全部原值，并定位非法部门、人工角色或版本冲突。
- 版本冲突：显示他人最新修改时间和最新摘要，要求刷新；错误码为 `VERSION-409-002`。
- 区域中心阻断：列出仍关联的省份、地市、客户、任务或审批，并提示先到 M08 处理。
- 直接生效失败：员工部门/角色编辑、区域中心主管变更、员工停用/恢复等操作保持原值，不显示部分成功记录，也不创建审批失败状态。
- 权限错误：无权入口不可见；直接访问或伪造请求返回 403，数据不变且不泄露对象信息。
- 退出登录：二次确认后结束当前会话，清除当前客户选择和本地敏感信息，返回登录页。
