# DEC-179：集团编号由系统生成并永久保留

- 日期：2026-08-28
- 状态：已确认
- 背景：Current PRD 已定义集团稳定 ID、集团名称、统一社会信用代码及行业归属，但缺少面向用户展示、检索和跨模块引用的集团编号。Prototype 曾自行按集团数组位置展示临时“集团编码”，该表达没有正式产品依据，也不能保证编号稳定。
- 决策：
  1. 正式字段名称为“集团编号”，与内部集团稳定 ID、集团名称和统一社会信用代码分离。
  2. 集团编号格式为 `CG` + 8 位全局流水，在集团创建成功时由系统生成；新增表单只读显示“保存后自动生成”，用户和导入模板均不能填写或修改。
  3. 集团编号在系统内全局唯一。集团创建失败时对象不成立且不显示成功编号；重复请求返回原集团和原编号，不产生第二个集团或重复编号。
  4. 已成功分配的集团编号永久不回收，不因集团停用、恢复、批次关闭或后续状态变化而改变或复用。
  5. M09 拥有集团编号事实并在集团详情提供独立编号筛选；M02 只读展示并独立筛选同一编号；M05 在停用/恢复快照和历史中保留同一编号；M10 不接收集团编号输入，成功创建或匹配集团后在结果报告返回正式编号。
- 未采用方案：使用集团名称、统一社会信用代码或内部稳定 ID 代替集团编号；由用户或导入模板填写编号；按页面顺序或数组位置临时计算编号；停用或失败后回收已经成功分配的编号。
- 原因：为集团公司建立稳定、可见、可检索且跨模块一致的业务标识，避免名称变化、信用代码缺失或 Demo 临时序号造成错误引用。
- 决策人：Product Owner
- 影响范围：M02、M05、M09、M10、Acceptance、Glossary、Prototype
