## Quick Overview

- **模块解决什么：** 统一记录客户侧对象为什么停用、影响什么、何时直接生效，以及按什么条件恢复。
- **谁主要使用：** 仅唯一内置 `admin` 可查看和操作客户侧停用/恢复；总裁、市场副总、区域总监、PM、HR/人事及其他角色均无入口和操作权限。
- **主要对象：** 集团公司、客户公司、关键人和客户部门的停用/恢复操作、对象快照、影响摘要、处理记录和生效历史。
- **核心流程：** admin 从 M02/M09 发起停用，完成影响校验和二次确认后直接原子生效；再从 M05 详情按同样方式恢复。
- **关键边界：** M02/M09 拥有业务对象，M05 拥有客户侧停用/恢复影响、直接生效结果与历史，M04 不承载该流程，M06 拥有员工和账号停用。
- **治理边界：** 客户部门唯一归属和停用时统一关闭未完成任务继续按既有规则；DEC-198 替代多角色发起与审批链，DEC-164 明确停用/恢复无附件。

## 1. 模块目标

M05 为集团公司、客户公司、关键人和客户部门提供统一的停用/恢复记录与历史入口，使 admin 能够回答：谁操作、为什么停用、影响哪些下级/任职/任务/KPI/责任、何时生效、当前能否恢复，以及恢复后哪些历史和责任保持不变。

M05 负责：

- 客户侧停用/恢复操作、处理记录和生效历史；
- 停用前对象快照、影响确认、级联或替代处理表达；
- 停用与恢复的原子生效结果、失败结果和时间线；
- 已停用对象的恢复入口；
- 按对象权限展示停用/恢复历史和审计记录。

M05 不拥有：

- 集团公司、客户公司和客户部门主数据；
- 关键人身份、当前任职和经营行为；
- 审批实例、审批节点和通用审批动作；客户侧停用/恢复不产生这些对象；
- 员工、账号和内部部门；
- 任务、专项或覆盖 KPI 的生命周期。

| 角色 | 可见范围 | 操作入口 | 直接处理能力 | 关键边界 |
| --- | --- | --- | --- | --- |
| 总裁 | 无 M05 权限 | 无 | 无 | 无菜单、对象入口或历史查看；直接请求返回 403 |
| 市场副总 | 无 M05 权限 | 无 | 无 | 无菜单、对象入口或历史查看；直接请求返回 403 |
| 区域总监 | 无 M05 权限 | 无 | 无 | 不因客户责任范围获得停用/恢复能力 |
| PM | 无 M05 权限 | 无 | 无 | 不因当前有效负责地市获得停用/恢复能力 |
| HR/人事 | 无 M05 权限 | 无 | 无 | M06 的员工停用/恢复能力不产生客户侧 M05 权限 |

## 3. 核心对象

### 3.1 被处理业务对象

| 对象 | 产品含义 | 所有权 |
| --- | --- | --- |
| 集团公司 | 被停用或恢复的集团主数据对象 | M09 |
| 客户公司 | 被停用或恢复的客户经营主体 | M09 拥有主数据，M02 消费同一档案 |
| 关键人 | 被停用或恢复的客户关键人身份及当前任职主体 | M02 |
| 客户部门 | 唯一归属于一个客户公司的客户侧部门对象 | M09 |

这些对象的主数据和普通业务关系不因进入 M05 而转移所有权。

### 3.2 M05 操作与记录表达

| 对象 | 产品含义 |
| --- | --- |
| 停用操作 | admin 从业务对象详情发起、包含原因、影响处理、快照和二次确认的一次直接操作 |
| 恢复操作 | admin 从停用记录详情发起、包含恢复原因、恢复影响和二次确认的一次直接操作 |
| 停用记录 | 对象停用校验、确认、生效和影响处理的历史表达 |
| 恢复记录 | 已停用对象的恢复校验、确认和生效历史 |
| 对象快照 | 提交时对象名称、业务编号、稳定 ID、版本、状态和所属范围的只读事实；集团公司快照必须保留 M09 分配的集团编号，客户公司快照必须保留当时所属集团、显式组织上级及业务责任事实 |
| 影响摘要 | 下级、任职、未完成任务、覆盖 KPI、待审批、责任和统计影响的提交前快照 |
| 级联选择 | 集团或客户公司停用时对全部合法下级对象的条件选择 |
| 任务处理规则 | 停用生效时统一关闭适用未完成任务并记录原因；无通用任务转移或重新分配 |
| 生效历史 | 实际操作人、确认结果、实际生效时间、失败结果和恢复结果的时间线 |

### 3.3 M04 边界

客户侧停用/恢复不创建或关联 M04 审批实例、审批节点、处理动作、抄送关系、流程编号、审批待办或业务回调重试链路。M05 自身保存影响校验、二次确认、直接生效结果和审计历史，但不建立审批容器或审批状态机。

### 3.4 外部影响对象

关键人任职、未完成任务、专项与覆盖 KPI、其他待处理审批、客户/区域责任关系和正在执行的导入批次，分别由 M02、M03、M04、M08 和 M10 拥有。M05 只在影响摘要、阻断检查和生效历史中消费这些事实。

## 4. 页面与入口

### 4.1 业务对象中的停用入口

- 集团公司、客户公司和关键人由唯一内置 `admin` 从 M02 相应业务详情发起停用。
- 集团公司、客户公司和客户部门也可由 `admin` 从 M09 客户组织树的相应详情发起停用。
- 入口仅在对象为正常、当前账号为唯一内置 `admin` 且既有阻断检查通过时显示。

停用入口属于业务对象页面，影响校验、直接生效、停用记录和后续恢复属于 M05；页面入口不改变所有权。

### 4.2 停用影响确认

停用入口打开影响确认表单，展示：

- 对象类型、对象名称、业务编号、所属范围和停用前状态快照；集团公司显示原集团编号；
- 5-500 字停用原因；
- 统一关闭适用未完成任务并记录原因；
- 条件必填的完整级联对象；
- 下级、任职、未完成任务、覆盖 KPI、待审批、责任和统计影响摘要。

影响数量可按类别下钻。影响摘要加载失败、级联不完整或存在未处理冲突时不能进入二次确认，页面保留已填写内容并列出阻断项。

### 4.3 停用记录列表

筛选项：对象类型、对象名称、所属集团、所属区域、业务状态、实际操作人、操作开始日期、操作结束日期、生效开始日期和生效结束日期。每项使用常驻可见字段标签；对象名称只匹配名称字段，所属集团和所属区域分别只匹配对应归属字段。

列表字段：对象类型、对象名称、所属范围、停用原因、实际操作人、停用生效时间、当前业务状态、恢复结果和操作。

默认仅显示业务状态为已停用的对象，按停用生效时间倒序。停用/恢复不产生审批状态或流程编号；当前权限范围没有记录时显示 Empty，有记录但筛选无命中时显示 Empty Result 并保留筛选条件。

### 4.4 停用记录详情

详情使用 Drawer，展示：

- 对象快照和停用前状态；
- 停用原因、任务处理方式和级联/替代处理；
- 下级、任职、任务、KPI、审批、责任和统计影响；
- 实际操作人和二次确认结果；
- 停用生效时间和失败结果；
- 恢复操作、恢复生效记录和完整时间线。

恢复成功后对象移出默认停用记录列表，但完整停用/恢复历史继续由 admin 在对象操作日志中查看。非 admin 通过历史关联或直接地址访问 M05 详情时返回 403，且不泄露对象信息。

### 4.5 恢复操作

恢复入口仅在对象已停用、全部上级对象正常、当前账号为唯一内置 `admin` 且既有恢复阻断检查通过时显示。表单展示目标对象快照、5-500 字恢复原因、上级状态和恢复影响。

admin 二次确认且恢复事务全部成功后，对象重新进入正常列表、树、搜索和候选；任一写入失败时整次不生效并继续保持已停用。不自动恢复下级、不取回已转移责任，也不补造停用期间已经过去的任务。

### 4.6 审计历史

M05 列表和详情直接展示停用/恢复的影响结果、实际操作人、确认结果、生效时间和失败结果，不提供“查看审批”入口。其他业务流程编号仅在作为阻断项且 admin 本身有权时提供受控查看；该入口不会把客户侧停用/恢复转成 M04 审批。

## 5. 用户操作

| 操作 | 谁 / 从哪里 | 前置条件与确认 | 生效与成功反馈 | 失败保护 |
| --- | --- | --- | --- | --- |
| 发起停用 | 仅 `admin` 从 M02/M09 对象详情 | 对象正常；打开影响确认，不立即改变对象 | 尚未确认，不产生记录或流程编号 | 非 admin 或状态不符时不显示入口；直接访问返回 403 |
| 查看影响 | 停用影响确认表单 | 实时计算下级、任职、任务、KPI、审批、责任和统计影响 | 展示数量和可下钻明细 | 加载失败保留表单、禁用提交并允许重试 |
| 确认停用 | 仅 `admin` 从影响确认表单 | 原因和条件级联完整；影响校验通过；二次确认当前影响与未完成任务关闭清单 | 停用事务全部成功后直接生效并写入 M05 记录；不创建 M04 审批事实 | 版本变化、重复提交或任一阻断/写入失败时整次不生效，不留下部分结果 |
| 确认恢复 | 仅 `admin` 从 M05 停用详情 | 对象已停用、全部上级正常，唯一性、责任、版本和恢复顺序校验通过；二次确认恢复影响 | 恢复事务全部成功后直接恢复正常并写入 M05 历史 | 任一校验或写入失败时列出原因并保持已停用，不留下部分结果 |
| 查看历史 | 仅 `admin` 从 M05 或对象历史关联 | 查看公司全局记录 | 展示停用、影响、确认、生效、恢复和失败时间线 | 非 admin 返回 403；历史不可修改或删除 |

F012 客户侧停用/恢复未定义计划生效日期字段。停用和恢复在 admin 完成影响校验、二次确认且对应业务事务全部成功后立即生效；不得从 M04 通用计划生效分支推导新的 M05 字段或审批链路。

## 6. 字段与业务规则

### 6.1 通用操作字段

| 字段 | 展示/录入 | 必填 | 默认/候选 | 产品规则 |
| --- | --- | --- | --- | --- |
| 对象类型/对象名称 | 只读 | 是 | 按入口确定 | 提交时保存稳定 ID、名称快照和对象版本 |
| 操作动作 | 只读 | 是 | 停用/恢复 | 按入口确定，不能在表单内切换 |
| 原因 | 多行输入 | 是 | 无 | 5-500 字；进入 M05 审计历史 |
| 未完成任务处理 | 只读规则 | 停用适用 | 统一关闭适用未完成任务并记录原因 | 不提供通用转移、迁移或重新分配选项；恢复不使用 |
| 级联对象 | 树形多选 | 条件必填 | 当前有权的正常下级对象 | 选择级联时必须包含全部合法下级，不允许留下正常孤立下级 |
| 影响摘要 | 只读 | 是 | 实时计算 | 下级、任职、任务、KPI、待审批、责任和统计每类数量可下钻；失败时不能提交 |

**Current Rule（DEC-164）：** 本期客户主数据停用和恢复均不支持附件，表单不展示上传、预览、下载或删除附件入口。旧 F012 按钮表在“申请停用”中出现的附件字段保留为 Historical / Replaced Evidence，不再作为当前字段。

### 6.2 统一规则

- 原因统一为 5-500 字并进入 M05 审计历史。
- “关闭未完成任务”只关闭待执行、当前逾期、暂停中和已过期未完成的执行记录；关闭不计完成、不生成维系记录、不产生下一期任务。
- 进入二次确认前和实际写入前均重新计算适用未完成任务清单；确认后统一关闭新增命中的适用任务。任一关闭或对象写入失败时整次操作不生效，对象和任务均保持原状态，不得改走通用任务转移。
- 补录审核中和其他审批中的任务必须先结束审批，停用流程不能静默覆盖。
- 确认提交中禁止普通编辑、重复停用/恢复和相反动作；重复或并发确认只产生一个合法结果。
- 集团公司、客户公司、关键人和客户部门均不物理删除；稳定 ID、业务编号、显式组织上级快照、历史快照和审计永久不因停用、恢复或失败而回收。
- 停用事务全部成功后才从正常树、搜索、候选、任务生成和当前统计中剔除；确认前或失败时仍按原业务状态参与业务。
- 恢复不自动恢复下级、不自动取回已转移的客户/任务/责任、不改写停用期间历史，也不补造已经过去的任务。
- 恢复顺序为集团公司 → 客户公司 → 关键人；客户部门独立恢复。

### 6.3 统一阻断条件

影响摘要加载失败，或当前对象/级联对象存在关键人调岗审批、地市负责人交接审批、任务延期/暂停/取消/补录审批、客户责任版本变化、正在执行的导入写入或另一并发停用/恢复操作时，必须先处理对应事项。页面按对象列出相关流程编号或批次编号，并仅在 admin 对该外部事实有权时提供查看入口。

### 6.4 集团公司

**停用约束：** 以 M09 显式组织上级关系识别的正常下级客户公司必须先迁移到其他合法上级，或被完整纳入级联停用；完整级联包含全部正常后代客户公司和有效关键人，不能只停部分后留下正常下级。影响摘要分别统计客户公司、关键人、任务、专项、覆盖 KPI、待审批和客户部门。

**生效影响：** 集团、级联客户公司和关键人退出当前树、搜索、候选、默认统计及专项新匹配，未完成任务按已确认的任务处理方式处理。历史维系记录、已完成任务、编号、任职和附件快照保留。

**恢复约束：** 恢复集团只恢复集团本身，不自动恢复客户公司、关键人或已关闭任务；集团恢复后再按客户公司、关键人顺序逐级恢复。

### 6.5 客户公司

**停用约束：** 以 M09 显式组织上级关系识别的正常下级客户公司必须先迁移到同集团其他合法上级，或被完整纳入级联停用；正常关键人不能挂在已停用客户公司下。存在有效关键人时必须完整级联停用，或先通过关键人调岗把全部关键人移出。

**生效影响：** 客户公司退出树、搜索、候选和当前经营统计；适用未完成任务统一关闭并记录原因；当前覆盖率分母剔除该公司，历史责任、已结束 KPI 和历史快照不回算。

**恢复约束：** 所属集团和当前显式组织上级必须正常，业务责任区划仍有效，行业可展示且对应当前责任人存在。恢复只让客户公司重新进入正常入口，不自动恢复关键人或历史任务；当前责任按恢复时有效业务责任关系重新解析，组织路径不据此重算。

### 6.6 关键人

**停用约束：** 保留关键人稳定 ID、编号、身份、当前任职和全部历史；当前任职只标记因关键人停用而不可用，不伪造任职结束日期。

**生效影响：** 关键人退出有效列表、任务新生成、专项新增匹配和覆盖率。若其是目标部门或岗位最后一名有效关键人，对应进行中覆盖 KPI 重新打开，并按当前责任人展示待处理结果。

**恢复约束：** 所属集团、客户公司和当前任职客户部门必须正常，手机号和微信仍满足唯一性。恢复后只生成恢复时间之后仍适用的未来任务，不补停用期间已过去任务；覆盖 KPI 按恢复后的当前责任归属，原历史不转移、不重复建项。

### 6.7 客户部门

当前 Candidate 按 DEC-161 表达：客户部门只能归属于一个客户公司，下级部门与上级部门必须属于同一客户公司。存在当前任职引用时，停用前必须选择同一客户公司内、状态正常、不是自身或后代的合法替代客户部门，或先处理当前任职；不能使用跨客户公司共享模板。

**生效影响：** 当前任职按 admin 二次确认的方案迁移并记录原/新客户部门、实际操作人和生效时间；历史任职、已结束 KPI 和历史记录继续展示原部门快照。客户部门停用不直接停用关键人；无合法替代且仍有当前引用、导入引用未结束或替代部门在确认前失效时不能生效。

**恢复约束：** 恢复后客户部门重新进入新增、编辑、调岗和导入候选，但不自动把已经迁移的任职改回原部门。

旧 F012、DEC-018 的集团共享“部门模板”及跨公司适用表达已由 DEC-161/DEC-163 替代，作为 `Historical / Replaced Evidence` 保留。Current Rule 只允许唯一客户公司内的部门路径。

## 7. 状态与反馈

### 7.1 页面状态

| 状态 | 用户看到什么 |
| --- | --- |
| Loading | 列表、详情或影响摘要加载中，显示对应加载状态 |
| Empty | 当前授权范围没有停用记录 |
| Empty Result | 当前范围有数据但筛选无命中，保留筛选条件并提供重置 |
| Error | 列表或详情加载失败可重试；影响摘要失败时保留表单并禁用提交 |
| PermissionDenied | 显示无权限，返回 403，不泄露对象是否存在 |
| Submitting | 停用/恢复确认或直接生效处理中，按钮禁用，重复操作不产生第二结果 |
| Success | 停用/恢复事务全部成功后显示明确结果并刷新关联页面 |

### 7.2 业务对象状态

M05 只按以下两个业务状态理解被处理对象：

- **正常：** 停用事务全部成功前仍参与原业务、列表和统计。
- **已停用：** 停用事务成功后退出正常业务入口，仍保留历史和恢复能力。

恢复事务全部成功后对象从已停用回到正常。任一写入失败时整次操作不生效并保持生效前业务状态。

### 7.3 直接操作状态边界

- **对象业务状态：** 只使用正常、已停用；影响校验、二次确认和提交处理中不增加其他业务状态。
- **操作结果：** 成功后直接切换业务状态并写入 M05 历史；取消或失败保持原状态，不留下部分处理结果。

客户侧停用/恢复没有审批进度、审批实例或流程编号。

### 7.4 M04 边界

M04 的审批中、已通过、已驳回、已通过-业务处理失败和处理人失效均不用于客户侧停用/恢复。不得把页面状态、业务对象状态、操作结果和外部审批状态组合成新的统一状态机，也不得因为 M04 存在通用计划生效分支而给 F012 增加计划生效日期字段。

### 7.5 错误与操作反馈

- **影响摘要失败：** 保留输入、禁止提交、允许重试。
- **上级未恢复：** 阻止下级或关键人恢复，展示固定恢复顺序。
- **级联不完整：** 列出遗漏对象，不能进入二次确认。
- **重复操作或编辑锁定：** 拒绝并发确认和普通编辑，不覆盖已成立结果。
- **任务未处理：** 确认前阻止；写入前出现新任务则重新计算，任一处理失败整次不生效。
- **其他流程冲突：** 列出有权查看的流程编号或批次编号，不静默覆盖。
- **对象或责任版本变化：** 展示最新摘要，要求刷新后重新确认，不覆盖新状态。
- **替代客户部门失效：** 客户部门停用不生效，原任职保持不变。
- **直接操作失败：** 对象保持生效前状态，停用失败保持正常、恢复失败保持已停用；M05 记录失败结果，不创建 M04 实例或回调重试链路。
- **越权：** 403 且不泄露对象、流程或候选信息。

## 8. 用户流程

### 8.1 产品流程

1. **发起停用：** 唯一内置 `admin` 从 M02/M09 业务对象详情打开停用影响确认，业务对象不改变。
2. **影响确认：** 系统展示对象快照、原因、任务处理、完整级联和外部影响；存在阻断时停留在表单。
3. **二次确认：** 校验通过后由 admin 确认当前影响；取消不产生记录或状态变化。
4. **生效：** 确认后执行停用事务；全部成功才改变业务对象并写入 M05 历史，失败则整次保持原值。
5. **已停用：** 对象退出正常树、搜索、候选和当前统计，M05 保留详情、历史和恢复入口。
6. **恢复操作：** admin 在全部上级正常且其他恢复条件满足时，从 M05 详情填写原因并确认恢复影响。
7. **恢复确认：** 校验通过后由 admin 二次确认；取消或校验失败时业务对象继续保持已停用。
8. **恢复生效：** 恢复事务全部成功后对象回到正常入口；失败时整次保持已停用；不恢复下级、不取回责任、不补历史任务，完整记录继续保留。

### 8.2 FLOW-04

[FLOW-04 M05 deactivation lifecycle](../user-flows/FLOW-04-M05-deactivation-lifecycle.md) 表达对象在 admin 二次确认且直接事务全部成功后于正常和已停用之间切换；确认前、取消或失败均保持原业务状态。

### 8.3 FLOW-13

[FLOW-13 M05 deactivation and restore](../user-flows/FLOW-13-M05-deactivation-and-restore.md) 的 Current 分支表达仅唯一内置 `admin` 操作、影响校验、二次确认、原子直接生效和停用时统一关闭适用未完成任务。原机械迁移块的多角色审批及“转移或关闭”保留为 Historical / Replaced Evidence。

### 8.4 FLOW-09

[FLOW-09 M04 approval lifecycle](../user-flows/FLOW-09-M04-approval-lifecycle.md) 由 M04 拥有，但客户侧停用/恢复不消费该流程。不得因为 FLOW-09 存在审批、回调或计划生效分支而给 F012 增加审批事实、重试链路或计划生效日期字段。

## 9. 权限边界

### 9.1 M05 拥有

- 客户侧停用/恢复操作、处理记录和生效历史；
- 对象快照、影响确认、级联/替代处理和结果表达；
- 仅由唯一内置 `admin` 查询公司全局停用/恢复历史并使用受控恢复入口。

### 9.2 外部所有权

- **M09：** 集团公司、客户公司和客户部门主数据及普通维护。
- **M02：** 客户经营、关键人身份、任职和普通经营行为。
- **M04：** 其他业务的审批实例、节点、路由、处理动作、抄送和处理人失效；客户侧停用/恢复不进入 M04。
- **M06：** 内部部门、员工、账号及员工停用/恢复。
- **M03：** 任务、专项、覆盖 KPI 和维系记录生命周期。
- **M08：** 区域、省市责任和地市负责人关系。

### 9.3 访问边界

M05 不拥有员工/账号停用、客户主数据普通编辑、关键人普通经营、任务生命周期或审批容器。唯一内置 `admin` 拥有公司全局 M05 权限；其他角色无菜单、对象入口、历史和操作，伪造请求或直接访问统一返回 403 且不泄露对象事实。
