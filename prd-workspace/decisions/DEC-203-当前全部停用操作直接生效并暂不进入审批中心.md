# DEC-203：当前全部停用操作直接生效并暂不进入审批中心

- 日期：2026-09-04
- 状态：已确认
- 背景：当前产品中的员工、客户侧对象及若干基础配置分别定义了停用权限、校验和生效结果，但“不进入审批中心”的结论分散在不同模块。Product Owner 已确认，当前正式提供的全部停用操作均不走审批，满足各对象既有条件并完成确认后直接生效；审批中心后续完善时，再按实际业务逐对象评估是否引入审批。
- 决策：
  1. 当前已经正式提供的全部停用操作均为来源模块内的直接生效动作，不创建 M04 审批实例、审批节点、流程编号、审批待办、抄送关系或审批回调重试链路。
  2. “直接生效”不等于无条件或点击即生效。操作资格、对象状态、必填原因、引用/影响校验、阻断条件、二次确认、并发校验、审计和业务后处理继续分别以对象 Owner PRD 的当前规则为准。
  3. 当前适用对象包括：M06 员工及其联动账号、系统管理员单独停用的非内置员工账号；M05/M09 的集团公司、客户公司、关键人、客户部门；M09 的行业和标准关键人岗位；M11 的采购包和平台公司。M09 生日/节假日规则的启用/停用属于配置开关，同样由 admin 保存后直接生效，但不建立停用记录生命周期。
  4. 各对象的生效事务边界保持不变。员工停用继续按 DEC-202 先使员工、账号和会话失效，再按责任组交接，失败组不回滚已停用状态或成功组；客户侧对象继续按 DEC-198 在影响校验和二次确认后原子生效；行业、标准岗位、采购包、平台公司和规则开关继续使用各自既有引用校验、阻断条件和二次确认规则。
  5. 当前已经定义的恢复操作继续按各 Owner PRD 直接生效，不因本决策新增统一恢复流程、审批路由或对象状态。
  6. 内部部门（包括区域运营中心）的停用/恢复/删除仍不属于当前迭代；系统管理员模板和唯一内置 `admin` 账号仍不可停用或删除。区域、省份、地市责任、项目取消/中止及任务暂停等不同业务动作不因名称或结果相近而被纳入本决策。
  7. “审批中心后续完善后再评估”属于 `DEFER`。未来只有在 Product Owner 针对具体对象确认新的权限、申请字段、审批路由、生效时点、失败处理和历史表达，并正式更新 Current Product 后，该对象的停用才可进入 M04；审批中心功能存在本身不会自动改变任何停用流程。
- 替代关系：统一并补充 DEC-165、DEC-198、DEC-202 及 M09/M11 已有直接生效边界；替代 DEC-012、DEC-116、DEC-159、DEC-184 及其他 Current 文档中仍可能被误读为当前停用审批的旧表达。上述 Decision 中未被后续规则替代的对象状态、权限、影响处理和历史保留规则继续有效。
- 未采用方案：把“直接停用”解释为取消影响校验、阻断条件或二次确认；把尚未实现的内部部门停用纳入当前能力；为全部对象预设一条未来统一审批流程；因 M04 已存在而自动生成停用审批。
- 原因：先统一当前生效方式，可以避免研发根据旧审批文字或 M04 通用能力自行创建停用流程；同时保留对象级安全校验和后处理，并把未来审批设计留到相应业务完成评审时逐项决定。
- 决策人：Product Owner
- 影响范围：M01、M03、M04、M05、M06、M09、M11、Shared、Acceptance、Decision Index
