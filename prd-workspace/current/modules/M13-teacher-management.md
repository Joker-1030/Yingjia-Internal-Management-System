# M13 培训老师管理

> 文档状态：CURRENT；Product Review：NOT REVIEWED；Approved Baseline：NONE。
> Owner：本文件；产品入口：`prd-workspace/current/PRD.md`。2026-10-21用户明确“进入prd和demo”。

## 1. 目标与边界

维护内部及外部培训老师的档案、教学方向、合作渠道和统一排期，供M11项目按方向及空闲日期选师。在“培训老师”分组设置“老师管理”“老师排期”两个菜单，并提供老师、教学管理人员两个角色。老师为独立对象，不归属某个客户、区域运营中心或单个项目。

本期不包含课酬结算、费用扣减、项目成本/毛利、资质审批、评分排名、排课优先级、自动改派、通知或工作台指标；外部机构只作为渠道信息，不新增机构管理模块。

## 2. 对象与事实所有权

| 对象 | 含义与所有权 |
| --- | --- |
| 老师档案 | 内部/外部两类；同人一份档案及统一排期，外部不能按渠道重复建人；M13拥有 |
| 内部员工关联 | 内部老师关联M06已有员工及老师角色，姓名/手机号复用员工信息；外部不创建账号；员工事实仍归M06 |
| 教学方向 | 老师可授课能力的原多选字段，直接引用M11采购包已有课程；课程归M11，不新增或维护独立教学方向目录 |
| 合作渠道 | 外部老师可同时有个人和多个机构渠道；每家机构独立联系信息及参考课酬；M13拥有 |
| 人工不可用日期 | 老师整天不能安排项目的起止日期，含首尾；M13拥有 |
| 项目占用 | M11项目开始至结束的自然日期整天占用；来自M11，不在M13重复维护项目人员或时间 |
| 教学管理范围 | admin或当前“师资管理部”主管为师资管理部内每个教学管理人员分配内部老师、外部机构渠道、外部个人渠道三项，可多选；师资管理部主管同时拥有全部三类老师的档案、渠道、课酬和排期维护权；业务对象范围归M13，角色关联归M06、模板归M07 |

## 3. 角色、可见范围和操作

| 身份 | 可见与可维护 |
| --- | --- |
| admin | 全部老师、公共资料、简历、完整联系方式、各渠道及课酬；建档、编辑、排期、启停；分配教学管理范围 |
| 师资管理部主管 | 全部三类老师、公共资料、简历、完整联系方式、各渠道及课酬；建档、编辑、排期、启停；可为师资管理部内教学管理人员分配三项教学管理范围 |
| 教学管理人员 | 只看/维护负责范围内全部老师及排期；双渠道老师的公共资料和排期共同维护，各自只维护有权渠道及课酬；没有分配范围不获得老师数据 |
| 总裁 | 仅新增“老师排期”只读入口，查看全部内部/外部老师的授课占用与人工不可用；可切日历/甘特图及筛选老师；不因此获得档案、联系方式、简历、渠道、课酬或维护权限 |
| 内部老师本人 | 只读本人资料和排期，可查看本人完整手机/邮箱/微信；只可新增、修改、删除本人登记的人工不可用日期；不维护公共资料或他人登记日期，不看课酬、机构渠道及简历 |
| 有权项目负责人/总监及其他原有权项目用户 | 在原项目权限内选公司全部符合条件的老师；只读公共资料及脱敏联系方式，不看简历、渠道联系信息或课酬；不取得M13维护入口 |
| 其他身份 | 不因公司/区域经营查看权自动获得老师档案管理、排期维护、完整联系方式或简历权限 |

同人兼任按其有效角色和业务范围判断；具备有效总裁排期查看资格时，排期显示全部老师，档案及维护仍只按其其他有效身份原范围判断，总裁原工作台默认入口保持。师资管理部主管是按当前部门主管关系识别的M13特定配置资格，不新增系统角色；其老师档案、渠道、课酬、简历和排期维护范围固定为全部三类老师，教学管理范围配置对象仅限师资管理部内的教学管理人员。不能用项目查看权或老师身份绕过简历/渠道/费用上限。其他部门主管不因主管关系获得老师配置或维护权限，也不扩大M06人事维护权。

老师范围：内部老师对应“内部老师”；有机构渠道的外部老师命中“外部机构渠道”，有个人渠道的命中“外部个人渠道”，命中任一有权类别可访问公共资料及统一排期。外部各机构渠道属于同一“外部机构渠道”范围，不按某家机构另建管理角色。

## 4. 页面及交互

- “培训老师”分组下分为“老师管理”“老师排期”两个菜单。老师管理页面展示档案列表及原建档/详情/编辑/启停及分工操作，不混排月历或甘特图；管理者介绍“维护老师资料。”，老师本人介绍“查看个人资料。”。老师排期页面单独展示§4.1既有排期视图，介绍“查看授课与不可用日期。”。
- 老师管理沿本模块原访问资格和本人/管理范围；老师排期复用既有查看权限并增加总裁全体排期只读资格，不增加独立业务权限。总裁仅有排期菜单，不因本次变更取得档案菜单。老师身份的档案菜单及页名为“我的信息”，admin/教学管理人员仍称“老师管理”；老师身份的排期菜单及页名为“我的排期”，纯老师账号默认进入该页；admin/教学管理人员仍称“老师排期”，兼任按有效角色和原默认落地优先规则。本人档案入口保留。档案详情中的排期及人工不可用维护入口保持，排期可视化的点击仍只读。
- 老师列表展示姓名、内部/外部、教学方向、启用/停用及操作。列表只返回有权老师，沿用通用列表分页；不新增人数、评分或经营指标。
- 有权维护者从“新增老师”建档；从操作列“详情”查看公共资料、本人有权的联系方式/简历/课酬/渠道及排期；“编辑”维护档案；姓名不再重复承担详情入口。
- 详情展示项目占用及人工不可用的起止日期，项目占用只读；无跨项目操作权者不因此获得项目详情跳转。内部老师只显示本人可用的操作。
- 新增/编辑使用表单，字段错误保留输入并指出原因；保存成功刷新对应列表/详情。取消、右上角关闭、遮罩关闭不保存。停用/恢复及删除人工不可用经二次确认，取消不改变原值；校验失败保持原对象。
- admin从本模块维护教学管理人员的三项负责范围；只修改范围不改员工角色。老师教学方向由有权维护者多选M11采购包中的课程，以采购包及课程内容识别；不提供独立方向目录、方向新增/改名入口，也不为采购包增加方向配置项。
- 页面正常、空、错误、无权反馈沿用通用规则。无权字段及附件不输出，不以遮挡DOM文本代替数据权限。

### 4.1 日历与甘特图排期

- 在“老师排期”菜单内提供既有排期可视化，不再与“老师管理”的档案列表同页混排，不新建独立排课模块。内部老师使用日历，只能查看本人排期；教学管理人员可切换日历/甘特图，默认打开日历，只能查看原三项管理范围命中的老师，不因视图或筛选扩大范围。
- 总裁从“老师排期”只读查看全部内部/外部老师的排期，默认日历、北京时间当前月及全部老师（筛选全选文案“全部老师”）；可单选/多选老师、切换月份及日历/甘特图，切换保留月份/筛选。只查看既有日程详情，不进入老师档案、不维护排期，不因总裁排期资格读取联系方式、简历、渠道或课酬；项目详情仍沿M11原权限。
- 默认展示北京时间当前自然月，可切换月份。教学管理人员默认展示全部负责老师，可筛选其中一名或多名；老师本人不提供他人老师筛选。未分配管理范围或范围内无老师时不返回其他老师或其安排，沿用既有空/无权反馈。
- 日历按自然日期展示授课项目占用与人工不可用日期，多日安排跨天连续展示；按既有整天口径呈现，不拆成上下午或小时排课。安排横跨月份时展示其与当前月份重叠的日期，不漏掉月初前开始、月内仍持续的安排。
- 甘特图以老师为行、当前月份的自然日期为列，以连续区间展示同一老师的项目占用和人工不可用。日历和甘特图使用同一排期数据、当前月份及老师筛选；切换视图不重置月份或已选老师，不改变排期、占用或原状态。
- 点击日程只读查看对应安排的既有详情及起止日期，不在日历/甘特图中拖拽改期或修改项目人员。项目详情访问仍受M11原权限限制，无项目详情权者不能借日程进入项目详情；老师本人及管理人员可维护人工不可用的资格、入口和冲突保护按§3/8保持。
- 日程及详情不因可视化展示取得原本无权的老师联系方式、简历、渠道或课酬。项目取消/中止的占用释放、历史保留及老师启停均沿用§8/9，不在两种视图另算一套排期。

## 5. 档案字段与建档

| 字段 | 要求 |
| --- | --- |
| 老师姓名 | 必填；内部关联员工后只读复用姓名；外部填写姓名 |
| 内部/外部 | 必填；内部选择已有老师角色员工；外部不关联登录账号 |
| 简介、性别 | 可补录；简介为公开教学介绍，不存放需保密的渠道或课酬 |
| 手机号 | 必填；内部复用M06手机号，外部填写；遵守通用手机号格式 |
| 出生日期、年龄 | 出生日期可补录，不允许未来日期；年龄按出生日期与当前北京时间计算周岁，不重复存年龄 |
| 学历 | 可补录 |
| 简历 | 可补录附件；只允许admin及有权教学管理人员访问，详见§7 |
| 教学方向 | 至少一门、可多选采购包已有课程；候选显示所属采购包及课程内容，复用原字段而不另增课程方向字段 |
| 邮箱、微信号 | 可选；邮箱遵守通用格式；联系方式按§7保护 |
| 内部标准课酬 | 可补录，金额及每条含税/不含税口径一起填写，单位元/天 |
| 外部合作渠道 | 至少一个；可有个人及多个机构，机构名必填；各渠道参考课酬独立 |
| 状态 | 启用/停用；不提供物理删除；停用规则见§9 |

内部老师建档不复制员工账号，不在M13修改员工姓名、手机号或角色；这些变化继续由M06负责。角色关联本身不自动生成完整老师档案。外部同一老师的多机构/个人来源在一份档案内维护，不能以渠道拆分排期。

机构渠道字段为机构名称、联系人、联系电话、联系人微信号、联系人邮箱和参考课酬；仅机构名称必填，联系方式均可选。个人渠道复用老师本人的联系方式并维护独立参考课酬，不重复新增一个个人老师档案。

课酬按每条选择含税或不含税，金额非负、最多两位小数；空值表示未补录，不等于零，不根据另一条价格换算。字段名称/相邻税务选择和元/天单位共同明确口径。内部标准课酬、个人渠道参考课酬、每家机构参考课酬彼此独立，不影响M11报价、项目金额、平台合作课酬或产生结算。

## 6. 统一方向与项目选师

- 课程唯一维护来源是M11采购包内已有课程（原采购包称课程方向），不另建M13全局方向目录。老师教学方向可多选这些包内课程，同名但所属采购包不同的课程不自动合并；采购包原课程介绍、价格及生命周期保持。平台师资合作项目也先选采购包再选包内一门课程，平台公司合作课酬规则保持。
- 培训项目单选包内课程；主讲师、辅讲师每个人的教学方向都包含该课程，助教只检查空闲。项目复用原采购包/选课项，不额外增加课程方向字段。AI软件项目仍不使用授课人员或培训方向。
- 项目人员候选只提供启用、整段自然日期有空且适用方向匹配的老师；日期或方向不完整时提示先完成条件，不展示不受限的全部人员。
- 内部老师还须对应员工在职且具有有效老师角色；员工停用或移除老师角色后立即退出新选及替换候选，提交时再次复核，不能用旧表单继续新选；已有项目和历史按§9保留，不自动改派。
- 编辑老师教学方向时，如果移除的方向仍被该老师作为主讲师或辅讲师参与的未开始（M11已立项）/进行中项目使用，阻止整个保存，提示受影响项目，保留原档案；先由项目负责人按原阶段权限更换老师或调整项目，再重新保存。admin及教学管理人员均不能绕过；助教沿既有规则不要求方向，不因仅担任助教阻止移除方向；已交付等历史安排不因此被重写。
- 所有M11可编辑人员入口、影响人员排期的日期变更都在保存时重新校验；排除当前项目自身占用，不能通过旧页面、变更账号、直接提交或伪造人员绕过。
- 失效或冲突的已选人员保留为待处理选择并提示原因，供移除/替换；不静默丢失已选人、不自动换人。项目阶段可编辑范围和已交付实际人员更正仍由M11拥有。
- 已有历史人员及方向快照保持，不根据重名猜测绑定老师、不自动重写旧评价。尚未绑定正式老师身份的旧人员只作历史展示，不作为新选正式老师；项目修改人员时需选正式档案。

项目字段及阶段规则见 [`M11 项目管理`](./M11-project-management.md) → §8“商业资源与快照”、§9“项目人员与排期”、§11“分阶段编辑权限”。

## 7. 隐私和简历附件

- 老师手机号/邮箱/微信、机构联系人电话/微信/邮箱加密保存，页面默认脱敏。不得把页面星号视为加密保存已经完成。
- admin及对应范围内教学管理人员可主动查看完整值；内部老师可主动查看本人完整联系方式，项目负责人/总监只看脱敏值。
- 渠道信息及课酬仅admin和有权教学管理人员可见，先校验渠道范围再判断完整值资格。老师本人不因此获得机构联系人或课酬。
- **简历仅admin及有权教学管理人员可查看、预览、下载和维护**；项目用户只看公共资料，内部老师本人也不单独获得简历访问权。不得用文件名链接、直达地址或附件接口绕过；不新增自动简历脱敏或公开副本。
- 简历复用 [`Shared统一产品规则`](../shared/03-unified-product-rules.md) →“附件统一规范”：图片/PDF/Office、单文件20MB、单对象9个、单次100MB；文件头/类型及扫描、受控访问等规则保持。图片/PDF在线预览，Office按既有元数据及下载表达，不继承M11大文件/全类型预览例外。
- M06组织与员工中原手机号统一脱敏规则保持；本模块完整值权限不能回流到员工列表、详情或编辑快照。

## 8. 排期和冲突

- 使用北京时间自然日期整天排期，起止日期均包含。项目在同一天上午/下午的两段授课仍冲突；跨多日项目每名已选人员在整个开始日至结束日期均占用，与计费确认天数无关。
- 项目占用和人工不可用共用同一老师身份校验，跨主讲/辅讲/助教及渠道均不产生额外可用名额。所有角色无强制覆盖。
- admin及有权教学管理人员维护范围内人工不可用；内部老师只维护本人登记项。登记/修改不可用与已安排项目冲突时阻止保存，提示冲突项目，先由项目负责人调整时间或人员。
- 项目候选和保存复核都检查其他项目及人工不可用，失败保持原项目/档案，不预占老师或写半条历史。
- 项目取消释放排期；中止释放后续排期、保留历史，沿用M11既有规则。已交付/完成的原授课日期只作历史，不产生新的未来占用。
- M13不改项目阶段、时间、人员，不自动取消、替换或撤销已安排项目；方向/员工状态变化与历史资料衔接不得被解释成自动改派策略。

## 9. 启停

老师有未开始（M11已立项）或进行中的授课项目时禁止停用，展示冲突项目，先由项目负责人换老师。已交付但资料/评价未齐的项目不阻断；已完成、取消、中止及原授课历史保留。停用后退出新建和替换候选；恢复后按方向/空闲重新进入候选。老师档案停用与员工账号停用分别处理，不以停用老师自动禁用员工账号，也不新增员工交接业务。

内部员工被停用或移除老师角色后，即使老师档案仍为启用，也立即退出新选/替换候选；已有项目人员安排、排期及历史保留，由项目负责人按原项目权限另行调整，不自动清除、迁移或改派。员工及账号停用仍按M06原规则立即生效，不套用“老师档案停用前须先换师”的阻断，不等待项目换人后才停用员工；本次不改变档案启停状态或增加交接流程。
