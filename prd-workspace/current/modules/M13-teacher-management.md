# M13 培训老师管理

> 文档状态：CURRENT；Product Review：NOT REVIEWED；Approved Baseline：NONE。
> Owner：本文件；产品入口：`prd-workspace/current/PRD.md`。2026-10-21用户明确“进入prd和demo”。

## 1. 目标与边界

维护内部及外部培训老师的档案、教学方向、合作渠道和统一排期，供M11项目按方向及空闲日期选师。在“培训老师”分组设置“老师管理”“老师排期”两个菜单，并提供老师、教学管理人员两个角色。老师为独立对象，不归属某个客户、区域运营中心或单个项目。

本期不包含课酬结算、费用扣减、项目成本/毛利、资质审批、评分排名、排课优先级、自动改派、通知或工作台指标；外部机构只作为渠道信息，不新增机构管理模块。

## 2. 对象与事实所有权

| 对象 | 含义与所有权 |
| --- | --- |
| 老师档案 | 内部/外部两类；同人一份档案及统一排期，外部不能按渠道重复建人；M13拥有 |
| 内部员工关联 | 内部老师关联M06已有员工及老师角色，姓名/手机号复用员工信息；外部不创建账号；员工事实仍归M06 |
| 教学方向 | 老师可授课能力的原多选字段，直接引用M11采购包已有课程；课程归M11，不新增或维护独立教学方向目录 |
| 外部老师合作属性 | 老师与我司合作关系的独家/非独家标记，一份外部老师档案一项，不按渠道分别定义；M13拥有 |
| 合作渠道 | 外部老师可同时有个人和多个机构渠道；每家机构独立联系信息及参考课酬；M13拥有 |
| 人工不可用日期 | 老师整天不能安排项目的起止日期（含首尾）及必填备注/原因；M13拥有 |
| 项目占用 | M11项目开始至结束的自然日期整天占用；来自M11，不在M13重复维护项目人员或时间 |
| 教学管理范围 | admin、总裁、市场副总为全部教学管理人员、当前“师资管理部”主管为师资管理部内教学管理人员分配内部老师、外部机构渠道、外部个人渠道三项，可多选；师资管理部主管同时拥有全部三类老师的档案、渠道、课酬和排期维护权；业务对象范围归M13，角色关联归M06、模板归M07 |

## 3. 角色、可见范围和操作

| 身份 | 可见与可维护 |
| --- | --- |
| admin | 全部老师、公共资料、简历、完整联系方式、各渠道及课酬；建档、编辑、排期、启停；分配教学管理范围 |
| 师资管理部主管 | 全部三类老师、公共资料、简历、完整联系方式、各渠道及课酬；建档、编辑、排期、启停；可为师资管理部内教学管理人员分配三项教学管理范围 |
| 教学管理人员 | 只看/维护负责范围内全部老师及排期；双渠道老师的公共资料和排期共同维护，各自只维护有权渠道及课酬；没有分配范围不获得老师数据 |
| 总裁、市场副总 | 总裁、市场副总在M13拥有与admin相同的全部老师管理与排期权限：全部内部老师、外部机构/个人渠道老师；建档、编辑、启停、人工不可用维护；完整联系方式主动查看、全部渠道及课酬、简历查看/预览/下载/上传/删除；可为全部教学管理人员配置内部老师、外部机构渠道、外部个人渠道三项范围。复用原菜单和四层权限节点，模板可收紧；不授予M06员工/账号/角色维护或M11项目占用修改，原冲突及业务校验保持。 |
| 内部老师本人 | 只读本人资料和排期，可查看本人完整手机/邮箱/微信；只可新增、修改、删除本人登记的人工不可用日期；不维护公共资料或他人登记日期，不看课酬、机构渠道及简历 |
| 有权项目负责人/总监及其他原有权项目用户 | 在原项目权限内选公司全部符合条件的老师；只读公共资料及脱敏联系方式，不看简历、渠道联系信息或课酬；不取得M13维护入口 |
| 其他身份 | 不因公司/区域经营查看权自动获得老师档案管理、排期维护、完整联系方式或简历权限 |

同人兼任按其有效角色和业务范围判断；总裁、市场副总以有效角色和模板访问全部老师档案及排期，其原经营工作台默认入口保持；兼任老师不将其缩成仅本人资料或排期。师资管理部主管是按当前部门主管关系识别的M13特定配置资格，不新增系统角色；其老师档案、渠道、课酬、简历和排期维护范围固定为全部三类老师，教学管理范围配置对象仅限师资管理部内的教学管理人员。不能用项目查看权或老师身份绕过简历/渠道/费用上限。其他部门主管不因主管关系获得老师配置或维护权限，也不扩大M06人事维护权。

老师范围：内部老师对应“内部老师”；有机构渠道的外部老师命中“外部机构渠道”，有个人渠道的命中“外部个人渠道”，命中任一有权类别可访问公共资料及统一排期。外部各机构渠道属于同一“外部机构渠道”范围，不按某家机构另建管理角色。

## 4. 页面及交互

- “培训老师”分组下分为“老师管理”“老师排期”两个菜单。老师管理页面展示档案列表及原建档/详情/编辑/启停及分工操作，不混排月历或甘特图；管理者介绍“维护老师资料。”，老师本人介绍“查看个人资料。”。老师排期页面单独展示§4.1既有排期视图，介绍“查看授课与不可用日期。”。
- 老师管理沿本模块原访问资格和本人/管理范围；老师管理和老师排期均向总裁、市场副总开放，与admin同样访问全部老师并维护；不新建平行入口。老师身份的档案菜单及页名为“我的信息”，admin/总裁/市场副总/教学管理人员仍称“老师管理”；老师身份的排期菜单及页名为“我的排期”，纯老师账号默认进入该页；admin/总裁/市场副总/教学管理人员仍称“老师排期”，兼任按有效角色和原默认落地优先规则。老师个人视图的“我的排期”位于“我的信息”上方；纯老师每次登录进入北京时间本月排期，不承接上次浏览的月份或资料页。兼任管理/经营角色继续沿用原默认入口优先级。
- “我的信息”直接在页面展示本人已有姓名/来源/状态、公共教学资料及按原权限脱敏和主动查看的联系方式，无本人单行列表、详情按钮或资料抽屉；不展示排期、人工不可用记录及其维护入口，不增加资料编辑、简历、渠道或课酬权限。无本人档案时沿用空反馈。
- 管理端列表在原有权范围内筛选：姓名去首尾空格后不区分大小写包含匹配；来源（内部/外部）、授课类型（主讲/辅训/助教）、常驻省份/城市、教学方向（已有采购包课程）、状态（启用/停用）均可空单选。类型包含所选项即可，方向按课程身份匹配，不同条件同时满足。省市联动，改省清空城市；默认全部、不预选启用。“查询”应用，“重置”清空并恢复有权全量，均回分页首页。每项有常驻标签，不用综合关键词；无匹配沿用空反馈。列表操作保留已应用条件，每次登录重置；个人资料页不展示列表筛选。
- 外部老师“合作属性”为独家/非独家单选，可留空、不预设默认值；由原有权档案维护者在新增/编辑时维护，提交复核原权限/范围/版本及有效选项，失败保留输入且整体不保存。它描述老师与我司的合作关系，不是老师与某机构的签约关系，不随机构或个人渠道变化自动推断。管理列表在“老师来源”处显示外部老师的合作属性标签，未填写显示“—”；管理端老师详情显示“合作属性”。内部老师不展示标签/字段，也不保存外部合作属性；仅有项目身份的老师资料不增加此字段。只作识别标记，不改变费用、排期、项目候选/资格、既有人员安排或任何访问范围。
- 管理端列表增加“合作属性”单选筛选，默认全部，可选独家、非独家；与原筛选条件同时满足。选择任一属性只命中相应外部老师，内部或未标记者不命中；与来源“内部”同时选择时沿用无匹配反馈，不自动改写其他条件。查询/重置、操作后保留及登录重置继续沿用原列表规则。
- 老师列表展示姓名、老师来源（内部/外部）、授课类型、常驻省市、教学方向、启用/停用及操作。列表只返回有权老师，沿用通用列表分页；不新增人数、评分或经营指标。
- 有权维护者从“新增老师”建档；从操作列“详情”查看公共资料、本人有权的联系方式/简历/课酬/渠道及排期；“编辑”维护档案；姓名不再重复承担详情入口。
- 详情展示项目占用及人工不可用的起止日期，项目占用只读；无跨项目操作权者不因此获得项目详情跳转。管理端详情保留原排期及编辑/删除操作；教学管理人员身份的新增入口统一在“老师排期”，详情不再提供新增；admin、总裁、市场副总及师资管理部主管的原入口保持。老师个人端在“我的排期”同页复用本人月历及原完整安排列表，列表保留全部本人项目占用和人工不可用记录，维护动作仍只作用于本人登记项。
- 新增/编辑使用表单，字段错误保留输入并指出原因；保存成功刷新对应列表/详情。取消、右上角关闭、遮罩关闭不保存。停用/恢复及删除人工不可用经二次确认，取消不改变原值；校验失败保持原对象。
- 新增/编辑弹窗中，教学方向复用采购包课程的可搜索多选：默认收起候选，展开后按采购包名称或课程内容搜索，候选区限高滚动；已选项在候选区外完整展示并可逐项移除，搜索、收起及切换其他字段不丢选择。没有匹配结果时提示无匹配课程，不创建方向或课程。
- 外部合作渠道以紧凑列表展示机构名称或个人合作；已存在渠道默认收起，逐项展开维护原联系人/联系方式及三项课酬；添加机构或个人渠道时展开新项并收起其他项，同时仅展开一项，可折叠后继续修改其他字段。机构名称变动同步到该行标题，空名称显示“机构合作”；添加入口置于渠道列表上方，移除只影响当前草稿，最终整档保存才生效。折叠不清空输入、课酬或渠道，也不跳过校验；错误定位并展开相应区块。复用同一个老师编辑弹窗，不逐层叠加机构弹窗或新建机构档案。
- admin、总裁、市场副总从本模块维护全部教学管理人员的三项负责范围；只修改范围不改员工角色。老师教学方向由有权维护者多选M11采购包中的课程，以采购包及课程内容识别；不提供独立方向目录、方向新增/改名入口，也不为采购包增加方向配置项。
- 页面正常、空、错误、无权反馈沿用通用规则。无权字段及附件不输出，不以遮挡DOM文本代替数据权限。

### 4.1 日历与甘特图排期

- 在“老师排期”菜单内提供既有排期可视化，不再与“老师管理”的档案列表同页混排，不新建独立排课模块。内部老师使用日历，只能查看本人排期；教学管理人员可切换日历/甘特图，默认打开日历，只能查看原三项管理范围命中的老师，不因视图或筛选扩大范围。
- 总裁、市场副总从“老师排期”查看全部内部/外部老师的排期，默认日历、北京时间当前月及全部老师（筛选全选文案“全部老师”）；可单选/多选老师、切换月份及日历/甘特图，切换保留月份/筛选。日历/甘特图中的日程点击仍只读；可从老师管理进入档案维护及登记人工不可用，完整联系方式、简历、渠道和课酬按§3/7开放；项目详情及项目占用修改仍沿M11原权限。
- 教学管理人员在“老师排期”页使用“登记不可用日期”，弹窗先单选“老师 *”（默认“请选择老师”，必填），候选为当前原管理范围内且有不可用维护资格的老师，再填写原开始/结束日期；候选不受当前日历的单选/多选筛选缩小。无可维护老师或无维护权限不提供新增入口，详情不再提供新增按钮；原详情编辑/删除不迁移。保存复核当前账号、所选老师最新管理范围/维护权限、档案版本及原日期/项目冲突，选择失效或失败保留表单且不写入；缺老师提示“请选择老师”，版本/权限和冲突沿原反馈。取消/关闭不保存；成功刷新当前排期，保留月份、老师筛选及日历/甘特图视图，不打开老师资料抽屉。兼任admin、总裁、市场副总或师资管理部主管按原全局管理身份入口处理。
- 个人“我的排期”页提供“登记不可用日期”，原本人登记项编辑/删除随原安排列表一起迁入；项目及其他人登记项只读，月历点击仍只读。增改删成功刷新当前排期页并保留月份，不打开资料抽屉；原冲突拦截、版本/权限、删除确认及失败保持按§8执行。
- 默认展示北京时间当前自然月，可切换月份。教学管理人员默认展示全部负责老师，可筛选其中一名或多名；老师本人不提供他人老师筛选。未分配管理范围或范围内无老师时不返回其他老师或其安排，沿用既有空/无权反馈。
- 管理端“选择老师”使用下拉多选，触发控件保留该名称并显示下拉箭头；展开列表向下与控件左侧对齐，候选多时在列表内滚动。复用原有全选及逐位老师复选，勾选/取消立即更新当前日历或甘特图，连续选择期间列表保持展开；再次点击触发控件或点击外部收起，已选项不丢失。默认全选、可见老师范围、全选文案、空选反馈以及切月份/视图保留条件均按本节既有规则，老师本人仍无此筛选；不改变登记不可用弹窗中单选老师的交互。
- 日历按自然日期展示授课项目占用与人工不可用日期，多日安排跨天连续展示；按既有整天口径呈现，不拆成上下午或小时排课。安排横跨月份时展示其与当前月份重叠的日期，不漏掉月初前开始、月内仍持续的安排。
- 甘特图以老师为行、当前月份的自然日期为列，以连续区间展示同一老师的项目占用和人工不可用。日历和甘特图使用同一排期数据、当前月份及老师筛选；切换视图不重置月份或已选老师，不改变排期、占用或原状态。
- 点击日程只读查看对应安排的既有详情及起止日期，不在日历/甘特图中拖拽改期或修改项目人员。项目详情访问仍受M11原权限限制，无项目详情权者不能借日程进入项目详情；老师本人及管理人员可维护人工不可用的资格、入口和冲突保护按§3/8保持。
- 日程及详情不因可视化展示取得原本无权的老师联系方式、简历、渠道或课酬。项目取消/中止的占用释放、历史保留及老师启停均沿用§8/9，不在两种视图另算一套排期。

## 5. 档案字段与建档

| 字段 | 要求 |
| --- | --- |
| 老师姓名 | 必填；内部关联员工后只读复用姓名；外部填写姓名 |
| 老师来源（内部/外部） | 必填；保留内部选择已有老师角色员工、外部不关联登录账号的原关系 |
| 合作属性 | 仅外部老师适用；可留空的独家/非独家单选，不默认代填，描述与我司的合作关系；管理端标签、详情及筛选见§4 |
| 授课类型 | 必填、至少一项，可多选主讲、辅训、助教；用于项目对应人员槽位筛选，不替代内部/外部来源 |
| 常驻地 | 必填省份和城市，使用既有行政区划有效省市关系，不填详细地址；属于公共教学资料，项目选人资料可查看 |
| 简介 | 可补录；为公开教学介绍，不存放需保密的渠道或课酬 |
| 性别 | 可留空，下拉单选男、女，不自由填写；留空不自动推定 |
| 手机号、微信号 | 至少填写一项，也可同时填写；手机号填写时遵守通用手机号格式，微信号去首尾空格后须为1-64字且无控制字符；邮箱不能替代此要求。内部手机号仍只读复用M06，微信号在M13维护，不放宽M06员工手机号规则 |
| 出生日期、年龄 | 出生日期可补录，不允许未来日期；年龄按出生日期与当前北京时间计算周岁，不重复存年龄 |
| 学历 | 可留空，下拉单选高中及以下、中专、大专、本科、硕士、博士，不自由填写；留空不自动推定 |
| 简历 | 可补录附件；只允许admin、总裁、市场副总、师资管理部主管及有权教学管理人员访问，详见§7 |
| 教学方向 | 至少一门、可多选采购包已有课程；候选显示所属采购包及课程内容，复用原字段而不另增课程方向字段 |
| 邮箱 | 可选，遵守通用格式；全部联系方式按§7保护 |
| 内部老师分角色课酬 | 主讲、辅训、助教各自维护对外标准课酬和内部结算课酬，共最多六项独立参考价格，可补录；每项金额及税务口径一起填写，元/天 |
| 外部合作渠道 | 至少一个；可有个人及多个机构，机构名必填；各渠道主讲、辅训、助教三项参考课酬独立，可补录 |
| 状态 | 启用/停用；不提供物理删除；停用规则见§9 |

内部老师建档不复制员工账号，不在M13修改员工姓名、手机号或角色；这些变化继续由M06负责。角色关联本身不自动生成完整老师档案。外部同一老师的多机构/个人来源在一份档案内维护，不能以渠道拆分排期。

机构渠道字段为机构名称、联系人、联系电话、联系人微信号、联系人邮箱和主讲、辅训、助教三项独立参考课酬；仅机构名称必填，联系方式均可选。个人渠道复用老师本人的联系方式并维护三种授课类型的独立参考课酬，不重复新增一个个人老师档案。

外部老师合作属性的真实存量不依据渠道、合同以外信息或历史项目推定，未标记显示“—”，由有权维护者核实后在原档案编辑中补录，不因未标记阻断原项目或选师。Demo按当前功能提供独家/非独家及未标记样例，不实现旧数据迁移兼容。

课酬编辑及详情展示的授课类型与档案已勾选类型一致：仅选择主讲、辅训时，只展示这两类；内部老师的对外标准/内部结算，以及外部个人、各机构渠道的参考价均适用。编辑时勾选变化立即联动所有课酬区；取消勾选收起对应行、不自动清空已填写价格和税务口径，重新勾选恢复原值，保存后再次勾选仍可复用原值。隐藏行不赋予授课资格，原取消类型二次确认及已有项目保留规则仍按§6执行。

课酬按每条选择含税或不含税，金额非负、整数最多6位且最多两位小数，元/天录入格式上限为999999.99；空值表示未补录，不等于零，不根据另一条价格换算。字段名称/相邻税务选择和元/天单位共同明确口径。内部老师的对外标准课酬是对外提供师资授课的参考价，内部结算课酬是公司向内部老师支付的参考价；主讲、辅训、助教分别定价，不从一项推算另一项。外部个人及每家机构渠道分别维护主讲、辅训、助教参考价，各渠道独立。沿用原费用可见与维护权限，老师本人、仅有项目身份的用户不因类型或常驻地获得课酬查看权。本次仅维护档案价格，不在项目中记录老师课酬快照，不增加实际结算、付款、成本或毛利，不改变M11报价、项目金额及平台合作课酬。价格填写不赋予授课资格，项目按已勾选授课类型取人。

全部内部对外标准/内部结算、外部个人及各机构分角色参考课酬消费 [Shared统一产品规则](../shared/03-unified-product-rules.md) →“金额位数与单位精度（2026-11-10）”；原税务、空值/0及费用可见维护权限保持，不新增项目费用或实际结算。

## 6. 统一方向与项目选师

- 课程唯一维护来源是M11采购包内已有课程（原采购包称课程方向），不另建M13全局方向目录。老师教学方向可多选这些包内课程，同名但所属采购包不同的课程不自动合并；采购包原课程介绍、价格及生命周期保持。平台师资合作项目也先选采购包再选包内一门课程，平台公司合作课酬规则保持。
- 非框架服务培训项目单选包内课程；主讲师、辅训老师每个人的教学方向都包含该课程，助教只检查空闲。项目复用原采购包/选课项，不额外增加课程方向字段。AI软件项目仍不使用授课人员或培训方向。
- 项目主讲师槽位只选含“主讲”的老师，原辅讲师槽位统一称“辅训老师”、只选含“辅训”的老师，项目助教只选含“助教”的老师。授课类型可多选，同一档案可分别成为相应槽位候选，但跨类型仍共用同一身份及排期。候选资料显示授课类型和常驻省市；常驻地只作选师参考，不增加地区硬性限制、自动排序或改派。
- 项目人员候选只提供符合对应授课类型、启用、整段自然日期有空且适用方向匹配的老师；日期或方向不完整时提示先完成条件，不展示不受限的全部人员。
- 内部老师还须对应员工在职且具有有效老师角色；员工停用或移除老师角色后立即退出新选及替换候选，提交时再次复核，不能用旧表单继续新选；已有项目和历史按§9保留，不自动改派。
- 编辑取消授课类型时，不因已关联项目阻止保存，但必须弹窗说明并二次确认。弹窗列出当前全部已关联项目的项目名称、当前阶段及当前负责PM（平台师资合作按原生态负责人显示）；不限定未开始/进行中，不遗漏其他阶段。说明“已创建项目保留原已选人员并继续执行；后续新项目按更新后的授课类型筛选”。确认后才整体保存；返回修改、关闭或遮罩取消均不保存并保留原表单输入；没有关联项目也须确认，并展示暂无关联项目。确认提交复核权限、档案版本及关联项目清单，清单或负责人/阶段变化时重新展示后再次确认。
- 已创建项目的原已选身份不因取消类型而失效，继续按原安排执行，在原阶段可编辑操作中可保留；新增、替换或改选其他身份仍按最新授课类型筛选和提交复核。排期、方向、员工状态等原校验与阶段权限保持，项目人员、费用、评价和历史不自动改写。
- 编辑老师教学方向时，如果移除的方向仍被该老师作为主讲师或辅训老师参与的未开始（M11已立项）/进行中项目使用，阻止整个保存，提示受影响项目，保留原档案；先由项目负责人按原阶段权限更换老师或调整项目，再重新保存。所有有权管理者均不能绕过；助教沿既有规则不要求方向，不因仅担任助教阻止移除方向；已交付等历史安排不因此被重写。
- 所有M11可编辑人员入口、影响人员排期的日期变更都在保存时重新校验新增/替换人员对应授课类型（原已选身份按上条保留）及原有效性/方向/排期；排除当前项目自身占用，不能通过旧页面、变更账号、直接提交或伪造人员绕过。
- 失效或冲突的已选人员保留为待处理选择并提示原因，供移除/替换；不静默丢失已选人、不自动换人。项目阶段可编辑范围和已交付实际人员更正仍由M11拥有。
- 已有历史人员及方向快照保持，不根据重名猜测绑定老师、不自动重写旧评价。尚未绑定正式老师身份的旧人员只作历史展示，不作为新选正式老师；项目修改人员时需选正式档案。

项目字段及阶段规则见 [`M11 项目管理`](./M11-project-management.md) → §8“商业资源与快照”、§9“项目人员与排期”、§11“分阶段编辑权限”。

### 框架服务选师例外（DEC-243）

M11资源为框架服务的培训项目不选采购包课程：主讲必选，辅训/助教可选；三槽位分别按授课类型、启用状态、内部员工资格及全日期排期校验，不要求课程方向。候选、提交、原允许的人员/日期编辑一致使用该例外，排除本项目自身占用；不放宽其他培训项目方向匹配，不影响取消类型后原已选身份保留规则，不增加AI软件授课人员。移除教学方向时，未使用课程方向的框架项目不形成方向引用阻断，框架占用/日期校验仍由M11拥有。详情见 `prd-workspace/current/modules/M11-project-management.md` → §8.6“框架管理与框架服务”；验收见 `prd-workspace/current/acceptance/M13.md` → AC-M13-33。

## 7. 隐私和简历附件

- 老师手机号/邮箱/微信、机构联系人电话/微信/邮箱加密保存，页面默认脱敏。不得把页面星号视为加密保存已经完成。
- admin、总裁、市场副总、师资管理部主管及对应范围内教学管理人员可主动查看完整值；内部老师可主动查看本人完整联系方式，项目负责人/总监只看脱敏值。
- 渠道信息及课酬仅admin、总裁、市场副总、师资管理部主管和有权教学管理人员可见，先校验渠道范围再判断完整值资格。老师本人不因此获得机构联系人或课酬。
- **简历仅admin、总裁、市场副总、师资管理部主管及有权教学管理人员可查看、预览、下载和维护**；仅有项目查看身份的用户只看公共资料，内部老师本人也不单独获得简历访问权。不得用文件名链接、直达地址或附件接口绕过；不新增自动简历脱敏或公开副本。
- 简历复用 [`Shared统一产品规则`](../shared/03-unified-product-rules.md) →“附件统一规范”：图片/PDF/Office、单文件20MB、单对象9个、单次100MB；文件头/类型及扫描、受控访问等规则保持。图片/PDF在线预览，Office按既有元数据及下载表达，不继承M11大文件/全类型预览例外。
- M06组织与员工中原手机号统一脱敏规则保持；本模块完整值权限不能回流到员工列表、详情或编辑快照。

## 8. 排期和冲突

- 使用北京时间自然日期整天排期，起止日期均包含。项目在同一天上午/下午的两段授课仍冲突；跨多日项目每名已选人员在整个开始日至结束日期均占用，与计费确认天数无关。
- 项目占用和人工不可用共用同一老师身份校验，跨主讲/辅训/助教及渠道均不产生额外可用名额。所有角色无强制覆盖。
- 人工不可用新增及编辑表单增加多行文本“备注/原因 *”，所有原有权登记者均必填，包括教学管理人员和老师本人；去除首尾空白后必须非空，空值或纯空白提示“请填写备注/原因”，失败保留老师、日期和已输入内容，整体不写入。编辑回显原备注/原因，提交按本次必填规则校验。保存后的原因在原安排列表“备注/原因”列及人工不可用日程详情中展示，仅原排期可见范围内查看；本人可以只读查看管理人员为其登记的原因，原修改/删除资格不变。项目授课行该列显示“—”，月历/甘特条仍显示原安排名称。真实存量缺失原因不自动编造，保留原记录并显示“—”，后续编辑须补填；Demo使用完整新样例，不实现老数据兼容。
- admin、总裁、市场副总、师资管理部主管及有权教学管理人员维护范围内人工不可用；内部老师只维护本人登记项。登记/修改不可用与已安排项目冲突时阻止保存，提示冲突项目，先由项目负责人调整时间或人员。
- 项目候选和保存复核都检查其他项目及人工不可用，失败保持原项目/档案，不预占老师或写半条历史。
- 项目取消释放排期；中止释放后续排期、保留历史，沿用M11既有规则。已交付/完成的原授课日期只作历史，不产生新的未来占用。
- M13不改项目阶段、时间、人员，不自动取消、替换或撤销已安排项目；方向/员工状态变化与历史资料衔接不得被解释成自动改派策略。

## 9. 启停

老师有未开始（M11已立项）或进行中的授课项目时禁止停用，展示冲突项目，先由项目负责人换老师。已交付但资料/评价未齐的项目不阻断；已完成、取消、中止及原授课历史保留。停用后退出新建和替换候选；恢复后按方向/空闲重新进入候选。老师档案停用与员工账号停用分别处理，不以停用老师自动禁用员工账号，也不新增员工交接业务。

内部员工被停用或移除老师角色后，即使老师档案仍为启用，也立即退出新选/替换候选；已有项目人员安排、排期及历史保留，由项目负责人按原项目权限另行调整，不自动清除、迁移或改派。员工及账号停用仍按M06原规则立即生效，不套用“老师档案停用前须先换师”的阻断，不等待项目换人后才停用员工；本次不改变档案启停状态或增加交接流程。
