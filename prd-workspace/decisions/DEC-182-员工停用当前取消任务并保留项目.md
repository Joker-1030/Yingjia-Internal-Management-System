# DEC-182：员工停用当前取消任务并保留项目

- 日期：2026-08-29
- 状态：已确认
- 背景：完整员工停用能力应在停用时选择交接人，完成适用责任、任务和项目交接，并在不存在阻断后才允许停用；但当前各业务板块的停用交接能力尚未完整。现有 Current Rule 同时存在“停用不阻断且任务保留”和“M11 项目未交接时阻止停用”两种相反表达，无法形成唯一当前结果。
- 决策：
  1. 当前阶段员工停用仍由 HR/人事或 admin 填写原因并确认后直接生效，不选择交接人，不执行待办、责任或项目阻断校验，不建立 M04 审批、WF 编号、审批待办或抄送。
  2. 员工、账号和会话停用，与该员工当前全部未完成 M03 任务取消同次生效。取消记录保留稳定编号、原执行人、停用原因、实际操作人、时间和员工停用关联；任务不伪记完成、不物理删除、不逐条建立取消审批。
  3. 部门主管、区域/地市和客户当前责任继续清空；部门成员关系、系统角色和当前审批节点继续保留。审批处理人失效仍由 M04 按既有规则暂停并受控替换。
  4. 员工名下项目继续保留，项目主阶段和项目并行待办不因员工停用自动取消。当前停用本身不迁移项目负责人，也不把项目当作 M03 任务级联取消。
  5. M08 主动地区交接或直接调整继续同步迁移该地区全部适用项目负责人，并保持地区责任与项目负责人原子生效；该规则不再作为当前员工停用的前置阻断。
  6. 员工恢复不恢复停用时已取消的任务，不自动取回已清空责任，也不改变保留项目的阶段。
- 完整版本边界：完整员工停用必须选择交接人，完成适用责任、任务和项目交接，并在不存在阻断后才允许停用。该能力不属于当前版本，不得据此在当前 Prototype 新增交接人字段、停用阻断、审批、待办或业务状态。
- 替代关系：替代 DEC-165 第 6-7 项中“未完成任务保留原员工、任务不自动关闭/清空/改派及恢复后继续保留”的任务结果；替代 M11 第 14 节、AC-M11-33、AC-F004-15 和 FLOW-16 中“未完成项目交接阻止当前员工停用”的表达。DEC-165 的直接停用/恢复、责任清空、部门成员与角色保留及审批处理人失效规则继续有效；DEC-175 的主动地区交接同步项目、失败整体阻断和禁止单项目转交规则继续有效。
- 未采用方案：当前继续保留停用员工的未完成任务；当前停用自动取消项目；当前停用自动选择或猜测交接人；仅取消任务但允许员工、账号或责任出现部分生效。
- 原因：当前阶段保持停用入口可执行，同时明确结束停用员工的未完成任务责任；项目是独立业务对象，不能被当作任务级联取消。完整交接能力留待各板块具备统一交接条件后上线。
- 决策人：Product Owner
- 影响范围：M03、M06、M08、M11、Acceptance、User Flow、Shared、Glossary、Product Boundary、Prototype
