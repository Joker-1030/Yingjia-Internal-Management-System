# FLOW-09 M04-approval-lifecycle

- 原始行：2526
- 原始最近标题：F1 通用审批实例生命周期与动作
- 迁移方式：Mermaid block mechanical copy
- 当前定位：主体为 Current Mechanical Evidence；`业务处理失败 -> 可关闭` 分支为 Historical / Replaced。Current Rule 保持审批结论“已通过”，业务对象可保持原状态，仅 admin 接收提醒并执行受控重试，不新建审批、不形成普通业务待办、不改为驳回（DEC-163）。

```mermaid
flowchart TD
    A[发起申请] --> B{是否直接生效动作?}
    B -- 是 --> C[生成已通过实例并回调业务<br/>admin即时分配/总裁发起停用等]
    B -- 否 --> D[待接收/待审批]
    D --> E{处理动作}
    E -- 通过 --> F{还有下一节点?}
    F -- 是 --> D
    F -- 否 --> G{有计划生效日?}
    G -- 无 --> H[立即回调业务生效]
    G -- 有 --> I[已通过待生效]
    I --> J{到达生效日且校验通过?}
    J -- 失败 --> K[业务处理失败<br/>可幂等重试或关闭]
    J -- 通过 --> H
    E -- 驳回 --> L[已驳回,业务恢复申请前状态]
    D -- 首人未处理时撤回 --> M[已撤回]
    E -- 转交 --> N[当前节点转给新处理人<br/>原应处理人保留审计]
    E -- 动态加签 --> O[当前节点前插入会签人]
    D -- 追加抄送 --> P[抄送人只读可见]
    E -- 管理员代办 --> Q[必须填代办原因<br/>保留原应处理人]
    D -- 处理人失效 --> R[替换处理人<br/>生成替换记录]
```
