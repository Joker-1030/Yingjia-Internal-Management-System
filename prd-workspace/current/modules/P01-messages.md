# P01 消息中心与待办

- 文档状态：Supporting Product Facts（Current）；不作为独立 PRD Source of Truth
- 功能范围：F013
- 原始事实章节：旧完整 PRD 第 1121-1169 行

## 模块目标

- 提醒用户已经发生的任务、客户变动、项目事项和系统异常
- 提供分类筛选、未读状态和受控业务跳转

## 用户角色

- 总裁、市场副总、区域总监、PM、HR/人事：本人消息
- 系统管理员：本人消息及当前定义的系统异常告警

完整数据范围、字段权限、直接访问和管理员约束统一引用 [角色、权限与数据范围](../shared/01-roles-permissions-and-data-scope.md)，本节不扩大该矩阵。

## 核心对象

- 消息
- 消息分类
- 未读状态
- 受控动作链接
- 项目提醒事件
- 商机跟进与方案支撑提醒事件

## 页面说明

本模块的当前页面范围：

- 消息浮窗
- 消息抽屉
- 侧栏未读数字角标：1-99 显示实际数量，超过 99 显示 `99+`

消息抽屉只提供“消息分类”和“未读状态”两个筛选项，均使用常驻可见字段标签；每项只匹配自身字段并继续受本人消息范围约束。

消息分类固定为六类：`任务`、`项目`、`商机`、`客户变动`、`责任交接`、`系统异常`。其中`客户变动`包含关键人、客户公司、集团和客户部门的已定义停用/恢复等结果。分类筛选默认显示`全部`，未读状态筛选独立，不增加其他消息分类。

## 功能列表

- 提醒用户已经发生的任务、客户变动、项目事项和系统异常
- 提供分类筛选、未读状态和受控业务跳转
- 未读消息项同时展示红点和未读状态；已读消息不展示未读红点。
- 打开消息浮窗只加载最新消息，不自动把全部消息标记已读。
- 点击一条消息或对该条执行明确已读动作时，只将该条标记已读，并同步侧栏数量、消息红点和未读状态。
- “全部已读”在同一结果中清除当前账号全部未读数量、红点和未读状态。
- AI 软件项目到期未确认交付时，到期立即及此后每天提醒项目负责人；逾期满 3 天后同时每天提醒区域总监；确认交付、取消或中止后停止。
- 培训项目已交付但资料或评价未齐时，立即及此后每天提醒项目负责人；满 3 天后同时每天提醒区域总监；项目完成、取消或中止后停止。
- 已中止项目不再产生项目推进提醒；仅在中止时确认涉及金额结算后保留`待回款`只读提醒。
- 项目提醒失败不回滚项目阶段；提醒不自动成为 M01 待办，是否进入待办由 M11/M01 的可处理责任规则决定。
- 项目进入`已交付`、`已完成`、`已取消`或`已中止`时只在项目页面及历史保留状态结果，不生成普通项目结果消息；AI 项目到期未确认交付、培训项目资料或评价待补齐提醒及项目责任交接消息按各自规则继续。
- 商机到达下次跟进日期当日上午提醒负责人；次日起每日一次，逾期满 3 个自然日时同步所属区域总监，新增有效跟进后停止旧承诺提醒。
- 方案支撑取消首次回应超时判断与节点消息；交付截止时间由 M12 维护，本次不因此新增交付逾期通知。
- 商机提醒失败不回滚 M12 商机、跟进、支撑或阶段事实；消息不产生审批关系或新的业务状态。
- 凡当前产品明确要求生成的系统异常消息，接收人统一为唯一内置`admin`。当前只包括节假日日历定时同步失败和实际自动恢复成功；区域配置异常只在 M08 区域页面显示，未定义的任务偏差、专项、调度或运行异常不自动生成消息，待完成产品确认后再增加。
- 当前不生成审批待办、目标责任人接收待办、审批抄送或审批结果通知；责任交接类消息仅覆盖已确认的关键人调岗、PM 停用后的地市交接、区域总监停用后的区域交接、地市负责人直接调整、项目负责人迁移、商机负责人改派、方案支撑人员改派和员工停用后的任务交接，均只发送来源模块已定义的业务结果消息，未列出的责任交接不自动发送。
- 任务延期实际成功后，本人操作只显示页面结果，不另发站内消息；admin 代办仅向实际任务执行人发送一次结果消息，只说明任务及调整后的截止时间，不向主管广播。执行人本身为区域总监时仍按执行人身份接收；失败或取消确认不发成功消息，重复提交不重复通知，通知失败不回滚延期。延期资格与成功事实由 [M03 维系管理](M03-maintenance.md) §6.3“完成、延期、暂停、取消与补录”维护；本条仅定义延期结果消息。
- 任务暂停实际成功后，本人操作只显示页面结果，不另发站内消息；admin 代办仅向实际任务执行人发送一次结果消息，只说明任务及“暂停至”日期，不向主管广播。执行人本身为区域总监时仍按执行人身份接收；失败或取消确认不发成功消息，重复提交不重复通知，通知失败不回滚暂停。暂停资格和结果由 [M03 维系管理](M03-maintenance.md) §6.3“完成、延期、暂停、取消与补录”维护。暂停期间仍停止既有任务提醒，本条只定义本次暂停成功的结果消息；自动恢复及节令暂停越期关闭消息见下文。
- 暂停任务到期并实际恢复待执行后，不另发“已恢复”消息，无论原暂停由本人还是 admin 操作；原任务/待办继续承接，不创建重复任务。后续仍按各类型现行当前截止、提醒节点和接收范围发送任务提醒，不能将“不发恢复消息”解释为停止后续提醒。恢复和截止规则见 [M03 维系管理](M03-maintenance.md) §6.3“完成、延期、暂停、取消与补录”；自动关闭不是恢复，节令暂停越期关闭按下条处理。
- 生日/节假日任务在暂停期间越过当前截止而实际自动关闭后，不向执行人、admin 或主管另发关闭消息，无论原暂停由本人还是 admin 操作。保留关闭结果、原因和历史，不再进入待办；不删除任务，不改变既有统计排除及关闭条件。规则由 [M03 维系管理](M03-maintenance.md) §6.3“完成、延期、暂停、取消与补录”维护，仅适用于节令暂停越期关闭，不扩展到其他来源的取消/关闭。
- 主动取消任务实际成功后，本人操作只显示页面结果，不另发站内消息；admin 代办仅向实际任务执行人发送一次结果消息，只说明任务已取消及取消原因，不向主管广播。执行人本身为区域总监时仍按执行人身份接收；失败或放弃确认不发成功消息，重复提交不重复通知，通知失败不回滚取消。取消资格及成功事实由 [M03 维系管理](M03-maintenance.md) §6.3“完成、延期、暂停、取消与补录”维护；本条不套用于自动关闭、客户停用级联或员工停用交接，各来源已定义的通知边界保持。
- 正常完成任务实际成功后，本人操作只显示页面结果，不另发站内消息；admin 代办仅向实际任务执行人发送一次结果消息，只说明任务已完成，不向主管广播。执行人本身为区域总监时仍按执行人身份接收；失败或重复提交不发/重复成功消息，消息失败不回滚完成。完成资格、记录、认定与续期由本节既有规则维护；逾期补录和逾期补完成分别按下列规则处理。
- 逾期补录实际成功后，本人操作只显示页面结果；admin 代办仅向实际任务执行人发送一次结果消息，说明补录已完成及认定结果，不向主管广播；执行人身份规则和通知失败不回滚沿用。
- 逾期补完成实际成功后，本人操作只显示页面结果；admin 代办仅向实际任务执行人发送一次结果消息，说明补完成及认定结果，不向主管广播；失败或重复提交不发/重复成功消息，消息失败不回滚补完成。
- 员工停用为接收人建立新 M03 执行项并实际交接成功后，仅向新执行人发送交接结果消息。单项说明任务名称、客户名称、当前截止时间和“员工停用交接”来源；同一成功责任组向同一新执行人交接多个任务时合并为一条，说明交接任务数和来源，不逐任务重复广播。旧执行项关闭不发送逐条关闭消息；规则见 [M06 组织与员工](M06-organization.md) §5“员工停用”第11条和 [M03 维系管理](M03-maintenance.md) §6.3。

- 关键人调岗实际生效成功后，通知调岗前后对应业务负责人及涉及区域总监，不默认通知总裁、市场副总；只表达关键人、原新单位/岗位和生效时间，不展示后台处理。触发与接收范围由 [M02 客户经营](M02-customer.md) §6.6“调岗并发、生效与失败保护”维护。
- 关键人由 admin 停用/恢复实际生效成功后，通知其所在客户公司的客户负责人及所属区域总监；省级客户的客户负责人是所属区域总监，市级/区县级客户的客户负责人是对应地市 PM，同一员工重复命中时只收一条。消息不向总裁/市场副总广播，仅说明关键人、客户单位、停用/恢复结果及生效时间，不展示后台处理，见 [M02 客户经营](M02-customer.md) §3.5“关键人停用/恢复表达”；同次集团或客户公司停用级联结果不另发逐关键人消息。
- 以客户公司为操作对象由 admin 停用/恢复实际成功后，通知该公司客户负责人及所属区域总监；客户负责人使用上述省级区域总监、市级/区县级地市 PM 映射，同一员工重复命中时只收一条。消息不向总裁/市场副总广播，仅说明客户公司、结果及生效时间，不展示后台处理，见 [M09 客户基础配置](M09-settings.md) §5“客户组织树停用与恢复边界”。单独停用公司时每位接收人只收一条公司结果消息，同次联动停用关键人不另发逐人通知；单独操作关键人仍正常通知。同次集团级联不另发逐公司消息。
- 集团停用/恢复实际成功后通知相关客户公司的客户负责人及涉及区域总监，客户负责人使用上述角色映射；同一员工通过多个客户或角色重复命中时，每位接收人只收一条集团结果消息，同次级联不重复发送公司或关键人通知。消息只说明集团、结果及生效时间，不向总裁/市场副总广播，不展示后台处理，失败不发成功消息且访问权不扩大。恢复集团不自动恢复下级，后续独立操作仍按各自规则通知；见 [M09 客户基础配置](M09-settings.md) §5“客户组织树停用与恢复边界”。
- 客户部门停用/恢复实际成功后通知该公司客户负责人及所属区域总监，客户负责人沿用上述角色映射；同一员工重复命中时，每位接收人只收一条部门结果消息。内容仅包括客户公司、客户部门、结果及生效时间，不向总裁/市场副总广播，不展示后台处理；停用联动影响的关键人、任职或任务不逐项发送消息，失败不发成功消息。恢复部门不自动恢复下级对象或已关闭任务；见 [M09 客户基础配置](M09-settings.md) §5“客户组织树停用与恢复边界”。
- 行业停用/恢复只在 M09 当前页面向操作人 admin 显示操作结果，不生成站内消息，不通知相关集团、客户负责人或区域总监；停用只退出新增集团和普通筛选候选，存量集团、客户公司及历史引用保持，恢复后重新进入候选，见 [M09 客户基础配置](M09-settings.md) §5“客户组织树停用与恢复边界”。
- 标准关键人岗位停用/恢复只在 M09 当前页面向操作人 admin 显示操作结果，不生成站内消息；停用仍须满足无有效任职或进行中覆盖 KPI 引用，恢复仅重新开放为后续候选，见 [M09 客户基础配置](M09-settings.md) §5“客户组织树停用与恢复边界”。
- admin 保存职级维系周期及提醒配置后，仅在 M09 配置页面反馈，不因配置修改向任何角色另发站内消息；实际任务提醒继续按既有生效规则执行。配置保存及生效边界见 [M09 客户基础配置](M09-settings.md) §5“页签一保存与生效”。
- 生日/节假日规则内容修改、启用或停用均只在 M09 当前页面向操作人 admin 显示结果，不生成站内消息。普通内容修改仅影响后续新任务，已有任务快照不变，实际任务提醒按既有规则执行。停用后不投递尚未发送的规则提醒；重新启用后只发送启用后符合节点的后续提醒，不补发停用期间错过的提醒，也不因启停额外广播；任务生成与已生成任务边界由 [M09 客户基础配置](M09-settings.md) §6“规则字段”和 [M03 维系管理](M03-maintenance.md) §6.2“任务生成与规则快照”维护。
- 员工停用、恢复不单独发送站内通知，不向业务人员广播员工状态；既有操作结果反馈保持。PM 停用后的地市交接、区域总监停用后的区域交接及成功建立新任务的交接分别按已确认规则通知；其他责任交接按上文列出的来源事件规则执行，未定义的新交接仍需逐项确认，见 [M06 组织与员工](M06-organization.md) §5“员工停用”第9-11条。
- PM 停用后，每个地市交接成功通知新接收 PM 及所属区域总监，内容为地市、原/新负责人和实际生效时间；已停用人员不接收，失败交接不发成功消息。规则由 [M06 组织与员工](M06-organization.md) §5“员工停用”第9条维护。
- 区域总监停用后，每个区域交接成功通知新接收区域总监及市场副总，内容为区域、原/新负责人和实际生效时间；已停用人员不接收，失败交接不发成功消息。规则由 [M06 组织与员工](M06-organization.md) §5“员工停用”第10条维护。
- 覆盖 KPI 在有效期内失去达标条件时，只重新打开原执行项/待办，不发送重新打开消息；恢复达标后自动完成，不新建重复任务，见 [M03 维系管理](M03-maintenance.md) §6.6“关键人覆盖 KPI 字段与口径”。
- 新专项正式发布后通过 M03 既有执行任务/责任人待办承接，不另行发送专项发布消息，见 [M03 维系管理](M03-maintenance.md) §6.4“专项通用字段”；不把消息复制为新的待办对象。
- 地市负责人直接调整成功后，通知原任、新任及该地市所属区域的区域总监；接收范围由 [M08 区域中心与地市配置](M08-region.md) §8.3“直接调整”维护。
- 数据导入当前延期，暂不提供模板、批次或异步导入功能；后续采用人工导入，本次不生成导入结果消息。既有批量导入设计只作 Deferred / Historical Evidence，不作为当前产品行为，见 [M10 数据导入](M10-import.md)“当前范围状态”。
- 区域配置异常只在现有区域页面展示状态与具体原因，不发送站内异常通知；修复后仅更新页面状态，不发送“已恢复”消息，既有影响保护、恢复处理和记录保持，见 [M08 区域中心与地市配置](M08-region.md) §7.2“区域配置状态”。
- 节假日日历手动同步成功只在 M09 当前页面向操作 admin 显示结果，普通定时同步成功保持静默，两者均不生成站内消息；定时同步失败后自动恢复成功是例外，仅向 admin 发送一次恢复通知，其他角色不接收，同次恢复重试或后续连续成功不重复发送。admin 手动重试成功只在页面反馈，不发送恢复通知；同步失败仍仅向 admin 发送系统内告警，不向总裁、市场副总或其他业务角色发送。同一故障首次同步失败仅向 admin 发送一次告警，持续失败及同一故障重试不重复发送；只有实际同步恢复成功后再次失败，才作为新一轮故障重新告警。手动重试和自动同步实际成功均可结束本轮故障，不以是否发送恢复通知作为判断依据；仅使用旧版本降级不属于恢复。降级与暂停规则由 [M09 客户基础配置](M09-settings.md) §6“年度节假日日历”维护。

## 消息产生、展示与受控跳转

### 产生边界

- 只有 Current PRD 明确定义的业务结果、到期提醒、逾期升级和系统异常才生成站内消息。消息是来源业务事实的结果表达，不创建新的任务、审批、状态或权限。
- 任何操作只有在业务事实实际成功后才生成成功消息；失败、取消确认、重复提交和仅页面反馈不生成成功消息。消息投递失败不回滚已生效的业务事实，按消息服务的重试规则处理。
- 同一业务事件向多个接收人发送时，每位接收人各自保留一条，不在消息正文展示接收人名单；同一接收人同一事件只保留一条。

### 消息卡片和列表

- 消息卡片只展示消息分类、标题、必要的结果摘要、来源模块名称、发生时间、未读样式和在当前权限下可用的操作按钮。详情事实保留在业务目标页面，消息中心不复制完整业务详情。
- 消息时间统一按北京时间展示：当天为`今天 HH:mm`，前一天为`昨天 HH:mm`，更早为`YYYY-MM-DD HH:mm`；列表按发生时间从新到旧排列。
- 未读消息只使用未读红点和未读样式，不单独置顶。打开浮窗不自动全部已读；点击单条消息先将该条标记为已读，再尝试跳转；跳转失败仍保持已读。点击“全部已读”只影响当前账号当前可见消息。
- 消息不提供删除操作，消息作为业务结果记录保留。无消息时显示`暂无消息`；消息列表加载失败时显示失败原因和“重试”，不生成失败消息。
- 目标页面加载失败时保留原消息内容并标记本条已读，页面提示无法打开目标；不修改原消息正文，不把加载失败另造为业务消息。
- 目标对象已经失效时保留原消息正文，在卡片底部显示`该内容已失效`，不显示操作按钮。消息跳转不自动展开子对象、历史、附件或其他下钻内容。

### 摘要格式

- 任务结果：`任务：{任务名称}；结果：{结果}；时间：{发生时间}`。延期追加新截止时间，暂停追加“暂停至”日期，取消追加取消原因，逾期补录/补完成追加认定结果。
- 责任交接：`对象：{对象名称}；原负责人：{原负责人}；新负责人：{新负责人}；生效时间：{时间}`；同次迁移多个项目时追加`受影响项目：N 个`，不逐项展开后台迁移过程。
- 员工停用任务交接：单项展示任务名称、客户名称、当前截止时间和`员工停用交接`；同组同一新执行人的多项合并结果展示`已交接任务：N 项；来源：员工停用交接`，具体任务事实仍在维系管理查看。
- 客户对象停用/恢复：`对象：{对象名称}；结果：{停用/恢复}；生效时间：{时间}`；发生级联时追加已确认的`受影响范围：N 人`或相应公司/关键人数，不逐项列出后台处理。
- 系统异常：`对象：{对象名称}；异常：{异常原因或结果}；发生时间：{时间}`。不展示技术错误码、接口、数据源或后台处理过程。
- 项目待处理：`项目：{项目名称}；事项：{待确认交付/资料或评价待补齐}；发生时间：{时间}`。
- 商机跟进或方案支撑：`商机：{商机名称}；客户：{客户名称}；事项：{提醒/支撑结果}；时间：{时间}`。

### 合并、去重与无消息边界

- 同一公司停用及其联动关键人停用合并为一条公司结果消息，显示受影响范围数量，只保留一个进入公司详情的按钮；同一集团级联公司和关键人合并为一条集团结果消息，显示受影响公司数和关键人数，进入集团详情；同一部门级联关键人、任职或任务合并为一条部门结果消息，显示受影响范围数量，进入部门详情。
- 一次员工停用涉及多个城市或区域时，按每个成功交接的城市/区域各发一条；不得把不同责任组压成一条总消息。失败责任组不发成功消息。
- 同一次员工停用，在一个成功责任组向同一新执行人交接多个任务时，每位新执行人收一条合并结果；不同责任组不合并，失败组和旧执行项关闭不发成功消息。
- 同一次地区责任交接或员工停用交接中，多个项目随同一责任组迁移时，按同一接收范围合并为一条项目结果消息，显示受影响项目数量和共同的原负责人、新负责人及实际生效时间；不按项目逐条重复发送。不同责任组仍分别发送，失败责任组不发送成功消息。
- 同一任务分别成功延期、暂停、取消时，每次成功操作各发一条；第一次成功后重复提交不再发送第二条。失败与成功结果不合并。
- 自动关闭、客户停用级联关闭任务、员工停用关闭旧任务、专项结束关闭执行项、客户或关键人失效导致任务关闭，均不逐任务发送关闭消息；保留来源页面的原因和历史。
- 覆盖 KPI 失去达标条件时只重新打开原待办，不发送消息、不创建重复任务；恢复达标后自动完成。新专项发布直接进入责任人既有待办，不另发发布消息。
- 项目进入`已交付`、`已完成`、`已取消`或`已中止`不生成普通结果消息；已定义的到期未确认交付、资料/评价待补齐提醒及项目责任交接消息不受影响。
- 区域配置异常及修复只在区域配置页面显示，不生成站内消息；生日/节假日规则编辑或启停、行业及标准关键人岗位停用/恢复、职级周期和提醒配置保存只在来源页面反馈，不另发消息。

### 用户不可见内容

消息正文和按钮不展示系统重算、匹配、权限判断、日志写入、接口、数据库、技术错误码、内部 ID、处理步骤或面向 PM/研发的说明。后台规则用于保证消息结果正确，不自动成为用户需要阅读的前端内容。
