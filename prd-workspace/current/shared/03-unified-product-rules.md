## 附录 A：正式产品统一规则

本附录描述正式产品研发必须遵守的统一字段、安全、附件、错误和审计规则。产品菜单评审时可以后置阅读；Demo 不需要实现并发、幂等、服务超时、锁定计数或真实文件安全扫描，只需演示对应页面状态和提示语。

### 术语通俗速查

本表只解释“字面不好懂”的技术与业务词，完整业务术语以 `../GLOSSARY.md` 为准。

| 词 | 通俗解释 |
| --- | --- |
| 幂等 / 幂等键 | 同一个操作重复提交（比如网络卡了连点两次）只算一次，系统不会生成两份重复数据；幂等键就是用来识别“这是同一次操作”的凭证 |
| 乐观并发 / 版本冲突 | 两个人同时打开同一条数据修改，先保存的成功，后保存的会收到“数据已被他人修改”提示，必须刷新后基于最新值重新确认，不会悄悄覆盖别人的改动 |
| 责任快照 | 任务或审批生成时记下“当时”的负责人；之后人员调动不改写历史记录，保证追溯时能看到当时的真实责任人 |
| 数据范围 | 这个账号能看见哪些客户数据：公司全局 / 全国市场 / 本区域 / 负责地市 / 公司组织，由角色和区域地市责任计算，不能手工指定 |
| 写入来源 | 这条数据当初怎么进系统的：手工录入 / 批量导入 / AI 辅助 / 系统生成，用于审计追溯 |
| 疑似重复 | 导入时与已有数据可能重复的行（如手机号相同），默认跳过不写入，由人工核对后决定 |
| 规则版本快照 | 任务生成时把当时的规则（周期、宽限天数、标题）抄一份存在任务上；之后改规则只影响之后生成的任务，已生成的不再变 |
| 责任型审批 | 审批节点必须由“按责任关系算出来的人”处理，不能随便转给无关人员 |
| 回调 | 审批通过后系统自动去执行的业务动作（如迁移客户负责人、关闭任职），回调失败进入业务处理失败并可重试 |
| 原子 / 同一业务操作 | 原子范围必须由所属业务规则明确。M10 数据导入固定为单行原子：每行独立成功或失败，失败行不回滚其他成功行；同一行对应业务对象不得形成产品事实半成品。不得把“原子”默认扩张为整个批次或工作表。其他模块继续按各自已确认范围读取 |
| 字典 / 候选 | 下拉框里可选的合法值集合（如标准岗位、行业、区划），只能从里面选，不能自由输入 |
| 会签 | 一个节点需要多个人都处理后才算过；预设会签是流程定义时就固定的，动态加签是审批中临时增加的 |
| 抄送 | 不参与审批、但需要知道结果的人；抄送人只能看不能操作 |
| 代办 | 管理员代替当前处理人处理节点，必须填写代办原因，且保留原应处理人记录 |
| 脱敏 | 敏感字段（如手机号）对无权角色显示部分内容（前 3 后 4 位） |
| 计划生效日 | 审批通过后不立即生效、等到指定日期才生效；生效前再次校验数据是否仍然合法 |
| 逐级上溯 | 找审批人时，本部门没有有效主管就找上一级部门主管，一直找到总裁兜底 |

### 字段与文本规范

除功能字段表另有规定外，执行下表。长度按 Unicode 字符数计算，不按字节计算；保存前去除首尾空格，将连续空白压缩为一个普通空格，长文本保留换行但去除每行行尾空格。

| 字段类别 | 存储建议 | 长度/格式 | 规则 |
| --- | --- | --- | --- |
| 稳定 ID | `char(36)` | UUID | 服务端生成，不允许客户端指定或修改 |
| 独立业务编号 | `char(10)` | `^[A-Z]{2}[0-9]{8}$` | 关键人、父任务、审批流程在正式对象持久化时由服务端原子生成；对象前缀固定，用户只读，永久不回收 |
| 子级业务编号 | `char(17)` | `^MT[0-9]{8}-[0-9]{6}$` | 任务执行记录使用；前 10 位完整等于父任务编号，后 6 位在父任务内原子递增，用户只读，永久不回收 |
| 名称 | `varchar(100)` | 2-100 字 | 不允许仅空白、控制字符或 HTML 标签 |
| 人员姓名 | `varchar(50)` | 2-50 字 | 允许中文、少数民族间隔点和英文字母；不允许数字与特殊符号 |
| 编码/工号 | `varchar(32)` | 2-32 字；`^[A-Za-z0-9][A-Za-z0-9_-]{1,31}$` | 大小写不敏感唯一；展示保留录入值 |
| 手机号 | `varchar(11)` | `^1[3-9][0-9]{9}$` | 不允许空格或国家码；需要脱敏的列表显示前 3 后 4 位 |

关键人手机号固定隐私上限：列表、详情、编辑表单、审批快照和操作日志对全部角色统一脱敏，不显示明文。M07 字段权限只能进一步收紧，不能放宽该上限。
| 微信号 | `varchar(64)` | 1-64 字 | 去首尾空格；禁止控制字符 |
| 邮箱 | `varchar(254)` | 1-254 字；`^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,63}$` | 整体按小写值做唯一性比较，展示保留录入值 |
| 标题 | `varchar(100)` | 2-100 字 | 不允许纯标点或纯空白 |
| 职务 | `varchar(100)` | 1-100 字 | 允许中文、英文、数字及常用括号 |
| 短原因 | `varchar(500)` | 5-500 字 | 驳回、停用、延期、取消、转交和管理员代办使用 |
| 备注 | `varchar(500)` | 0-500 字 | 非必填时空字符串转为 `null` |
| 业务描述 | `text` | 5-2000 字 | 支持换行；前端显示剩余字数 |
| 日期 | `date` | `YYYY-MM-DD` | 无时分秒 |
| 日期时间 | `timestamp` | `YYYY-MM-DD HH:mm:ss`，精确到秒 | 数据库存 UTC，界面与业务计算使用 `Asia/Shanghai`；业务比较先转换到同一时区并截断小数秒，不四舍五入，页面、接口和验收均不使用毫秒边界 |
| 布尔值 | `boolean` | 是/否 | 必填布尔字段不得用 `null` 表示否 |
| 排序值 | `smallint` | 1-9999 | 越小越靠前；同值按名称、稳定 ID 排序 |

必填下拉必须提交稳定 ID，禁止提交展示文本。前端校验用于即时反馈，服务端必须重复执行全部必填、长度、枚举、范围、唯一性和状态校验；服务端结果为最终依据。

### 用户界面信息边界

- 业务页面只展示用户完成当前操作、理解业务状态或处理异常所需的信息。不得仅为解释实现而展示内部自动/人工来源、后台处理机制、内部版本标识、规则引擎细节或系统维护说明。
- 系统内部来源、自动维护、版本、并发、审计、快照和权限计算规则继续作为实现与追溯事实保留；从页面移除说明不代表删除或放松这些规则。
- 必须保留用户完成操作所需的字段约束、候选范围、权限边界、保存后果和二次确认；必须保留可操作的校验失败、配置异常具体原因、安全警告、业务影响、恢复指导和业务状态结果。
- 全局清理类似说明时必须先做用户可见文案清单并逐项判断；不得机械删除帮助用户正确提交、识别风险或恢复异常的信息。

### 密码与登录安全

- 密码长度 12-64 位，至少包含大写字母、小写字母、数字、特殊字符四类中的三类，不得包含手机号连续 6 位或工号完整值。
- 最近 5 次密码不得复用；密码在传输和日志中不得明文出现。
- 只有“验证码正确、手机号命中正常账号、密码错误”才计入该账号连续密码失败次数；验证码错误/过期、手机号不存在、账号不可用、账号已锁定或请求异常均不计次。连续 5 次密码错误后锁定 30 分钟；成功登录或锁定到期清零，锁定期间即使密码正确也不能登录。
- 初始密码和系统管理员重置密码均由系统生成符合复杂度的密码，不设有效期且不强制首次/下次登录修改。系统管理员点击“重置密码”后立即完成重置，不手工输入新密码、不填写重置原因；成功弹窗展示已重置密码，右下角“复制并关闭”复制成功后关闭。员工本人主动修改前，当前系统生成密码对 HR/人事在员工详情持续可见；本人修改后任何角色不可见修改后的密码。密码明文只允许在签发展示和该 HR 查看入口出现，不进入日志。再次重置后旧密码永久失效；重置入口仅系统管理员可见（DEC-158、DEC-166）。
- 修改密码成功后撤销该账号其他会话，当前会话重新签发；重置密码立即撤销全部会话。
- 登录会话连续闲置 30 分钟失效，单次登录无论是否持续操作最长 12 小时；失效后清除本地业务缓存并返回登录页。系统不按固定周期强制修改密码；本期初始密码和管理员重置密码也不触发强制修改。安全风险事件后的强制改密能力留待后续统一安全版本设计。

### 附件统一规范

| 类型 | 允许扩展名 | 允许 MIME |
| --- | --- | --- |
| 图片 | `.jpg`、`.jpeg`、`.png` | `image/jpeg`、`image/png` |
| PDF | `.pdf` | `application/pdf` |
| Word | `.doc`、`.docx` | `application/msword`、`application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| Excel | `.xls`、`.xlsx` | `application/vnd.ms-excel`、`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| PowerPoint | `.ppt`、`.pptx` | `application/vnd.ms-powerpoint`、`application/vnd.openxmlformats-officedocument.presentationml.presentation` |

- 原始文件名 1-200 字；单文件不超过 20 MB；单个业务对象最多 9 个；单次提交附件总大小不超过 100 MB。
- 扩展名、声明 MIME 和文件头必须一致；拒绝可执行文件、脚本、宏文件、压缩包、加密文件、零字节文件及使用双扩展名伪装的文件。
- 上传完成且安全扫描通过后才返回可提交的附件 ID；扫描或对象存储不可用时上传失败，表单其他内容保留。
- 图片和 PDF 支持在线预览；Office 文件在本期预览面板中展示文件名、类型、大小和上传人，并提供下载，不承诺在线解析内容。
- 删除只解除当前业务对象关联并写审计，不物理删除仍被其他审计记录引用的文件。
- 预览、下载、删除每次重新校验父业务对象权限；下载使用 5 分钟有效的单次签名地址，不把永久对象地址返回前端。
- 未提交表单的临时附件保留 24 小时后清理；正式附件的保留周期跟随父业务对象。

### 列表、筛选与页面反馈

- 普通列表默认每页 20 条，可切换 20/50/100，服务端单页最大 100；页码从 1 开始。
- 默认按 `创建时间倒序 + 稳定 ID 倒序`，责任配置和树形对象按排序值、名称、稳定 ID 升序。
- 关键词最大 100 字，按名称、编码或功能表明确列出的字段模糊匹配；必须转义通配符，禁止前端拼接查询语句。
- 同一筛选维度多选取并集，不同维度取交集；“重置”恢复当前角色授权范围全量，不扩大权限。
- 首次加载超过 300 ms 显示骨架或加载状态；普通读取 10 秒无响应显示超时和“重试”，写入 15 秒无响应后查询幂等结果，不能直接重复创建。
- 区分“当前范围无数据”和“筛选无结果”；无权限显示 403 状态，不使用空白页面代替。
- 字段错误显示在字段下方并聚焦首个错误；全局错误保留表单、已上传附件 ID 和用户选择。

### 并发、幂等与一致性

- 可编辑主对象包含整数 `version`。更新、状态变化和审批处理必须携带读取时版本；版本不一致返回 409 和最新摘要，不覆盖他人修改。
- 新增、导入确认、审批处理、任务完成、任务生成、调岗重算和通知发送使用 `Idempotency-Key` 或等价唯一键；同键同参数返回首次结果，同键不同参数返回冲突。
- 按钮提交后立即进入处理中并禁用；网络重试不得产生重复对象、重复任务、重复审批或重复通知。
- 员工与账号创建、员工多部门/角色编辑、区域中心主管自动成员与角色维护、员工直接停用/恢复、地市交接生效、维系记录与任务完成、审批通过回调均不得向用户留下半成品业务事实。

### API 与错误反馈约定

成功响应至少包含 `requestId`、`data`；列表另含 `page`、`pageSize`、`total`。失败响应至少包含 `requestId`、`code`、`message`、`fieldErrors`，不得返回堆栈、SQL、对象存储地址或越权对象信息。

| 错误码 | HTTP | 含义 | 前端处理 |
| --- | --- | --- | --- |
| `AUTH-401-001` | 401 | 未登录、会话过期 | 清理本地业务缓存并返回登录页 |
| `AUTH-403-001` | 403 | 无功能、字段或对象权限 | 显示无权限，不说明对象是否存在 |
| `DATA-404-001` | 404 | 在有权范围内对象不存在 | 返回列表或刷新父上下文 |
| `VALID-400-001` | 400 | 字段校验失败 | 展示 `fieldErrors` 并聚焦首项 |
| `STATE-409-001` | 409 | 当前状态不允许操作 | 刷新对象并展示最新状态 |
| `VERSION-409-002` | 409 | 乐观锁冲突 | 展示最新摘要，由用户重新确认 |
| `DUP-409-003` | 409 | 唯一键或疑似重复 | 指出冲突字段，不泄露越权对象详情 |
| `PERM-400-001` | 400 | 权限集合缺少父级或前置依赖，或包含不可授予的 F002 | 标记冲突权限并要求按最新权限树修正 |
| `PERM-503-001` | 503 | 权限版本或鉴权服务不可用 | 失败关闭，显示请求编号并允许稍后重试 |
| `FILE-400-001` | 400 | 文件格式、大小或数量不合法 | 保留其他已通过附件 |
| `FILE-503-002` | 503 | 存储或安全扫描不可用 | 保留表单并允许稍后重试 |
| `UPSTREAM-503-001` | 503 | 区划、节假日等上游不可用 | 使用功能定义的降级规则 |
| `SYSTEM-500-001` | 500 | 未分类服务端错误 | 显示请求编号并记录告警 |

### 审计字段

所有主对象和流程对象至少保存：内部 ID（`id`）、适用时的业务编号（`code`）、创建时间（`createdAt`）、创建人（`createdBy`）、更新时间（`updatedAt`）、更新人（`updatedBy`）、数据版本（`version`）和写入来源（`source`）。写入来源固定为手工录入（`manual`）、AI 辅助（`ai_assisted`）、批量导入（`import`）、系统生成（`system`），业务页面只展示中文。涉及状态或责任变化时另存修改前值、修改后值、原因、业务身份、真实操作账号、关联审批 ID、请求 ID 和发生时间。审计日志只追加不可修改；页面按对象权限展示，系统管理员公司全局可查。

### 后续 AI 辅助兼容契约

本期不实现 AI 按钮、模型调用或模拟结果，但新增与编辑能力必须遵守以下可扩展边界：

1. AI 只生成与对应字段表一致的结构化草稿或字段建议；草稿保存独立草稿 ID（`draftId`）、草稿版本（`draftVersion`）、创建人和授权范围快照，不是正式对象。
2. 草稿阶段不生成业务编号，不触发任务、审批、通知、统计、唯一性占位或责任迁移。只有用户确认且正式创建事务成功时才取号。
3. 确认人必须拥有与人工表单相同的页面、操作、字段、对象和附件权限；服务端重新执行必填、长度、格式、枚举、数据范围、唯一性、对象状态、审批路由和附件安全校验，模型结果不得作为校验通过依据。
4. 正式创建记录“写入来源为 AI 辅助”（`source=ai_assisted`）、确认人（`confirmedBy`）、确认时间（`confirmedAt`）和草稿 ID（`draftId`）；扩展字段预留 AI 会话 ID（`aiConversationId`）、模型版本（`modelVersion`）、提示模板版本（`promptTemplateVersion`）、建议快照及字段级采纳/修改结果。上述字段仅审计和获授权详情可见，不进入普通列表或业务导出。
5. 模型输入、输出、用户修改和最终提交前后值按父对象权限保护；不得将越权对象、明文敏感字段或永久附件地址送入模型。模型调用日志不得记录密码、完整手机号、未授权客户或附件正文。
6. AI 生成与确认分别使用幂等键；同一确认键重试返回首次正式对象和编号。AI 超时、不可用、输出缺字段或格式错误时不写正式对象、不取号，保留人工表单和已输入内容。
