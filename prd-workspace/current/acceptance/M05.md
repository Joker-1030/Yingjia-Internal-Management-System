# M05 Acceptance Criteria

> Mechanical migration from the current full PRD. Stable IDs, priority, and row order are preserved. Product-owner-confirmed wording replacements are governed below and retain their prior wording as Historical / Replaced Evidence.

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F012-06 | 集团或客户单位存在正常下级 | 不选完整级联且直接申请停用 | 系统阻止并展示下级及任务影响；完整处理后才进入审批 | P0 |
| AC-F012-07 | 停用审批通过 | 从树、搜索、下拉、统计和停用记录查看 | 正常入口均隐藏，指标剔除；有权用户仍可在停用记录查看审计详情 | P0 |
| AC-F012-08 | 上级仍停用 | 申请恢复下级或关键人 | 系统阻止并提示恢复顺序；上级恢复后才可提交 | P0 |
| AC-F012-09 | 同一对象已有停用审批中申请 | 再次提交停用或普通编辑 | 重复申请和普通编辑均被拒绝，原审批不受影响 | P0 |
| AC-F012-10 | 停用对象存在适用的未完成任务 | 审批通过 | 停用事务统一关闭适用未完成任务并写入原因；关闭不计完成、不生成维系记录，不提供通用任务转移、迁移或重新分配 | P0 |
| AC-F012-11 | 有权用户查看正常客户单位详情 | 发起停用、查看影响摘要并提交 | 生成流程编号并关联展示“停用审批中”；审批前客户业务状态仍为正常并按原状态参与业务，流程投影不写入客户持久状态；列表、详情和审批状态一致 | P0 |
| AC-F012-12 | 客户单位已停用且所属集团正常 | 从停用记录详情发起恢复并审批通过 | 审批中仍保持停用；通过后恢复正常并重新进入有权树、搜索和候选，不补造停用期间历史任务 | P0 |
| AC-F012-13 | 集团仍停用或客户已有恢复审批中申请 | 尝试恢复下属客户、关键人或重复申请 | 页面明确提示先恢复上级或已有申请，接口返回状态冲突且不改变对象 | P0 |
| AC-F012-14 | 集团仍有正常客户单位和关键人 | 仅选择部分下级申请停用 | 系统要求完整级联并列出遗漏对象；不能让正常下级挂在已停用集团，审批不创建 | P0 |
| AC-F012-15 | 客户单位有有效关键人、未完成任务和覆盖 KPI | 选择级联停用并审批通过 | 客户和关键人一起停用，适用未完成任务统一关闭且不算完成，单位退出当前覆盖率分母，历史记录/编号/已结束 KPI 不改 | P0 |
| AC-F012-16 | 停用关键人是某单位目标部门或岗位最后一名符合条件的有效关键人 | 停用生效并在有效期内恢复，且恢复前后分别模拟责任人不变和已变更 | 对应覆盖率下降且进行中覆盖 KPI 重新打开；责任人不变时复用原聚合执行项，责任人变化时计入新责任人的现有项或新建唯一项，原历史不转移且不补过去事件任务 | P0 |
| AC-F012-17 | 客户部门存在当前任职引用 | 使用合法替代模板停用后再恢复原模板 | 当前任职迁移并记录流程，历史任职不改；恢复后原模板重新可选，但已迁移任职不自动改回 | P0 |
