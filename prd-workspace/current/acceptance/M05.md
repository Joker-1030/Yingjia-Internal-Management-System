# M05 Acceptance Criteria

> Mechanical migration from the current full PRD. Stable IDs, priority, and row order are preserved. Product-owner-confirmed wording replacements are governed below and retain their prior wording as Historical / Replaced Evidence.

| AC 编号 | Given | When | Then | 优先级 |
| --- | --- | --- | --- | --- |
| AC-F012-06 | 集团或客户公司存在由显式组织上级关系识别的正常下级客户公司 | admin 未先迁移下级且未完整选择级联对象便确认停用 | 系统阻止并展示全部正常下级、后代及任务影响；把下级迁移到合法上级或完整纳入处理后才可确认，历史快照保留停用时显式上级与业务责任事实 | P0 |
| AC-F012-07 | admin 已完成影响校验并二次确认，停用事务全部成功 | 从树、搜索、下拉、统计和停用记录查看 | 正常入口均隐藏，指标剔除；admin 仍可在停用记录查看审计详情；不创建 M04 审批实例、流程编号、待办或抄送 | P0 |
| AC-F012-08 | 上级仍停用 | 申请恢复下级或关键人 | 系统阻止并提示恢复顺序；上级恢复后才可提交 | P0 |
| AC-F012-09 | admin 已打开同一对象的停用/恢复确认，或对象版本在确认前发生变化 | 重复确认、并发提交或基于旧影响摘要确认 | 只允许一个合法结果；版本变化时要求刷新并重新校验，失败时对象保持原业务状态且不留下部分处理结果 | P0 |
| AC-F012-10 | 停用对象存在适用的未完成任务 | admin 二次确认停用 | 停用事务统一关闭适用未完成任务并写入原因；关闭不计完成、不生成维系记录，不提供通用任务转移、迁移或重新分配；任一写入失败则对象和任务均保持原状态 | P0 |
| AC-F012-11 | admin 查看正常客户单位详情；其他角色查看同一对象 | 分别查找停用入口并尝试直接请求 | admin 可查看影响摘要并二次确认后直接生效，M05 记录对象快照、影响结果和实际操作人；其他角色无入口且请求返回 403，不泄露对象信息；全程不创建 M04 审批实例、流程编号、待办、抄送或回调重试链路 | P0 |
| AC-F012-12 | 客户单位已停用且所属集团正常 | admin 从停用记录详情查看恢复影响并二次确认 | 事务全部成功后恢复正常并重新进入有权树、搜索和候选，不补造停用期间历史任务；失败时整次不生效并保持已停用 | P0 |
| AC-F012-13 | 集团仍停用，或恢复校验发现唯一性、责任、对象版本或恢复顺序不满足 | admin 尝试恢复下属客户或关键人 | 页面明确列出阻断原因且不能确认；对象保持已停用，不产生部分恢复结果或 M04 审批实例 | P0 |
| AC-F012-14 | 集团仍有正常客户单位和关键人 | admin 仅选择部分下级确认停用 | 系统要求完整级联并列出遗漏对象；不能让正常下级挂在已停用集团，不产生停用结果 | P0 |
| AC-F012-15 | 客户单位有有效关键人、未完成任务和覆盖 KPI | admin 选择完整级联并二次确认停用 | 客户和关键人一起直接停用，适用未完成任务统一关闭且不算完成，单位退出当前覆盖率分母，历史记录/编号/已结束 KPI 不改；任一处理失败时全部保持原状态 | P0 |
| AC-F012-16 | 停用关键人是某单位目标部门或岗位最后一名符合条件的有效关键人 | 停用生效并在有效期内恢复，且恢复前后分别模拟责任人不变和已变更 | 对应覆盖率下降且进行中覆盖 KPI 重新打开；责任人不变时复用原聚合执行项，责任人变化时计入新责任人的现有项或新建唯一项，原历史不转移且不补过去事件任务 | P0 |
| AC-F012-17 | 客户部门存在当前任职引用 | admin 使用合法替代客户部门完成影响校验并停用，之后再恢复原客户部门 | 当前任职迁移并记录前后客户部门和实际生效时间，历史任职不改；恢复后原客户部门重新可选，但已迁移任职不自动改回 | P0 |
| AC-F012-18 | 带 `CG` 集团编号的集团公司由 admin 停用、恢复并形成历史 | 查看影响确认、对象快照、停用记录详情及恢复后的历史 | 所有位置始终展示 M09 同一集团编号；停用、恢复和失败不修改、不重新生成且不回收编号；M05 不建立第二份集团编号事实 | P0 |

> Source Governance（2026-08-22，DEC-163）：AC-F012-10 的历史 Given/Then 为“停用选择关闭未完成任务或先处理任务；前者关闭，后者仍有任务时阻断”。该可选分支已被“统一关闭适用未完成任务”替代；原文保留于本注记作为 Historical / Replaced Evidence。稳定 ID、优先级和顺序不变。

> State Governance（2026-08-22，DEC-163）：AC-F012-11 历史措辞“客户标记停用审批中”已分层为关联流程投影，审批前客户持久业务状态仍为正常；AC-F012-15 历史“任务按选项关闭”已由统一关闭适用未完成任务替代。旧措辞保留于本注记作为 Historical / Replaced Evidence。

> 附件 Current Rule（DEC-164）：本期客户主数据停用和恢复均不支持附件。旧 F012 按钮表“申请停用”中的附件字段作为 Historical / Replaced Evidence 保留；本注记不增加 AC ID，也不改变既有 AC 优先级或顺序。
>
> Customer Hierarchy Current Rule（2026-08-28，DEC-180）：AC-F012-06 的下级客户公司由显式组织上级关系识别，不再按业务责任省市区或公司层级推导；停用与恢复快照保留当时的组织上级和业务责任事实。

> Business State Display Rule（2026-08-31，DEC-184；2026-09-03 由 DEC-198 部分替代）：对象业务状态只展示正常/已停用继续有效；客户侧业务处理失败归 M04、受控重试及重复发起锁定已取消。

> Admin Direct Effect Current Rule（2026-09-03，DEC-198）：替代 AC-F012-06 至 AC-F012-18 中多角色发起、审批路由、流程编号、审批中锁定及回调重试表达。客户侧停用/恢复仅唯一内置 `admin` 可操作，完成影响校验并二次确认后直接原子生效；M05 保留对象快照、影响结果和完整历史，但不创建 M04 审批实例、流程编号、待办、抄送或回调重试链路。
