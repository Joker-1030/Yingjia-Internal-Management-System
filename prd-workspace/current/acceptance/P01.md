| AC-F013-16 | M12 商机的下次跟进日期为当天且持续无新有效跟进 | 连续运行消息任务并在第 3 个逾期自然日后新增有效跟进 | 当日上午提醒负责人，次日起每日一次，第 3 个逾期自然日同步区域总监；新跟进后旧承诺提醒停止，节假日不顺延，消息失败不改变商机事实 | P0 |
| AC-F013-17 | M12 方案支撑请求尚未接收或经过交付截止时间 | 查看消息与请求状态 | 不计算或发送首次回应超时消息；本次不新增交付逾期通知或自动状态流转；原商机跟进提醒不受影响 | P0 |
| AC-F013-18 | 用户完成 M02 调岗、M03 任务异常/逾期补录、M08 地市交接或 M12 指标调整 | 查看消息中心、侧栏角标和工作台待办 | 不生成审批待办、目标责任人接收待办、审批抄送或审批结果通知；只保留来源模块已定义的业务结果消息，且通知失败不回滚已生效业务事实 | P0 |
| AC-F013-19 | 地市负责人直接调整业务迁移成功 | 投递业务结果消息 | 原任、新任及该地市所属区域的区域总监为接收对象，沿用M08 §8.3；不生成审批通知 | P0 |
| AC-F013-20 | 节假日日历同步首次失败并持续失败，随后手动或自动实际恢复成功后再次失败 | 投递告警并重复处理同一故障 | 同一故障首次失败仅 admin 接收一次告警，持续失败及重试不重复，总裁、市场副总及其他角色不接收；手动或自动实际恢复后再失败作为新一轮故障重新告警，不因手动恢复无消息而漏报；旧版本降级不算恢复，M09 降级与暂停规则保持 | P0 |
| AC-F013-21 | 关键人调岗当日或计划日到期实际生效成功，另有待生效/失败记录 | 投递调岗消息 | 仅成功事件通知原新业务负责人及涉及区域总监，不默认通知总裁/市场副总；只展示关键人、原新单位/岗位及实际生效时间，无后台重算说明；点击仍按既有对象权限校验 | P0 |
| AC-F013-22 | 员工停用或恢复成功 | 查看站内消息 | 不因该员工状态变化单独生成通知或广播，操作人仍获得既有结果反馈；不据此新增或取消另行定义的责任交接通知 | P0 |
| AC-F013-23 | PM停用后的多个地市责任组分别成功或失败 | 各地市交接成功生效 | 每个成功地市通知新接收PM及所属区域总监，内容仅地市、原/新负责人及生效时间；不通知已停用人员，失败组不发成功消息，不影响成功组通知 | P0 |
| AC-F013-24 | 区域总监停用后的多个区域责任组分别成功或失败 | 各区域交接成功生效 | 每个成功区域通知新接收区域总监及市场副总，内容仅区域、原/新负责人及生效时间；不通知已停用人员，失败组不发成功消息，不影响成功组通知 | P0 |
| AC-F013-25 | 新专项正式发布并生成执行任务 | 查看责任人任务及消息 | 复用既有执行任务作为责任人待办，不发送专项发布消息，不创建重复待办；工作台仍按既有当前可处理资格及展示规则聚合 | P0 |
| AC-F013-26 | 覆盖KPI有效期内失去达标条件，随后恢复达标 | 查看原执行项/待办及消息 | 原待办重新打开，不发送重新打开消息、不创建重复任务；恢复达标后自动完成，原编号和失去/恢复达标时间保持可追溯 | P0 |
| AC-F013-27 | 当前 M10 数据导入处于延期状态 | 查看消息中心、菜单或尝试访问导入结果 | 当前不提供批量导入、批次结果或导入结果消息；后续数据采用人工导入。旧的异步导入通知规则仅作延期设计/历史证据，不作为当前消息行为 | P0 |
| AC-F013-28 | 区域发生M08定义的配置异常，随后修复恢复 | 查看区域页面及站内消息 | 现有页面展示配置异常与具体原因，异常出现和修复恢复均不生成站内通知，恢复后更新现有页面状态；既有客户责任和任务保护、恢复处理及记录保持 | P0 |
| AC-F013-29 | admin 停用或恢复关键人，分别成功或失败 | 查看消息 | 仅实际成功后通知其所在公司的客户负责人及所属区域总监；省级客户的客户负责人为所属区域总监，市级/区县级客户的客户负责人为对应地市 PM，同一员工重复命中只收一条；不向总裁/市场副总广播，内容为关键人、客户单位、停用/恢复结果和生效时间，无后台处理说明，沿用对象访问权限；同次集团或客户公司停用级联不另发逐关键人通知，后续独立操作仍按本条通知 | P0 |
| AC-F013-30 | admin 以客户公司为操作对象停用或恢复，分别成功或失败 | 查看消息 | 仅实际成功后通知该公司客户负责人及所属区域总监；省级客户的客户负责人为所属区域总监，市级/区县级客户的客户负责人为对应地市 PM，同一员工重复命中只收一条；不向总裁/市场副总广播，内容仅公司、停用/恢复结果及生效时间，无后台处理说明；单独停用公司时每位接收人只收一条公司结果消息，同次联动停用多个关键人不另发逐人消息；后续独立操作关键人仍正常通知；对象访问权限保持，集团整体按 AC-F013-31 聚合，同次集团级联不另发逐公司通知 | P0 |
| AC-F013-31 | admin 对集团停用/恢复，分别实际成功或失败，相关公司存在共同客户负责人或区域总监 | 查看集团结果消息及同次级联消息，并随后独立操作公司或关键人 | 成功后通知相关公司客户负责人及涉及区域总监；客户负责人按省级区域总监、市级/区县级地市 PM 映射，同一员工通过多个客户或角色重复命中时仅收一条集团结果消息，同次级联不另发公司或关键人通知；仅说明集团、结果和生效时间，不向总裁/市场副总广播，不展示后台处理，不扩大访问权；失败不发成功消息；恢复集团不自动恢复下级，后续独立操作按自身规则通知 | P0 |
| AC-F013-32 | admin 停用或恢复客户部门，分别实际成功、失败或联动影响多个关键人、任职及任务 | 查看消息及后续恢复结果 | 成功后通知该公司客户负责人及所属区域总监；客户负责人按省级区域总监、市级/区县级地市 PM 映射，同一员工重复命中时仅收一条部门结果消息；内容仅为客户公司、客户部门、结果和生效时间，不向总裁/市场副总广播，不展示后台处理，不扩大访问权；停用联动影响不逐项发送消息，失败不发成功消息；恢复不自动恢复下级对象或已关闭任务 | P0 |
| AC-F013-33 | admin 分别停用无有效任职或进行中覆盖 KPI 引用的标准关键人岗位、尝试停用仍有引用的岗位，并恢复已停用岗位 | 查看 M09 页面反馈与站内消息 | 合法停用/恢复和引用阻断均只在 M09 当前页面向操作 admin 显示结果，不生成站内消息；恢复仅重新开放为后续候选，不向业务角色发送通知 | P0 |
| AC-F013-34 | admin 停用有存量集团引用的行业，随后恢复该行业 | 查看 M09 页面、相关存量对象及站内消息 | 停用/恢复只在 M09 当前页面向操作 admin 显示结果，不生成站内消息，不通知相关集团、客户负责人或区域总监；存量集团、客户公司和历史引用保持，候选变化由 M09 负责 | P0 |
| AC-F013-35 | 生日/节假日规则存在后续提醒节点 | admin 停用规则并在错过提醒节点后重新启用 | 启停本身只在 M09 当前页面反馈，不生成站内消息；停用期间不发送尚未发送的规则提醒，重新启用不补发错过的提醒，只按启用后符合条件的后续节点发送 | P0 |
| AC-F013-36 | 节假日日历分别手动同步成功和无先前失败的普通定时同步成功 | 查看消息中心和 M09 页面 | 两次成功均不生成站内消息；手动成功只在 M09 当前页面向操作 admin 显示结果，定时成功保持静默；同步失败告警仍仅通知 admin | P0 |
| AC-F013-37 | 节假日日历定时同步失败后，分别自动恢复成功或由 admin 手动重试成功 | 查看恢复消息、重试同次恢复投递并继续成功同步 | 自动恢复实际成功后只向 admin 发送一次恢复通知，其他角色不接收，同次恢复重试及后续连续成功不重复通知；手动重试成功只有页面反馈，不发恢复消息；未实际恢复或仅使用旧版本降级不发恢复消息 | P0 |
| AC-F013-38 | admin 保存职级维系周期及提醒配置，后续任务达到有效提醒节点或升级阈值 | 查看保存结果消息及任务提醒 | 配置保存本身不生成站内消息，仅在 M09 页面反馈；达到既有提醒资格的任务仍正常发送对应提醒，不将“不发送配置修改消息”解释为停止任务提醒；原接收人、节点与防重规则保持 | P0 |
| AC-F013-39 | admin 普通编辑生日或节假日规则内容并保存成功 | 查看保存反馈与后续任务提醒 | 保存本身只在 M09 页面反馈，不产生站内消息；实际任务提醒仍按原生效与快照规则投递，不因内容编辑无消息而停止；规则启停仍按 AC-F013-35 执行 | P0 |
| AC-F013-40 | M03 任务由本人或 admin 代办延期 | 对比成功、取消确认、失败、重复提交及消息投递失败 | 本人成功只页面反馈；admin 代办成功只向实际任务执行人发送一条包含任务和新截止时间的结果消息，不向其他主管广播；执行人是区域总监时正常接收。取消或失败不发成功消息，重复提交不重复发送，消息失败不撤销已生效延期 | P0 |
| AC-F013-41 | M03 任务由本人或 admin 代办暂停 | 对比成功、取消确认、失败、重复提交及消息投递失败 | 本人成功只页面反馈；admin 代办成功只向实际执行人发送一条包含任务及“暂停至”日期的结果消息，不向其他主管广播，执行人是区域总监时正常接收。取消确认或失败不发成功消息，重复提交不重复发送，消息失败不撤销暂停；这条结果消息不恢复暂停期间的任务提醒，也不新增自动恢复或自动关闭消息 | P0 |

| AC-F013-43 | M03 暂停任务到期实际恢复待执行，原暂停分别由本人及 admin 代办 | 检查恢复时及后续达到既有提醒节点的消息 | 恢复时不向执行人、admin 或主管额外发送“已恢复”消息，仍由原任务/待办承接；后续任务提醒按既有当前截止、节点与接收范围正常执行。自动关闭不按恢复处理，不套用本条决定关闭通知 | P0 |
| AC-F013-44 | 生日/节假日任务在暂停期间越过当前截止并实际自动关闭，原暂停分别由本人和 admin 操作 | 查看消息、任务关闭结果及待办 | 不向执行人、admin 或主管另发关闭消息；任务保留关闭结果、原因与历史且不再进入待办。不将自动关闭误认成恢复，也不把本条扩展为所有来源的取消/关闭均无消息 | P0 |
| AC-F013-45 | M03 任务由本人或 admin 代办正常完成 | 对比成功、失败、重复提交及消息投递失败，并排除逾期补录/补完成 | 本人成功只页面反馈；admin 代办成功只向实际执行人发送一条“任务已完成”结果消息，不向其他主管广播，执行人是区域总监时正常接收。失败或重复提交不发成功消息，消息失败不撤销完成；逾期补录和逾期补完成按各自规则处理 | P0 |
| AC-F013-46 | M03 任务由本人或 admin 代办逾期补录 | 检查成功、失败、重复提交及消息投递失败 | 本人成功只页面反馈；admin 代办成功只向实际执行人发送一条补录完成及认定结果消息，不向主管广播；失败或重复提交不发/重复发送，消息失败不撤销补录 | P0 |
| AC-F013-47 | M03 任务正常完成生成下一期，或逾期补录/补完成失败 | 检查下一期任务、页面反馈和消息 | 下一期不额外通知，沿用既有待办/提醒；逾期补录或逾期补完成失败只页面反馈，不发送失败消息并保留表单；成功通知按各自规则执行 | P0 |
| AC-F013-48 | M03 任务由本人或 admin 代办逾期补完成 | 检查成功、失败、重复提交及消息投递失败 | 本人成功只页面反馈；admin 代办成功只向实际执行人发送一条补完成及认定结果消息，不向主管广播；失败或重复提交不发/重复发送，消息失败不撤销补完成 | P0 |
