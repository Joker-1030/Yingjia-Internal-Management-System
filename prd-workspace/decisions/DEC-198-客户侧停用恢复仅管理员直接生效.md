# DEC-198：客户侧停用恢复仅管理员直接生效

- 日期：2026-09-03
- 状态：已确认
- 背景：M09 的角色权限已将客户基础配置写权限限定为系统管理员，但 M02、M05、M09、Shared、Flow 和既有 Decision 仍允许总裁、市场副总、区域总监、PM 按范围发起客户侧对象停用/恢复，并进入 M04 审批，形成了权限与流程冲突。Product Owner 进一步确认当前停用/恢复只给系统管理员，且确认后直接生效。
- 决策：
  1. 集团公司、客户公司、关键人和客户部门的停用与恢复仅允许唯一内置系统管理员 `admin` 操作；总裁、市场副总、区域总监、PM、HR/人事及其他角色均无入口、无操作权限。
  2. 无权角色通过直接地址、伪造请求、搜索、候选或历史关联尝试操作时返回 403，不返回对象名称、状态、数量、路径或是否存在。
  3. admin 发起操作后，系统仍先校验对象状态、上下级关系、影响摘要、级联完整性、未完成任务、任职、KPI、责任、并发版本和其他既有阻断条件；影响无法完整计算或存在阻断项时不得确认。
  4. 校验通过并由 admin 二次确认后，停用或恢复直接生效，不创建 M04 审批实例、审批节点、流程编号、审批待办、抄送或业务回调重试链路。
  5. M05 继续保存对象快照、影响结果、停用/恢复原因、实际操作人、生效时间、级联与任务处理结果和完整历史；直接生效不等于不留记录。
  6. 停用事务继续统一关闭适用未完成任务并保留历史；任一写入失败时整次操作不生效，不留下部分停用、部分恢复或部分任务关闭结果。
  7. 恢复继续遵守上级正常、唯一性、责任有效性和恢复顺序，不自动恢复下级、已关闭任务、已转移责任，也不补造停用期间已经过去的任务。
  8. 行业与标准关键人岗位继续由 admin 在 M09 内按既有规则直接停用/恢复；本决策不改变其对象范围和阻断规则。
  9. M06 员工、账号和内部部门的停用/恢复不受影响，继续使用 M06 已确认的 HR/admin 直接生效规则。
- 替代关系：替代 DEC-163 第 5 项的多角色发起规则；替代 DEC-151 中“客户主数据停用/恢复发起资格由 DEC-163 管理”的部分；替代 DEC-184 第 2-4 项及“未改变发起权限、审批路由”的相关表述。DEC-184 关于客户对象只展示 `正常` / `已停用` 两种真实业务状态继续有效。
- 未采用方案：保留总裁、市场副总、区域总监或 PM 的范围内发起权；admin 发起后继续进入 M04 审批；直接生效后不保留 M05 记录与影响审计。
- 原因：客户基础配置由 admin 统一维护，停用/恢复继续开放给其他角色会造成权限边界不一致；仅保留 admin 并直接生效可以降低审批与权限冗余，同时通过影响校验、原子结果和历史记录保持业务安全与可追溯性。
- 决策人：Product Owner
- 影响范围：M02、M04、M05、M09、Shared 权限矩阵、FLOW-04、FLOW-13、Acceptance、Product Boundary、DEC-151、DEC-163、DEC-184
